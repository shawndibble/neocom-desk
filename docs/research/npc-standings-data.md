# NPC agents / NPC corporations / factions: what data exists

Checked 2026-10-28 (game build 3654997, SDE released 2026-10-27). Live ESI calls used `User-Agent: research-bot/1.0`, no email.
ESI OpenAPI spec (`https://esi.evetech.net/meta/openapi.json`, compat date 2020-01-01) was downloaded and parsed for field lists and scopes.
Fuzzwork CSVs were downloaded from `/dump/latest/csv/` and CCP's `eve-online-static-data-3654997-jsonl.zip` was downloaded and inspected locally.

| Reprocessing tax                                                                                         | **The repo does NOT implement the station tax.** `engine/industry/reprocessing.ts` assumes the 50% base rate and explicitly excludes the standings-based station tax (decision `20260906-180034`, `docs/features/industry-plans.md:451`, `docs/research/eve-uni-validation/industry.md:66` "WE LACK"). Known game rule (EVE Uni, fetched today): station tax is 5% at 0 standing and falls to 0% at 6.67 standing with the station owner; the page gives no curve. ## What a modal could show

### With data we already have (no new files)

- **Standing row facts**: name, kind (faction / corp / agent), standing value + tier icon, "used for fees" flag (already in Contacts Standings).
- **NPC corp** (`PublicInfoModal` corporation tab, ESI public): name, ticker, CEO, member count, home station id, description, member tax rate, alliance history (empty for NPC). Corp's **faction** from `lpCorporations.json` (181 corps) or from `stations.json` owner pairs (185 owners): corp -> faction and the **list of its stations** (name, system, system security, region via `systems.json` + `regions.json`).
- **Broker fee at this corp's stations**: `brokerFeePct(brokerRelations, factionStanding, corpStanding)` vs the same at (0, 0), using the standings already loaded and the Broker Relations level; "Sales tax" via Accounting. Needs only the corp -> faction join above.
- **Whether the corp has an LP store** (membership in `lpCorporations.json`) and the character's LP with it (`/characters/{id}/loyalty/points`), with a link into the existing LP store UI. Store offers from the public ESI endpoint (no standing requirement exists there).
- **Faction facts** from `/universe/factions` (public, one 22 KB request, not currently called): description, size factor, system, station count, militia corp. Faction names are already resolvable via `resolveNames`. No `faction` kind exists in `PublicInfoKind`, so a faction modal needs a new kind.
- **Agent card today**: name, race/gender/bloodline/corp from `/characters/{id}` public; faction only when the corp record has it (usually it does not; fix by using the corp -> faction join).

### With a small new SDE file (bake-only change; all source CSVs are already in the Fuzzwork dump, 2 of them already downloaded)

- **Agents file** (~69 KB gzip without names, ~187 KB with): per agent level (1-5), division (Security / Distribution / Mining / R&D / ...), type (basic, FW, research, storyline, ...), isLocator, station -> system -> region, plus names from `npcCharacters`. Enables: "agents of this corp, grouped by level / division / system", an agent card showing level + division + station + "locator agent", and the standing needed to talk to them (game-rule table L1 none / L2 1.0 / L3 3.0 / L4 5.0 / L5 7.0 applied against effective standing = base + (10 - base) x 0.04 x Connections or Diplomacy level). Standing from the character's agent/corp/faction rows can say "you can/can't use this agent". Caveats: the "max of agent/corp/faction" access rule and the R&D "corp requirement minus 2" are wiki rules, not SDE data.
- **Full NPC corporation file** (283 rows, ~25 KB raw / well under 10 KB gzip with the useful columns): factionId (273), size, extent, ticker, HQ station and home system, investors, friend/enemy corps, main activity, member tax, divisions. Covers non-LP corps that today have no faction mapping outside `stations.json`.
- **Per-station reprocessing take and efficiency**: two extra fields on `stations.json` (or a corp-level aggregate) so the modal can show the 5% to 0% refining tax at the character's standing (rule unconfirmed; see D).
- **Faction file** (27 rows): either `/universe/factions` live or `chrFactions` baked; includes militia corporation ids (6 factions) and `stationCount` / `stationSystemCount`.

### Not available at all (SDE or ESI)

- Agent **quality** (blank on every row in the SDE; retired).
- Per-agent or per-corp **standing requirements** other than the generic level table, and any "which agent can I currently use" endpoint; ESI gives no agent list or locator.
- **Effective standing** from ESI; it must be computed from base + the three social skills (and implant/ESI-undocumented modifiers are unverified). Unauthenticated, so unverifiable here; the repo already flags base-vs-effective as an unverified assumption.
- LP store **standing requirements** (the offers endpoint has none; the old SDE `lpOfferTables` ids exist but not the standing gates).
- Live data on mission availability, agent current location changes (agents are static in stations), or mission counts per agent.
