# Scope decisions — Characters table gets a Group column and Remove column, not a row menu (issue #2077)

_Recorded 2026-09-27 · issue #2077._

- **Group move and character removal reach the Characters table view as two new columns (`group`, `remove`), not entries in `CharacterRowContextMenu`.** The context menu keeps its five navigation-only destinations exactly as #2059 left them, so #2059's premise that the menu is nav-only stays true and `rowMenuGuard.test.ts` is untouched. `group` renders the same `Select` the card uses (`Ungrouped` plus each group, wired to `moveCharacterToGroup`); `remove` is a trailing danger `IconButton` that opens the existing remove-confirm dialog, matching the card's separate red X rather than burying a destructive action in a menu.
- **Group management (rename, reorder, delete a group) stays card-view only.** `GroupSectionHeader` lived in each table-view group section, which this change removes; table view goes from one `DataTable` per group section to a single flat table with a `group` column. Rather than give management a new home in table view, it stays exclusive to card view's section headers — table view can move a character between existing groups but not edit the groups themselves.
- **Table view's per-group sections are removed; the `group` column plus a group filter replace them.** Table view no longer shows `GroupSectionHeader`/"Ungrouped" section breaks. A pilot moving down the column can already see and change each row's group; a filter-bar "Filter by group" (All / a group / Ungrouped) covers narrowing to one group. Card view keeps its sectioned rendering unchanged, per #2077's own acceptance criterion.
- **`group` and `alerts` join the shared Sort-by dropdown (`CharacterSortKey`), in both card and table view, sorting alphabetically by group name (Ungrouped sinks to the end via the existing undefined-sinks-last rule).** Table view already had a header-click sort on its `alerts` column; the shared dropdown mainly changes card view's default order and gives both views a group-name sort. Alphabetical, not the group's manage-groups reorder position, to avoid a second "what does this order mean" question next to Move up/down.
- **Existing customized column lists get a one-time migration to add `group`/`remove` if missing, via a separate migrated-flag setting (`charactersColumnsMigratedGroupRemove`), not a `parse`-time append.** `useVisibleCharacterColumns`'s `parse` runs on every hydrate, so appending a missing id there would silently re-add a column a pilot had deliberately hidden after the first migration. A one-time flag checked once on load avoids that trap. New/reset installs get `group` and `remove` in `DEFAULT_VISIBLE_CHARACTER_COLUMNS` directly and need no migration.
