# Scope decisions — Corp projects live in Opportunities, not a tab (issue #4786)

_Recorded 2026-10-23 · issue #4786._

- **Corp projects are a third view of the Build panel (`?opps.view=corp`), not a tab and not a new section.** #4530 (a Projects tab) was closed: the game already lists the projects. What the game never shows is your build cost, your blueprint cost and the profit, and a manufacture project is a buyer with a fixed reward, a cap and an end date, so it belongs beside Ranked and All owned. The panel title "Build Opportunities" becomes "Build" (the page is already Opportunities); the table's accessible name keeps the old words (`industry.opportunitiesTableLabel`). The segmented control reads Ranked · All owned · Corp projects; on a phone the title select gains it as a third item.
- **The view is absent, not empty, whenever there is nothing to show.** No Corporation projects Permission, no corporation, or no open manufacture project that has an item to price, leaves the option out, and a stale `?opps.view=corp` reads as Ranked once the reads settle. Mining, delivery, combat, loyalty and any unknown project kind are never listed, and a project that names a market group or several types (no single item to price) is skipped, never an error.
- **The scope is its own opt-in Permission, `corpProjects` (`esi-corporations.read_projects.v1`), not part of `corp`.** The reads need no corporation role, and widening `corp` would move every already-granted corp Character to `roles-without-grant` (docs/features/corp.md). It stays out of `CORP_SYNC_SCOPES` and `FEEDER_SYNC_SCOPES`, so the corp sync allowlist parity test needs no change. Landing page: the Industry row.
- **Reads happen once when Opportunities opens and are cached, never polled.** One aggregated cache row per Character and corporation (`corp:<id>:manufactureProjects`, ten minutes): the list names no project type, so each open project costs a detail read and each manufacture one a contribution read, against a shared 600-token window per 15 minutes (`corp-project`).
- **"Units you can still contribute" is the participation limit minus what the Character has contributed, held to what the pool can still pay (`floor(pool left / reward each)`).** `submission_limit` and `submission_multiplier` are undocumented and are not read. The reward is `reward_per_contribution`.
- **A row is priced by the Build Plan "Add to Compare" saves, not by the owned-blueprint ranking path.** The plan (runs = units that make the remaining units, at the Character's hub, owned materials claimed) goes through `useComparedBuildResults` and `resolveBuildPlan`, so the blueprint source (Owned, Community offer, bought copy, or the amber "Assuming a copy" priced at 0) and the cost cannot differ from what Compare shows. This replaces the ticket's "per-type cheapest ask from `publicContractOfferIndex.ts`": that index is the raw cheapest contract of any kind, while plan pricing filters auctions and PLEX and prices by ME/TE and runs. Each selected Character is priced with their own skills and blueprints (standings are the Industry page's); a project shows once per selected Character of its corporation.
- **Profit is reward minus cost, not the hub sale.** Revenue is `reward × units`, with no sales tax or broker fee. `rankOpportunities` (ISK/hour, hub depth) does not apply: the table sorts by profit at cap, best first, and unpriced rows last.
- **Build Plan Compare draws plans as columns on a phone.** Below `lg`, each plan heads a column and each shown metric is a row (`CompareMatrix`), instead of a sideways-scrolling table; the Columns picker still decides the rows. Desktop is unchanged.
