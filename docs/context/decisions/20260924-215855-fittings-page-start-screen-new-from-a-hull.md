# Scope decisions — Fittings page: Start screen, new from a hull, three-column editor with a slide-out browser

_Recorded 2026-09-24._

- **With nothing open, the Fittings page is a Start screen, and a Fitting can start from a bare hull.** "New fitting from a hull" (search, or browse the Ships market groups by class) is the lead path; Import (EFT, links, EVE XML), My Fittings and In-game Fittings sit beside it. A phone shows them one tab at a time. Previously a Fitting had to be Loaded before anything could be edited. The picker offers no race filter and no "I can fly" filter: the market tree groups advanced hulls by role, not race, and a per-hull skill check across every hull is out of proportion for a picker.
- **Once a Fitting is open, everything that opens a different one moves behind a Fittings menu.** The Load card and the two fitting lists no longer stack above the editor; the menu reopens the same Start content in a dialog. The header carries the Fitting's identity and its own controls (view, Export, Save to EVE, Save), with implants and missing skills on a row beneath, and a strip of headline numbers (total DPS, EHP, capacitor, speed, lock range, signature, Jita sell).
- **Three columns, as in the game's own window: module browser | Ring or List | stats.** The browser is the Add panel, docked on the left when the screen is wide enough for all three (100rem). The stats sections are re-hosted unchanged. (A two-column focus layout with the browser only on demand was mocked up and dropped for this.)
- **Too narrow for three columns, the browser becomes a slide-out from the left; below desktop, the mobile layout.** The slide-out is non-modal so the page stays live: another slot click retargets it, and an item drags out of it onto the Ring (`20260924-205720`). It pushes the page aside instead of covering it, so no slot sits under it — it cannot get out of the way mid-drag instead, because moving or hiding a drag's source element cancels the drag. Below desktop width: Fitting / Stats tabs, and Add as a sheet.
