# Scope decisions — Fittings page: Start screen, new from a hull, focus layout with a slide-over Add panel

_Recorded 2026-09-24._

- **With nothing open, the Fittings page is a Start screen, and a Fitting can start from a bare hull.** "New fitting from a hull" (search, or browse the Ships market groups by class) is the lead path; Import (EFT, links, EVE XML), My Fittings and In-game Fittings sit beside it. A phone shows them one tab at a time. Previously a Fitting had to be Loaded before anything could be edited. The picker offers no race filter and no "I can fly" filter: the market tree groups advanced hulls by role, not race, and a per-hull skill check across every hull is out of proportion for a picker.
- **Once a Fitting is open, everything that opens a different one moves behind a Fittings menu.** The Load card and the two fitting lists no longer stack above the editor; the menu reopens the same Start content in a dialog. The header carries the Fitting's identity and its own controls (view, Export, Save to EVE, Save), with implants and missing skills on a row beneath, and a strip of headline numbers (drone DPS — labelled as such until per-weapon offense lands — EHP, capacitor, speed, lock range, signature, Jita sell).
- **Focus layout: the Ring or List beside the stats, not beside the Add panel.** Side by side from `xl`, stacked below that, and Fitting / Stats tabs on a phone. The stats sections are re-hosted unchanged.
- **Adding modules is a slide-over from the right, non-modal, on every width but a phone's** (which keeps its sheet). Non-modal so the page stays live: another slot click retargets it, and an item drags out of it onto the Ring (`20260924-205720`). On pointer-width screens it pushes the page aside instead of covering it, so no slot sits under it — it cannot get out of the way mid-drag instead, because moving or hiding a drag's source element cancels the drag.
