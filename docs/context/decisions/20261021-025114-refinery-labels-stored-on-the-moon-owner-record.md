# Scope decisions — Refinery labels: stored on the moon owner record, two setters, owner-name fallback on owner screens only (issue #4640)

_Recorded 2026-10-21 · issue #4640._

- **A refinery's free-text label lives on the moon owner's record, `feeders/{feeder}.refineryLabels.{structureId}` (`{ label, setAt, setBy, side }`), one per refinery.** A rejoin reopens that record, so labels carry on; the view is rebuilt from scratch and would lose them. The setter writes `label` and `labelSetAt` into the view's `refineries/{id}` doc in the same transaction (a rebuild can fail on a price read), and every rebuild copies them from the record. Accounting officers read the record, the moon owner reads the view: no rules change. Supersedes "Refinery labels are not stored yet" in `20261020-175727`.
- **Last edit wins by replacement, not by comparing timestamps.** Each save replaces the one entry in a transaction, whichever side made it; an empty label deletes it, so a clear from either side always falls back down the chain.
- **Two callables, one write path.** `setCorpTaxBookRefineryLabelCallable` (accounting officers, live role check, `edit`) and `setCorpTaxBookOwnRefineryLabelCallable` (the moon owner's CEO, Directors and Accountants, live). Both audit `refineryLabelSet`, refuse a refinery with no observed row from that moon owner (`unknown-refinery`, so the map never grows past its refineries) and a moon owner that left or was removed.
- **The moon owner's name plus the id is a fallback for officer and moon owner screens only.** The book's `names.refinery` stops at "Refinery <id>"; `names.ownerRefinery` adds the owner name and is used only on a moon owner's page. Statements, mails and the miner's personal overlay never get it.
- **An officer label reaches miners.** The accounting book's `names.refinery` feeds Statements and their miner lines, so a label either side typed shows there; the edit hint says so. Only the automatic owner-name fallback is kept off miner lines.
- **The learned system is the system a row already carries.** Feeder rows come from a ledger-only grant and rarely carry one; learning from miners' own ledgers (`learnRefinerySystems`) needs data neither page holds, so it is not wired.
