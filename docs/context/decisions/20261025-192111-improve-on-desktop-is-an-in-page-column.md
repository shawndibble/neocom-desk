# Scope decisions — Improve on desktop is an in-page column, opened from the fitting menu only

_Recorded 2026-10-25. Revises the entry and placement points of `20261024-171917` (Improve: a goal-driven swap search)._

- **On desktop Improve is a column in the page, left of the editor, not a `SlideOver`.** The player ticks rows to watch the stats column change, so the stats must stay in view: a column where the docked module browser sits (`FittingEditorLayout`'s `improveColumn`, a `Panel` sticky to the viewport with its own scroll and the selection bar at its foot) does that, while the old overlay, pinned at the 12rem mark beside a 13rem nav rail, sat over the nav's edge and the page header. With three columns' width the stats stay beside the editor; narrower, they go above it while Improve is open (`fittingLayout.leftColumn`). Below desktop (64rem, the `lg` breakpoint, not `md` as `20261024-171917` had it) it is a bottom sheet, the stats being a tab of their own there.
- **It slides out from behind the nav rail.** The rail sits above the page (z-30, below overlays at z-40 and up) and the column's slide-in travels its whole width, so it comes out from under the nav rather than crossing it. Reduced motion gets no slide.
- **Improve and the module browser share that column; the last one opened wins.** Opening Improve sets the browser aside; picking an empty slot brings the browser back and closes Improve. Back does not close the column (it is page layout, as the docked browser is); Escape and its close button do, giving focus back to the ⋮ button that opened it.
- **The fitting header's ⋮ menu is the only way in, for now.** #5142's stats-header "Improve…" link and empty-slot menu item are removed: the player is not ready to make Improve easy to find. Bringing contextual entry points back is a later call, as the original decision left it.
