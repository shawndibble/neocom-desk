# Scope decisions — Core feature SDE files are precached for offline use

_Recorded 2026-10-15._

- **Ten `public/data` files move back into the install precache: `blueprints.json` (1.6 MB), `shipTree.json` (0.6 MB), and `market/{systems,jumps,systemPositions,groups,attributes,regions,globalMarkets,lpCorporations}.json` (~1.4 MB together); about 3.5 MB raw added to the install.** Amends `20260928-144005-feature-sde-files-load-on-demand-not-precached.md` (which took `blueprints.json` and `shipTree.json` out) and `20260831-140406-the-market-catalogue-payloads-are-kept-out-of.md` (the whole market catalogue out), and narrows `20260930-164429-background-warm-of-lazy-sde-files-and-dogma.md` (the warm no longer covers these). The app is offline-first: Industry (blueprint catalogue, build plans), the Ship Tree, route planning (systems, jumps, system positions for jump-drive ranges), and the system/region/group/attribute/LP-corporation pickers must open on a device with no network _on its first visit after install_, not only after an idle warm happened to finish (it is skipped offline, under Save-Data, on slow or metered links, and until a service worker controls the page). They are small, shared by many routes, and read before anything can be warmed.
- **Still lazy, in `src/sde/lazySdeFiles.ts`: `masteries`, `reprocessing`, `marketWideTrees`, `pi-planet-radius`, `pi-system-planets`, `typeNames`, `market/types`, `market/stations`, `market/variations`.** Those are the big, single-feature files (~10 MB raw); the Market Browser's order-book catalogue (types, stations, variations) is still not paid for up front. They stay on the on-demand + idle-warm path from the earlier decisions. The same list is what `vite.config.ts` ignores for the precache and what `warmLazySde.ts` fetches (a test pins both to it and to `public/data`), so a file cannot be in neither again — `market/systemPositions.json` was lazy in the precache but missing from the warm.
- **The warm now continues past a file that fails** and reports which failed; one dropped request used to abandon every file after it. The `sde-data` cache's `maxEntries` rises from 32 to 64: each content change leaves a superseded `?v=` entry until the 90-day age cap evicts it, and 32 against an 18-file list could evict live files.
- **`webp` joins the precache glob** for images the running app shows (the Survey and Industry how-to images, the landing page's ship art; ~0.5 MB). `public/screenshots/` (~1 MB) stays out: signed-out landing page and store-listing art only.
- **Stale-build recovery no longer wipes the whole Cache Storage and never runs offline.** On a failed route chunk it now deletes only Workbox precache caches (keeping `sde-data`, the dogma engine bucket and image caches) and declines when `navigator.onLine` is false, letting the route's error boundary render, which says the page cannot load offline and reloads when the connection returns.
