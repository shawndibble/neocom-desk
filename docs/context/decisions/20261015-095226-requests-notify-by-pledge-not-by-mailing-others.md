# Scope decisions — Requests notify by Pledge, not by mailing others

_Recorded 2026-10-15. Supersedes the Mail to wording of the Request mail, Ask to copy and "one-page compose with mail" decisions: posting no longer mails anyone. ADR 0021 stands._

- **Posting a Request mails no one.** The Mail to field, its chips, the compose "mailing" and "done" phases and the per-recipient results are gone; compose is one form (location, terms, lines, the notification choice, Post). Everyone in the Community sees the board, and the nav badge counts new Requests. Ask to copy still opens compose with its one BPC line, but no longer ticks or mails the holder.
- **The requester chooses how to hear about a Pledge, per Request.** `notify: { app, mail }` on the Request document, set at post and editable through the edit callable (booleans only, validated server side; an edit that omits it keeps the stored choice). A Request stored without it (before this) reads as `{ app: true, mail: false }`, and so does a new one in compose. Both off is allowed: the board alone.
- **`notify.mail` makes the Pledger mail the requester, from the Pledger's own Character.** The Pledger's client sends it (ESI mail send, the Pledger's token, the Send mail Permission) after the Pledge is saved, in the invites' reserve, send, confirm or release shape. It costs the Pledger one of their own 100 Request mails a day (`MAX_REQUEST_MAILS_PER_DAY`, the same `requestMailQuota/{day}` doc and the same stale-retake and refund rules as before). One mail per Pledger per Request, kept by a server slot at `itemRequests/{id}/pledgeMails/{pledgerUid}` so it holds across devices: an update, or a withdraw then Pledge again, never mails twice. The slot is claimed only after the Pledge exists with a quantity, and only by a Member on another Member's open Request with `notify.mail` true. The recipient is the Request owner's Character, read from the Request on the server; the client names no one. A mail that fails never undoes or blocks the Pledge: the panel prints one quiet line (Mailed, or Not mailed with the reason; no mail Permission gets the Grant link beside the line instead of an attempt). The old `…/mails/{targetId}` collection and its callables are retired; leftover documents go with their Request.
- **`notify.app` is an in-app notification, read while the app runs, never pushed.** A new Notification Event, `communityRequestPledged` (Settings > Notifications lists it; in-app only by default), joins the existing communities poll domain. Cost stays off users in no Community (the `communityWatch` flag the Requests badge uses), and only the pilot's own Requests are read (one query on `ownerUid`), then the Pledges of each own open Request that wants the app, never the whole board or a Community-wide sweep. A Pledge by another Member that was not in the previous read fires it, once per Pledger per Request, by identity and with no clock comparison: a Request absent from the previous read is watched with nothing Pledged. A withdraw then Pledge again fires only if a poll saw the withdrawal between; the first poll ever is a silent baseline. Several new Pledges in one Community in one poll make one event naming the latest Pledger and Request. The alert opens the Communities page; its numeric subject routing cannot carry a Community id, so there is no deeper link.
- **The diff lives beside the other community diffs** in `src/engine/communities/communityAlert.ts`, not in `src/engine/notificationDiffs.ts`, because the communities domain's snapshot and its two existing diffs are there; the admin diffs now read only their own entry kinds so Pledge entries cannot mark a Community "known" for them.
