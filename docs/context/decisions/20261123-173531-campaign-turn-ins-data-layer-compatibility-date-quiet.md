# Scope decisions — Campaign turn-ins data layer: compatibility date, quiet Permission, trader system source (issue #6703)

_Recorded 2026-11-23 · issue #6703. Builds on `20261123-164921-campaign-turn-ins-rewards-from-campaign-objectives-one.md`._

- **The app's ESI compatibility date moves from 2026-08-01 to 2026-08-04.** The Military Campaigns routes exist only from 2026-08-04 (a lower date answers 404), and ESI's `/meta/changelog` lists nothing else between the two dates, so no other route changes. One global date rather than a per-request override: the client has one header, and a second date would mean two cached shapes per route. Cloud Functions (`functions/src/esiClient.ts`) and the build scripts (`scripts/lib/constants.mjs`) move with it: `functionsParity.test.ts` keeps the backend on the client's date.
- **Military Campaigns is left out of the per-Character Permission count** (Settings › Permissions picker, Character switcher). Every Character signed in before it shipped lacks it, and the earlier decision is that they are never pushed to re-login for it; a count turning every roster amber would be that push. The row still shows Not granted with a Grant button in Settings › Permissions, any other Grant picks it up (a Grant adds every default-on Permission a Character lacks), and its figures carry the missing-Permission mark (#6705).
- **The scope is `esi.activity.char:read`**, CCP's new `esi.<area>.<owner>:<verb>` shape (from ESI's OpenAPI, 2026-11-23); `EsiScopeName` and the registry test accept both shapes. The EVE applications (dev and production) must have the scope enabled before this ships, or SSO refuses the Base Grant.
- **An Item Trader's system is read from the objective's own English subtitle**, which links it once (`showinfo:5//<solarSystemID>`). Neither SDE table has it as a field; the traded item's description carries the same link, but the subtitle is the objective's own text. The source is recorded in the baked file (`traderSystemSource`), and the bake fails if a turn-in's system is not a known solar system.
- **One item turned in is one unit of objective progress**, so ISK and LP are paid per `progressInterval` items; LP only for full blocks (no carry-over assumed). A turn-in counts no more than the objective still needs, nor than the Character's `maxProgressPerParticipant` cap allows. Two Active objectives taking the same item (none today) keep the one paying more per item.
- **Participate reads `unknown` without a successful read**: no Permission, a 401/403, or a failed read with nothing cached. A Character that joined and later resigned (`is_committed: false`) is `notParticipating`.
