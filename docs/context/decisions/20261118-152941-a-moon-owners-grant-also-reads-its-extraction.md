# Scope decisions — A moon owner's grant also reads its Extraction started notifications

_Recorded 2026-11-18. Amends `20261112-061917`, which ruled the notification out._

- **A moon owner's grant now asks for `esi-characters.read_notifications.v1` beside the mining and structure scopes.** An Extraction's ore make-up exists only in the Extraction started notification, and ESI's extraction list does not carry it, so a moon owner's chunks sat at "Ore unknown" unless an officer linked a Survey. The scope is the grant's third (`FEEDER_SYNC_SCOPES`, both copies, pinned by a test); a new or reconnected grant carries it.
- **Only the grant holder's own feed is read, and only the three moon drill types** (started, laser fired, cancelled). `moonNotificationsOf` keeps those and drops every other notification before anything is parsed or stored. The consent text says so. It is read in the same best-effort step as the Extractions, after a good ledger read, so a failed or unanswered feed never moves the moon owner's health and the Extractions still land with the ore they already hold.
- **Old grants keep working.** One from before this carries the first two scopes and is still accepted; it just gets no ore from notifications. The grant document says which it is (`readsNotifications`, absent on old ones), the way `readsStructures` does. There is no new "Needs you" prompt: a moon owner picks the scope up when they reconnect, which asks for the full set. (Superseded by `20261121-110155`: a grant without it now asks to be granted again, and the officer's Ore unknown tooltip says why.)
- **The notification supplies the chunk's ore, and now also the laser-fired and cancelled times.** These go through the book's own `reconcileExtractions`, with the moon owner's stored Extractions passed so a chunk keeps the start it was stored with (no duplicate under a second id). A chunk whose notification is still in the feed but whose ESI listing is gone because it arrived is kept or added, so ore reaches a chunk already past its pop; this lasts only while the notification stays in the feed. A chunk still to come is never added from a notification alone: ESI dropping it means it was cancelled, and a lost cancel notice must not revive it. This supersedes "the laser-fired time is not known for a moon owner": it is, when the grant reads notifications, and the window starts there; without it the window still starts at the natural decay time.
- **Source order is unchanged (D13):** the notification, then a linked Survey, then unknown.
- **What it rules out.** Reading any other notification type, or any other character's feed. A feed that carries no moon notification changes nothing.
