# Scope decisions — Trade Hub per character (issue #5593)

_Recorded 2026-10-29 · issue #5593._

- **Every hub-reading surface follows the active Character's Trade Hub.** One rule, no per-surface list. Notification polling and net-worth snapshots run per Character, so they use the polled Character's own hub, never the active one. With no active Character (all-characters view) the account default applies. Out of scope, unchanged: Market Browser hub (device-local), Moon Mining's Payee hub, Stock Lists. Appraisal's hub switcher, Hauling lane and other page-level pickers keep working; the Character's hub is their starting value.
- **Data is additive.** `sync.marketHub` stays the account default (older bundles keep working). New synced key `sync.marketHubByCharacter` holds one map `characterId -> hub`, last write wins, parsed entry by entry so one bad entry from another device drops alone. A Character with no entry uses the default, so upgrading changes nothing and adding a Character needs no write.
- **No seeding write on hydrate.** A seed written on one device would overwrite a hub set on another (the map is one LWW value). Instead, the default select pins every Character on this device that lacks an entry at the old default before it changes the default, so changing the default never moves existing Characters. Known gap: a Character held only on another device is pinned when that device changes the default, not this one.
- **Removal prunes only the removed Character's entry**, after the Dexie transaction. Never pruned by the local roster, since another device may hold Characters this one does not.
- **`useMarketHub` is now the hub in force**, a derived store with the same value/hydrated/hydrate/setValue shape, so the ~45 reading sites needed no change. `useDefaultMarketHub` is the raw default. Its `setValue` (page-level pickers, LP Store, BPC Sourcing settings) writes the active Character's entry, or the default with no active Character. Settings' own default control and the Settings phone summary use `useDefaultMarketHub`.
- **One Character: no per-character UI.** The select is labelled "Trade Hub" and moves that Character's entry (if any) with the default.
- **Layout is mockup variant B**: default select, a one-line summary ("2 on Jita, 1 on Hek"), a closed "Set per character" disclosure with a hub select per Character and "Apply default to all".
- **No active Character writes the default directly.** `useMarketHub.setValue` with no active Character (all-characters view) sets the account default without pinning anyone, the old behaviour; accepted.
