# Scope decisions — Page scope control: one scope control writes every widget's scope

_Recorded 2026-11-22._

- **Scope stays a per-widget setting; the page's scope control is its bulk edit.** The Overview and the Corp Board each carry a control (This character, All characters, and on the Corp Board a named corporation) that writes the choice onto every widget, with one Undo. The control is the existing `CharacterFilterControl`, extended with named corporations and a Mixed display, in the `PageHeader` / `CharacterHeader` `scope` slot, so it looks and behaves as it does on every other page (faces trigger, words in the tooltip and accessible name). A widget can still be set apart from its menu, and the control then reads Mixed. This rules out a separate page-level setting that widgets follow: two sources of truth would let a widget show one scope under a header that says another.
- **Each page keeps its own layout, so each keeps its own scope.** The Corp Board will usually sit on a corporation while the Overview sits on All characters; nothing is shared between them.
- **A widget names its scope only when it is not the default.** A widget on All characters or a named corporation shows a chip; one on This character shows none, because a portrait and "name only" repeated on every card is noise (the header control already says the page is on This character, or Mixed).
- **A corporation is a scope of the Corp Board only (`corp:<id>`).** It narrows the widget's All read to that corporation (`corpNarrow.ts`) rather than making a read of its own, so the per-corporation reads stay shared and cached. The Overview offers no corporation scope: narrowing its sums to the Characters of one corporation needs per-Character rows its feeds do not keep.
- **A kind that reads one corporation never shows a figure under the wrong heading.** Under All, or under a corporation that is not the header Character's, Cash flow, Members, Inactive members and the like ask for one corporation (with a button to use the header Character's) instead of reading it quietly. A bulk All on the Corp Board puts them on All too, so they ask; on the Overview it leaves a kind that cannot sum where it is (its menu already disables All for it).
- **A new widget opens on All characters wherever its kind can sum.** Saved layouts are not rewritten. Dev and prod share one Firebase project and its data: an older build that does not know `corp:<id>` reads it as This character, additively.
