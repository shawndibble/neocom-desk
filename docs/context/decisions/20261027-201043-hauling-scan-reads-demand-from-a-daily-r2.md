# Scope decisions — Hauling scan reads demand from a daily R2 object (issue #5344)

_Recorded 2026-10-27 · issue #5344._

- **Pass 2 of the hauling scan reads demand from a daily R2 object, not ESI history per item.** The old pass read ESI history one item at a time in price order and stopped at 400 reads (about 2% of the ~19,720 sellable items); over a broad category the top 400 are mostly dear, thin-market items, so liquid items below rank 400 were never checked and "first 40 to pass" was not "best 40". The `public-data-lp-store` job already folds EVE Ref's 30-day history files; it now also writes `hauling-demand/<regionId>.json` per hub region (`{ lastSyncedAt, asOf, days, types }`, each type a tuple of volume, days with trades, order-count sum, recent sale price, newest day's high and low). The client summarises every pass-1 candidate locally (`demandFromAggregate`, same answer as `summarizeDemand` on the same points) and keeps the best 40 by `historyScore` for the order books. Prices stay live: pass 1 (Fuzzwork) and pass 3 (order books) are unchanged.
- **`lp-store-volume/*` stays byte-for-byte unchanged.** The demand data is a new sibling object, so the LP Store page cannot break.
- **Missing or stale falls back to the old ESI path, 400 cap included.** "Stale" is a newest day of data (`asOf`) more than four days old (the daily job stopped). The footer says which path ran. `capped` on the daily path means more than 40 survived the demand check and the best 40 were cut. Instant mode is unchanged and never reads the object. With Any hub, the scan reads the objects of the destination regions its lanes use, and runs on the daily data only when every one loads; the 40 cap stays overall.
- **The data is 1 to 1.5 days old.** EVE Ref lists a day around 11:00 UTC the next day, so the newest day is usually missing at the 00:30 run. That is fine for a 30-day figure. Rollout: run the job once by hand (`workflow_dispatch`) before relying on it; the fallback covers the gap.
- **Daily volume divides by the 30-day window, as `summarizeDemand` does.** A day EVE Ref has not listed yet counts as zero, exactly as ESI's missing today does.
