# Scope decisions — Ship losses are no longer server-pushed

_Recorded 2026-10-29. Amends the 2026-10-25 decision `server-pushed-events-community-triggers-polled-price-alerts` and ADR 0027._

- **`shipLost` leaves the server-pushed events.** The `dispatchProjections` tick no longer reads zKillboard, and a closed app is no longer told about a loss. The open app's Foreground Poller still raises it (`diffShipLost`), and the minimum-ISK setting still applies there. Why: the reads cost the most of anything on the tick (measured over 7 days: about 45 s per run, almost all of it the 1 s spacing between ~36 zKillboard calls) and produced 22 pushes from ~12,000 reads. Nobody needs a loss alert while the app is closed.
- **The tick is price alerts only.** One Fuzzwork call per hub station. The paced loss reads, their per-run cap, the 5-minute wall-time budget and the back-off on 420/429 go with them, as do `fetchZkillLosses`, `diffShipLosses`, the `shipLossIds` reading, the `shipLostMinimumIsk` input and the `zkillboardCalls` run stat. The 540 s timeout was sized for those reads and is left for now; lower it once the new run durations are seen.
- **Rollout is safe in either order.** A registration that still holds `shipLost` is ignored by the new function: it is no longer a polled event, and a stored `shipLossIds` reading is dropped by `trimBaseline` on the next write. An old client that still uploads `shipLostMinimumIsk` registers fine; the parser ignores the key, even a bad value. An old function with a new client simply stops receiving `shipLost` registrations. The client no longer parses or renders a `shipLost` push, so a stray one in flight falls back to the sender's plain title and body.
- **Kept on purpose.** `shipLostText` and the kills poll domain (the open app still words and raises a loss), the SRP killmail lookups (single killmail reads, a different path), and `quietHours.ts`'s loss allowance (harmless, and a future server event may be a loss).
- **The closed-app badge no longer shows on Ship lost** in Settings: it follows `SERVER_PUSHED_EVENT_IDS`.
