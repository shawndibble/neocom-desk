# Scope decisions — Either side sets a moon owner's payee (issue #4653)

_Recorded 2026-10-21 · issue #4653._

- **Both sides set the payee; the last edit wins (owner decision).** Reverses #4619's moon-owner-only rule and the #4520 note that nothing sets a payee. The accounting corporation's Accountant or higher (`setCorpTaxBookFeederPayeeFromBookCallable`) and the moon owner's CEO, Directors and Accountants (`setCorpTaxBookFeederPayeeCallable`), each with a live role check, write through one core (`corpTaxBookPayee.ts`): `withPayee` stamps `payeeChangedAt`, `withPayeeChange` appends `payeeHistory`, `payeeSetBy` records the side, officer and time, and the audit entry `feederPayeeSet` names the side. Only while active or being removed. Unset still means the moon owner corporation itself.
- **The hidden 48-hour payee rule applies to a change from either side**, because both stamp `payeeChangedAt`. It stays out of every UI string, mail, tooltip and error.
- **The other side is told in-app and by a short mail.** In-app: a dismissable strip ("Payee changed") on the other side's page, dismissed per device in `localStorage` (no shared store fits one officer's "seen it"; a later change shows again); the moon owner's "Who gets paid" line also says who set it and when. Mail: kind `payee-change` through the existing queue, from the changing officer's own token, only with the mail permission, never awaited. The server names the recipients: for a moon owner's change, the book's officers with a live access record; for the accounting side's, `moonOwnerMailRecipients` of the old and the new payee (the moon owner's CEO plus both payees). The mail carries who gets paid now, for whom, who changed it and the date; never a rate, the margin or any timing rule.
