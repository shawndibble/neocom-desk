# Scope decisions — Corp Doctrine Fits show in members' Fittings library (issue #6202)

_Recorded 2026-11-15 · issue #6202._

- **A corporation's SRP Doctrine Fits are listed to every member in the Fittings library, read-only and tagged Doctrine.** This narrows the "a Doctrine concept" ruling in [20261020-163024-appraisal-gets-a-from-my-fittings-source-not.md](./20261020-163024-appraisal-gets-a-from-my-fittings-source-not.md): the corp's own Doctrine Fits, which SRP Directors already enter, are now visible to members as library rows. Once they are there, Your Characters, Appraisal's From my Fittings (after Save a copy) and Export work on them unchanged. Personal or named doctrine sets, a Doctrines tab or page, roles or counts per doctrine, alliance doctrines and authoring outside SRP all stay out. Corp-wide readiness across members' characters (#4614) stays rejected, because it needs members' skills shared.
- **Members read them through a member-verified SRP router action, and the `srpDoctrines` rules stay officers-only.** Firestore rules cannot check current corp membership; the callable re-checks it live, so a Character who left the corp sees none. SRP off lists none, and the library shows no empty state for it.
- **A Director's save also stores the whole fit as a Fitting Share Code beside the snapshot.** SRP matching still reads only the snapshot (hull, modules, rigs, subsystems). Fits saved earlier are not migrated: they open from the snapshot alone, with the note "Saved without drones or charges. A Director can re-save it to include them." The field is optional, so dev and production can share one Firestore.
