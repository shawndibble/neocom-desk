# Scope decisions — Mail read-state syncs to ESI — the app's first write (issue #741)

_Recorded 2026-09-10 · issue #741._

- **Reading a mail in-app now writes back to ESI (`PUT /characters/{character_id}/mail/{mail_id}/`, `esi-mail.organize_mail.v1`), marking it read so it survives a real page reload — the app's first-ever ESI write, ending the "read-only by design" posture `src/esi/scopes.ts` and `CONTEXT.md` had held since issue #416.** Rejected the cheaper read-only alternative (persisting `locallyReadIds` to Dexie instead) because it never syncs the read flag to the game client or any other tool reading the same mailbox — it only hides the app's own re-fetch, not the actual staleness. Accepted the cost this widened Base Grant carries: every existing user re-consents on their next login (a real UX interruption, not silently absorbed), and the write is fire-and-forget with no persistent retry queue — mail-read state is idempotent and low-stakes, so a failed write just gets another chance the next time that mail is reopened or the mailbox reloads. This rules out any future "just add one more small write" without weighing the same re-consent cost again; it does not open the door to broader mail actions (delete/label/reply), which stay explicitly out of scope.
- **Consent-screen disclosure for the new scope does not go in the existing "Signing in grants read-only access to…" sentence on the login page.** Adding it there would make the sentence self-contradicting (a "read-only access" list that includes a write). Instead it's a separate fine-print line beside the "Read-only" trust card, and the two nearby absolute claims ("it never writes to your account", "no mail is sent") are softened to "nothing else about your mail is changed" so they no longer overstate against the one exception. `Login.test.tsx`'s scope-to-copy guard (`BASE_GRANT_PHRASES`, pinned against `esi/registry.ts`) is split into `READ_ONLY_PHRASES` (checked against the read-only sentence) and `WRITE_SCOPE_PHRASES` (checked against its own line) so the guard keeps forcing every Base Grant scope to have _some_ disclosure without forcing the write's disclosure into the wrong sentence.
