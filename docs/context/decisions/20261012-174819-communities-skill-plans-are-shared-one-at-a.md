# Scope decisions — Communities: Skill plans are shared one at a time

_Recorded 2026-10-12. Mockup: Option A, one flat tab row (removed from the repo once built; git history keeps it)._

- **There is no "share all" for Skill plans.** Each plan is shared by the Member, one at a time, from the Skill plans tab of a Community: a search adds a plan, Stop sharing removes it. Blueprints and Fittings can be shared wholesale; plans cannot, so a plan never reaches a Community the Member did not hand it to.
- **What is shared is the plan's name and its ordered skill targets** (skill, level, priority), nothing else: not milestones, Remap Markers, implants or boosters, and never the sharer's skills or clone. A plan may hold at most 500 skills to be shared.
- **A shared plan follows its owner's edits, by sweep.** Plans are written from several places (the list, the editor, the target picker, sync), so there is no one save to hook. A sweep, at boot, every half hour and when the Skill plans tab opens, pushes a shared plan whose own `updatedAt` is newer than the one its copy was made from, and removes the copy of a plan that was deleted. It never shares anything new.
- **Others copy a plan; the copy is theirs.** Skills › Plans › New plan › "From a Community plan…" opens a search over every plan the pilot's Communities share (by plan name or sharer), shows who shared it and where, and Copy to my plans makes an ordinary plan from the name and skills. It does not follow the original. The Community's Skill plans tab links to the same view (`/skills/plans?browse=community`).
- **Same gate and lifetime as the rest (ADR 0018).** Readable only by Members; written only by the owning Character under the `ownerHash` guard (doc id `<uid>~<plan id>`); entries are a flat list of triples because Firestore has no nested arrays; leaving or removal deletes that Member's plans at once; a logged-out Character is offered the same removal.
- **Needs a deploy.** The `skillPlans` rule and the delete-on-leave change are new, so `firebase deploy --only functions,firestore:rules` must run before sharing works against production.
