# Scope decisions — Every read Permission is on by default; a re-login fills every gap (issue #6102)

_Recorded 2026-11-12 · issue #6102._

- **Every read Permission is default-on.** `corp`, `structureMarkets`, `jumpFatigue`, `corpProjects`, `killmails` and `mercenaryDens` join the Base Grant, so a plain sign-in or Add character asks for every read. Each used to cost its own trip to EVE's login, and a player with many Characters on many EVE accounts signed out of one account and into another for every one. Only the six Write to EVE Permissions stay opt-in, unchanged. A player who wants less unticks it in Customize permissions, which still lists every Permission; the Opt-in tag now marks only the write ones. Supersedes in part `20260910-123303` (roles scope opt-in), `20260906-203425` (structure markets opt-in), `20261025-110041` (mercenary dens opt-in) and the opt-in wording of `20260924-143410`.
- **A re-login for a known Character fills every gap in one trip.** `beginEveLogin` asks for the Core Grant, the named groups, the Character's stored scopes and every default-on Permission it lacks, minus any the player unticked in Customize permissions. That device-local Customize choice is the only record of a declined Permission (Settings › Permissions has no off switch; revocation is on CCP's site), so it is what keeps #1520's rule that a re-login never re-requests a declined Permission. A named group is asked for even when unticked there, since the player just pressed for it. If the Customize choice cannot be read, the fill is skipped (Core + named + stored). The choice is per device, not per Character: unticking a Permission while adding one alt keeps it out of every Character's re-login on that device, and a device that never customized fills everything. Accepted, since there is no per-Character record of a decline to read.
- **A Customize choice saved before this change keeps what the player unticked and gains the six.** It was stored as a bare list; the new shape is `{ groups }`. In a bare list the six were unticked by default, so their absence says nothing and they read as ticked; everything else stays as stored. Write Permissions ticked there stay ticked in the dialog but are never part of a re-login fill.
- **No nag for existing Characters.** No banner, dot or count is driven by `defaultOn`; the Permission count already counted the five non-corp formerly opt-in Permissions, so a Character signed in before this change shows the same "n of N" as before. They pick the new scopes up on their next re-login for any reason, or from Settings › Permissions. Revocation is still judged requested vs granted, so nothing is purged.
- **Holding a scope calls nothing.** Corp reads stay gated by Corp Roles (`useCorpAccess`, `corpScopes.ts`), the Corporation row and corp banners stay hidden without a role or in an NPC corporation, and a structure market 403 stays a normal "not on the ACL" outcome. Granting a scope the roles cannot use is harmless.
- **Corporation stays out of the Permission count** (`20261022-190018` stands). Whether a Character can use it still needs a roles call per Character, and holding the roles scope does not answer that without the call.
