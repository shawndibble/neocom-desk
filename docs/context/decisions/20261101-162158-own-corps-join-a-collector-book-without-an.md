# Scope decisions — Own corps join a Collector book without an invite link

_Recorded 2026-11-01._

- **<Decision>.** <Why, and what it rules out.>
- **A self-invite, not a new join path.** `addOwnCorpTaxBookFeederCallable` mints an internal invite document (`selfInvite`, `sameOwner`, never shown, exempt from the 20-open-link cap) and runs the existing `saveFeederGrant` with its code, so the ledger-read role check, the unwind on refusal and the pointer/grant writes are the ones already tested. Any failure deletes the self-invite. It rules out a second accept transaction that could drift from `acceptInviteCore`.
- **The same owner is proven by the refresh token, not an account link.** The caller must be an editor of the Collector (live roles read, as for an invite link), and must hand over the CEO alt's mining-scope access and refresh tokens in the same request; the server refreshes that token and reads the alt's corporation, refusing `wrong-corp` when it is not the corporation the client named. Controlling that refresh token is the proof; no check that the alt shares the player's account was invented, since the app has none and the invite-link path already lets any alt on any account hand over a grant.
- **`coverageFrom` is clamped, never trusted.** The join may ask for a first covered day: not after today, not before today minus 30 days (EVE keeps about 30 days of ledger), not before the book's start date, and for a rejoin never inside an earlier period (`clampCoverageFrom`, mirrored in `functions/src/corpTaxBookEngine.ts`), so `reopenPeriod` cannot throw. Absent means today, as before. Ordinary invite links gain nothing from this: they carry no `coverageFrom`.
- **`sameOwner` is "settled otherwise", not a 0% owner rate.** A 0% rate would still accrue, show a rate, ask for payouts and read "no rate set" until someone typed it; settled otherwise already means "no owner rate, no payouts, no pay-list row, not a thing to look at". The record is stamped `sameOwner: true`, mode `settled-otherwise` with a mode change from the coverage start, and gets no `ownerRateHistory` or `offeredOwnerRatePct`. The Moon owners tab forces the settled reading for a `sameOwner` record (`settledNow`), so it stays `settled-otherwise` even if a stored mode change were flipped, and it is not counted in `needALook`. The summary path still serves it (`summaryFor` accepts a single settled mode change).
- **Remove keeps history.** `removeOwnCorpTaxBookFeederCallable` is for an editor of the Collector and only when `record.sameOwner === true` (else `not-yours`); it ends the moon owner at once through `endFeeder` (`removed`, coverage closed the day before, pointer and grant dropped, record kept). The 24-hour notice mail stays for every other moon owner.
- **Additive Firestore only.** `sameOwner` on the feeder record and the invite, `coverageFrom` and `selfInvite` on the invite, and `sameOwner` on the join audit entry are all optional; older readers ignore them, and dev and prod share one Firebase project. A rejoin carries `sameOwner` over. Needs-sign-in on an already-connected record reuses the Reconnect code through the existing grant action.
