# Scope decisions — Community Request admin removal and the expiry grace week

_Recorded 2026-10-15 (issue #3812)._

- **The admin removes a Request or a Pledge from the side panel only.** The panel carries a visible **Remove request…** and, per Pledger (named from the Members list; the panel shows aggregates to everyone else), **Remove…**, each behind a `ConfirmDialog`. There is no board row menu: a row gets a ⋮ only for two or more real actions (DESIGN.md §6c), and the row click already opens the panel that carries this one. Non-admins see none of it.
- **Removal is a callable, never a client write.** `removeCommunityRequestCallable` and `removeCommunityPledgeCallable` check the caller is the Community's admin under their current ownerHash (`requireAdmin`), then delete with the admin SDK (the Request recursively, with every Pledge under it). The rules stay as they were: the admin's client can delete neither (tested). There is no per-Community switch.
- **An expired Request is kept 7 days, then swept.** The daily `sweepCommunityRequests` deletes a Request 7 days after its `expiresAt` (`EXPIRED_RETENTION_MS`), with its Pledges, so it shows as Expired and the requester can still Extend it during that week (Extend on an expired Request is allowed and counts against the open cap). A closed Request goes 7 days after `closedAt` (`CLOSED_RETENTION_MS`), whatever its expiry; closing always stores `closedAt`, so there is no fallback. The sweep re-reads each candidate right before deleting, so one extended or reopened meanwhile survives, and it deletes at most 500 Requests a run (the rest continue next tick; the function takes the 540s timeout).
