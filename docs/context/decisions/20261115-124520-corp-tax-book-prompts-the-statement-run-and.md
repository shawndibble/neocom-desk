# Scope decisions — Corp Tax Book prompts the late-notice run and dots the Moons nav (issue #6208)

_Recorded 2026-11-15 · issue #6208._

- **One run sent every missed calendar period, oldest first.** A forgotten month went out with the next one, each period issued and its mail queued before the next started, so a failure part-way kept what was issued. Superseded by decision 20261120-235011: there are no calendar periods. A run plans one Late notice per Miner who is behind, a notice whose mail never left is offered again, and the queue's pace (one every 12–15 s, tab open) is EVE's limit and is unchanged.
- **The run stays a click, never automatic.** Automatic sync still never issues a Late notice or sends mail: mail goes out from an officer's Character in an open tab. "Needs you" carries one card whenever a run would send a Late notice; its title links to the Late notices tab, where the run is. It counts as one card however many Miners are due. It is computed from the whole-book view on both the read-model and live paths, so it adds no kind to `NeedsYouItem`.
- **The corp Moons nav entry wears the attention dot, not a count, for a book editor.** It lights while "Needs you" has a card (including the run card) or Automatic sync has stopped: one thing to go and handle, the existing §6c dot (`NavItem`'s `attention`). A count would mix cards and a stop, which are not the same unit. The book is too heavy to load in the shell, so each Moons visit stores what it found per Character and corporation in Dexie and the nav reads that; only an editor's visit stores it, and a viewer's visit clears it. Between visits, the open app rereads the one Automatic sync status doc every 30 minutes (visible Tab Leader only, never minting a token, and only for a Character whose editor visit is on record), so a stop lights the dot without a visit. Overdue, Unmatched and a due run move only on a visit or a reload of the book. A visit that finds no book, or no access to it, clears the dot. Late notices issued earlier whose mail never left raise no card: the run offers them whenever it is opened. The phone's More button does not echo it: the Moons page is desktop work.
- **A stopped Automatic sync is also a server-pushed alert, "Automatic sync stopped" (`corpTaxBookSyncStopped`), from the existing scheduled job.** It fits ADR 0027 with no new deployed function: `syncCorpTaxBooks` calls `deliverServerEvent` after `stopGrant` commits, as the vetting router does for `vettingShared`. It goes to the book's editors: officer records with edit rights checked in the last 30 days, plus the holder unless they lost the role or left the corporation (each Character once, 25 at most). It is not raised when the book was turned off on purpose (`book-off`). Like every server event it reaches only devices that opted it in (offered to every Character, default both channels, under World like vetting, since it needs no Corporation Permission and fires with the app closed), it never throws, and the run waits at most 5 s for it. A Collector (moon owner) grant's stop sends none. Functions are not auto-deployed, so it is live only once `syncCorpTaxBooks` is redeployed.
