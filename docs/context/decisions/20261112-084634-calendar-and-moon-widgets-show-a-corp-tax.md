# Scope decisions — Calendar and moon widgets show a Corp Tax Book's moon owner pops (issue #6116)

_Recorded 2026-11-12 · issue #6116._

- **The Calendar, Due soon and the Moon extractions widget also read the moon owners' Extractions a Corp Tax Book holds.** A CEO who runs one book for many corporations looks for pops there, and those corporations are read by the book's grants, not by a stored Character with a corp grant. It rules out asking players to add every alt CEO as a Character just to see pops.
- **Who reads a book: a Character whose roles open the Moons page** (Director, Accountant, Junior Accountant; `canViewCorpTaxBook`), under the officer rules. A lapsed officer record is renewed once, as the book's other reads do. One Character per book; the active one when it qualifies.
- **ESI wins per corporation.** A corporation some Character reads from ESI keeps its ESI rows, and the book's copy is dropped, so no pop shows twice and the fresher read wins. Only the book's moon-owner rows are read (`sourceCorporationId` set); the book's own chunks already come from ESI.
- **Read from the Overview read model (ADR 0032).** One doc per book, already windowed and without cancelled chunks, plus the small `feeders` collection for refinery names and each moon owner's last read (the rows' Data Age). A book whose read model is not built yet reads its live `extractions` (`naturalDecayTime` after now) instead. Only live chunks count, so a book whose moon owners' pops are all past adds nothing.
- **Best effort, bounded and reused.** The book read starts beside the ESI reads and is left out after 15 s. A read or a refusal is reused for 5 minutes, so a refused officer check is not repeated every load. "This corporation has no book" is reused for an hour, because the gate is a role check and most officers' corporations run no book. A book that cannot be read adds nothing. A widget, Due soon or Calendar whose every ESI read failed still lists a book's pops, and only shows Retry when no book answered either.
- **A moon owner's row names its corporation.** The Calendar puts each row under its corporation, as it does for every corp row. In the Moon extractions widget a book row reads `Refinery [TICKER]` (EVE's ticker brackets, after the name so the widget's short name keeps it). Due soon passes corporation labels whenever a book row is present, even for one corporation. The widgets still have no Corporation column (`20261111-221423`).
- **Known limit: the widget's own gate.** The Moon extractions widget is offered to a Character with `canReadMoonExtractions` (Station_Manager plus the mining scope). An Accountant or Junior Accountant who views the book without that role gets the pops on the Calendar but not the widget. Opening the widget to book viewers would be a new corp capability across the capability lists, scopes and permission screens; a CEO or Director already has it.
- **Out of scope:** server-side alerts (push or mail) for moon owners' chunks.
