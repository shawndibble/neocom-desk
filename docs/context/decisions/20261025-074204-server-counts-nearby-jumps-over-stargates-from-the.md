# Scope decisions — Server counts nearby jumps over stargates from the game location (issue #5122)

_Recorded 2026-10-25 · issue #5122._

- **The server counts a closed-app nearby alert's jumps over stargates only.** It runs a byte-for-byte mirror of `engine/route/jumpRoute.ts` over a bundled copy of the stargate graph and system security (`functions/src/data/stargateGraph.ts`, `scripts/build-stargate-data.mjs`), under the device's uploaded Travel Settings (preference, security penalty, Avoided Systems already resolved on the device, pod-kill / EDENCOM / Triglavian rules included). It leaves out the open Thera / Turnur holes and Ansiblex bridges `loadJumpBasis` adds in the app: holes need EVE-Scout's live list and bridges are the pilot's own synced data, and both only ever shorten a count. So a closed-app alert can come a little later than the open app's (fewer things count as near), never for something the app would call farther than N.
- **Its origin is the game location, not a hand-picked Current System.** A pick (`currentSystemPicks`) is device-local and "about this session"; with the app closed there is no session, so the server reads `GET /characters/{id}/location` and uses that. While the app is open its own poll still honours the pick.
- **The Travel Settings are a snapshot from the last upload.** The pod-kill part of the avoid list moves hourly; the server uses whatever the device last uploaded (at most an hour old while the app is open, older once it closes). Recounting server-side would need the kill feed per device and is not worth it for an alert threshold.
