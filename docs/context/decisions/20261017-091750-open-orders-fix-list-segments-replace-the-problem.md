# Scope decisions — Open Orders fix list: segments replace the problem groups (issue #4011)

_Recorded 2026-10-17 · issue #4011._

- **The Needs you / Watch / All segment replaces both the eight problem-group headers and the `hideHealthy` fold, and lives in the URL as `orders.view` (default `act`).** One flat worst-first table; the segment splits what the funnel matched by **Order Urgency**, and each segment's count is the rows it shows. `orders.hideHealthy` is gone: healthy orders are the Fine bucket, reached through All or the "N healthy orders · Show" line under the list. The segment is not a removable filter chip (there is always one), and "Clear all" keeps it. A link naming Watch problems (`openOrdersHref({ problems })`) opens on Watch or All, so a tile never lands on an empty Needs you.
- **Worst first means Needs you first.** Problem precedence alone puts a region undercut (Watch) above an expiring order (Needs you), so the default sort orders by urgency, then precedence, then ISK tied up. A sort the pilot picks from the funnel or a header holds across the whole list.
- **A row the page must show widens the segment to All, derived, never written.** A notification's `?highlight=` row outside the picked segment shows All until the pilot picks a segment; the work-through's current order does the same while the walk runs. Supersedes the "highlighted row forces its group open" rule (decision `20260924-003053`, step 9) in the same spirit: local derivation, no URL write racing `useHighlightParam`.
- **The work-through queue keeps its members and walks Needs you, then Watch.** Overview's "Work through (N)" counts every order that needs a fix (`needsAttentionCount`), system and region undercuts included, so the queue still takes those in; it walks them after the Needs you rows, in the table's order, and the segment widens to All once the walk reaches one.
- **"Do this" is its own pure call (`orderDoThis`), read off `adviseOrder`.** A verdict (with an Order Floor) wins; without one a station undercut still names the one-tick-under price the row always offered to copy, and an outbid buy order the one-tick-over bid. The right-click "Copy new price" copies the same price, so the cell and the menu never disagree; a "Do not chase this one" row has none.
- **Columns: five optional columns, all off, under a new setting key (`openOrdersOptionalColumns`).** The grouped page's `openOrdersVisibleColumns` is not reused: a pick saved there (price, floor, remaining, expires) is valid under the new ids and would switch four columns on for a pilot who never chose them. The floor column no longer hides itself when nothing has a floor; it reads "—".
- **Per-group "Refresh system & region prices" leaves the page.** The Order Detail's Who is cheaper section keeps the button; `useOrderDetail.checkDeeper(rows)` keeps its fan-out cap, now tested on the hook.
- **The notice stack folds into one quiet line at the list's foot**: fees at base standings per Character (with a ghost Grant `Button` in `NeedsConnection`, shown only once the grant is known to lack standings, as `GrantNote` does) and Characters that have not shared their orders. Re-auth `GrantBanner`s stay where they were. **`CachedNotice` does not fold in:** DESIGN.md has it above the view's content at every width, because below `md` the header's `DataAgeBadge` is hidden and it is the only place a phone shows the data's age; it is one short line, and only offline.
