# Scope decisions — server-side mining price snapshot: fuzzwork 6h capture + adam4eve one-time backfill (issue #1279)

_Recorded 2026-09-25 · issue #1279._

- **Added a 4th Cloud Scheduler job, `captureMiningPriceSnapshot`, every 6
  hours.** Mining Yield Overview's daily price previously came from ESI's
  history endpoint, which only has a blended buy+sell _average_ per day —
  wrong for a pilot who priced on one side, and the reported bug ("Jita buy
  and Jita sell show the same number"). `syncPublicContractOffers`'s own
  comment budgeted the deployment against 3 free Cloud Scheduler jobs per
  billing account; this is now a 4th, so the free-tier assumption no longer
  holds and the deployment cost is not zero going forward.
- **Two sources, one `marketHistory` collection, split by a per-day
  `source` tag.** Live capture (`source: 'fuzzwork'`) reads Fuzzwork's
  aggregates for the 5 major trade hubs every 6 hours and folds each
  capture into a running per-side average for _today's_ doc — this exists
  going forward whether or not any pilot opens the app that day, unlike the
  prior per-browser Dexie snapshot it now sits alongside. One-time backfill
  (`source: 'adam4eve'`) fills whatever day in the 90-day retention window
  has no doc at all yet, from Adam4EVE's `market_price_history` — a real
  buy/sell split, but region-wide (The Forge), not station-level. Once live
  capture has covered every day in the window (~90 days after this ships),
  the backfill path runs itself out of work and goes idle; it self-heals a
  missed run rather than needing to be re-triggered.
- **Adam4EVE's `*_price_high` field, both sides.** Verified 2026-09-25
  against live Fuzzwork Jita aggregates for Tritanium (34) and Compressed
  Bitumens (62454) across three same-day comparisons:
  `buy_price_high`/`sell_price_high` tracked Jita's real buyMax/sellMin
  within ~0.6% both times, while the sell side's `*_price_low` ran 15-20%
  low (region sell orders include far-flung, near-zero-volume outlier
  listings) and `*_price_avg` also ran low. One field name for both sides
  rather than a different pick per side, because the finding held for both.
- **A new `historical` price-basis tier, ranked between `live` and
  `average`.** `saved` (station-exact, either source) beats `historical`
  (real split, region-wide) beats `average` (ESI's blended number, not even
  the right side of the book). Adam4EVE-sourced days feed `historical`, not
  `saved` — conflating them would have hidden the region-vs-station
  distinction from the row-level "how sure is this price" tag.
- **Adam4EVE backfill scoped to Jita/The Forge only, not all 5 hubs.** The
  Overview's pricing only ever reads `DEFAULT_TRADE_HUB` (Jita); getting a
  historical split for the other 4 hubs from Adam4EVE would need 4 more
  regionID sweeps for no current reader. The live 6-hour capture still
  captures all 5 hubs going forward, for a future multi-hub feature.
- **`functions/src/data/miningTypeIds.ts`, generated by
  `scripts/build-sde.mjs`, not read cross-package from `public/data/`.**
  Cloud Functions deploys only bundle `functions/`'s own source tree, so
  `functions/` cannot read the app's `public/data/*.json` bake outputs at
  runtime. A generated `.ts` array literal (not `.json`) sidesteps
  `functions/`'s NodeNext module setup needing either `resolveJsonModule`
  plus per-call-site import attributes, or a runtime read-and-copy step.
