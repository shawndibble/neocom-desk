# Scope decisions — Move read_corporation_roles into the corp scope group

_Recorded 2026-09-10._

- **`esi-characters.read_corporation_roles.v1` moved from the base grant into the opt-in `corp` scope group.** It was the one corp-adjacent scope every character was asked for at sign-in, purely so the app could tell whether corp UI was worth showing at all. Moving it removes that scope from the ~95% of characters' consent screen who will never grant the rest of the group anyway. Existing characters who already held it keep it (`app/loginFlow.ts` unions with the stored grant) — this only changes what a _newly added_ character is asked for.
- **Cost accepted: the proactive "you just made Director, grant now" nudge (`CorpGrantPrompt`) no longer fires for a character that has never granted the `corp` group.** That nudge worked by reading role for free from the base grant; a role is now unknowable before opt-in, the same limitation `getCharacterMining` already lives with (`esi/registry.ts`). The only way in for such a character is the permanent Settings Corp access row.
- **`useCorpAccess` gained a fifth state, `not-granted`, rather than folding this into `roles-without-grant`.** Folding would put the Grant-access banner (`CorpGrantPrompt`) in front of every character who has never granted the group, including the ~95% who hold no corp role at all — exactly the consent-nagging round 42 exists to prevent, and the banner's copy names the roles held, which are unknown in this state. `not-granted` renders as nothing everywhere `none` and `roles-without-grant` already do (no nav item, no tab, no lock), and `CorpGrantPrompt`'s render condition stays pinned to `roles-without-grant` alone, so it is excluded automatically. Only the Settings Corp access row (`CorpAccessPanel`) surfaces it, with its own Grant button and a "Unknown until granted" Roles cell.
- **The corp-nav visibility gate (`Layout.tsx`'s `CorpNavItem`, `state !== 'ready'`) needed no change.** It already hides for any non-`ready` state, so it hides for `not-granted` the same way it already hid for `none` and `roles-without-grant` — no separate "has this character opted in" flag was needed.
