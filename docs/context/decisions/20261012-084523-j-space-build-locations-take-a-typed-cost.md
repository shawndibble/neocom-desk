# Scope decisions — J-Space build locations take a typed cost index, remembered per facility

_Recorded 2026-10-12._

- **A system ESI lists no cost index for reads as 0, not as "no prices".** ESI's `/industry/systems` omits wormhole systems and CCP publishes no value, so the old `null` made `pricesReady` false and blanked every price. `MarketSnapshot.systemCostIndex` stays `null` only when the ESI call failed (the offline signal); an answered call with no entry for the system gives `0` and `systemCostIndexMissing: true`. Rules out inventing a constant: the real index moves with the system's industry activity.
- **The pilot's typed index replaces it (`BuildPlanRecord.costIndexOverridePct`, a percent).** Applied once, in `resolveBuildPlan` and Auto Build, through `applyCostIndexOverride`, so the page, Compare and group rollups price the same fee. It also wins over an offline `null`. Shown as a Setup field only when ESI has no figure or an override is already set, with a visible note and an `InfoTooltip` saying to read it from the Industry window's Facilities tab. Primary Build location only: a Reaction Location has its own snapshot, and a manufacturing percent is the wrong number for it.
- **A location change drops the override** (it was read for one system), and recalls whatever is remembered for the new place.
- **Rigs, tax and the J-Space index are remembered per facility, for every facility.** `facilityMemory.ts` files them in the local `settings` table under `industry.facilityMemory`, keyed by the picked structure (else the system), so a second plan at the same structure starts with them. Unsynced and with no Dexie version: it is a cache of the pilot's own answers. The index is filed only where ESI has none; clearing it forgets it, so a deliberate clear is not undone. Separate from the Remembered Location (where the next plan starts), which holds one place per activity, not per structure.
