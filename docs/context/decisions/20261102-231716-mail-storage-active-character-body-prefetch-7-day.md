# Scope decisions — Mail storage: active-character body prefetch, 7-day bodies, 30-day drafts (issue #5882)

_Recorded 2026-11-02 · issue #5882._

- **Mail bodies are prefetched for the active Character only.** The 20 newest bodies are no longer downloaded in the background for every alt on boot and on each poll. Headers still load for every Character holding the scope (the All view, the unread counts and new-mail alerts need them); an alt's body is fetched when its mail is opened, and offline an unopened alt mail shows "not downloaded". Narrows decision `20261016-030421`, which warmed "the active Character and every other one holding the scope". Calendar details for other Characters are unchanged. Reason: the owner's goal of storing as little mail content as possible on the device; the reviewer's counterpoint (bodies sit in the same profile as the refresh tokens, so the privacy gain is modest) is accepted, the saving is in storage and background traffic.
- **A cached mail body lives 7 days, not 30, and the rule no longer exempts a mail that is still listed.** The old rule kept any body whose header was in the cached list regardless of age, so cutting 30 to 7 alone would have changed almost nothing for the newest 50 mails. The `referencedBy` exemption is removed for `mail:<id>`; a body older than 7 days is deleted by the daily prune and fetched again when opened (the active Character's newest 20 are re-warmed by the prefetch). Rules out: reading a mail older than a week offline without having reopened it that week.
- **A mail draft not edited for 30 days is deleted** by the same daily prune (Cancel used to keep a draft forever). No UI: a draft is restored as left, and one this old is almost certainly abandoned.
