# Scope decisions — additive corp capabilities do not hide corp ui while their scope is missing (issue #4058)

_Recorded 2026-10-18 · issue #4058._

- **`canReadMiningLedger` is an additive Corp Capability.** It answers to Accountant (and Director) and needs `esi-industry.read_corporation_mining.v1`, a scope the corp group already carries. An Accountant who granted the corp group before #327 added that scope holds every wallet scope and not this one. Requiring it the way #327 did would drop them from `ready` to `roles-without-grant` and hide their working corp wallet until they re-granted. Additive, a missing scope leaves Corp Access `ready`, keeps `canReadMiningLedger` off (so nothing reads the ledger into a 403), and names the scope in `missingScopes`.
- **Asked once, through the existing re-grant flow.** The corp grant prompt is also offered when the state is `ready` with `missingScopes`, under the same offer record keyed on the corp group's scope set — a Character who has not seen the full group's offer is asked once, and either button retires it. The Settings Corporation Permission row shows Not granted with its Grant button in the same case, as the durable path back. No new copy or control.
- **Additive is the pattern for later corp capabilities whose scope existing `ready` users may lack.** A capability belongs in `ADDITIVE_CORP_CAPABILITIES` (`features/corp/corpScopes.ts`) when its scope can be missing for Characters whose other corp surfaces work; it rules out the #327-style cost of hiding every corp surface to offer one new one.
