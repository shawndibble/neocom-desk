# Scope decisions — Group the corp board by kind, and pay for the lost ranking with a day strip (issue #566)

_Recorded 2026-09-07 · issue #566._

- **The `/corp` overview groups the board by kind, reversing `engine/corp/board.ts`'s own stated thesis.** That module's header says outright: "Merging them into one deadline-ordered list _is_ the feature." It was right about what the merge buys — "what is next" is answered perfectly — and wrong that it is the only question a corp manager arrives with. "What is my fuel situation" was unanswerable without reading past the moon drills, and on a 2000px viewport the single list left most of the page empty: the board track absorbed ~1400px while its row is a 96px countdown beside a text block with nothing to fill the rest. This rules out treating the flat list as the canonical rendering; it does **not** rule out the merge itself, which is still the only ranking on the page.
- **The ranking stays in the engine, and grouping never re-sorts.** `groupBoardByKind` filters `buildCorpBoard`'s output and preserves its order inside each group; `CorpKindCards` renders `CorpBoardRow` itself rather than its own countdown. A second ordering, or a second countdown, is the specific failure this rules out — four cards each deciding urgency differently, or one card printing a figure the short-timer rule refuses.
- **The Deadline Strip is the price paid for the lost single ordering, and it is not optional.** Four cards can each show a calm top three while, between them, they hide a bad Tuesday. The strip counts every readable clock per local calendar day and colours each day by the worst severity landing on it, so the cluster the merge used to make unmissable is still unmissable. Removing the strip while keeping the grouping would reintroduce exactly the blind spot this decision accepted.
- **Days are local calendar days, not rolling 24-hour windows.** The strip labels weekdays and dates, and a manager plans against "Tuesday", so a UTC bucket would file a Tuesday-evening timer under Wednesday for everyone west of Greenwich. `deadlinesByDay` therefore reads the machine's own zone deliberately and takes no zone argument.
- **Three bucketing rules, each a decision rather than a fallout.** `timing: 'untimed'` lands on no day (an offline service has no instant, and counting it would invent one). `timing: 'passed'` lands on day 0 (ESI drops `fuel_expires` once a structure runs dry, so there is no instant left to bucket, but the thing is outstanding now). An overdue-but-timed item also lands on day 0 rather than the day it expired — the strip is a forward look at outstanding work, and a bar in the past would be unreachable. This rules out reading the strip's total as the board's total: the two differ by the untimed items and anything beyond the window, which is asserted rather than assumed.
- **`serviceOffline` gets its own surface, not a fifth card.** It is the board's one untimed kind, so it has no clock to take a "most urgent three" from and no day to land on in the strip. A card would order it meaninglessly; dropping it would be a visible regression, since it renders in the flat board today. It becomes a full-width chip strip, present only when something is actually offline.
- **Standing degrades figure by figure, not panel by panel.** It mixes sources — the clocks come from structures/extractions/jobs, the money from the wallet — and a Character can hold either without the other. Runway and 30-day net are simply absent without `canReadWallet`; "Due in 24h" and the strip are absent without any board source; with neither, no panel. This rules out a hero band with holes in it, which is what a panel-level gate would have produced for a Station Manager who is not an Accountant.
- **The Deadline Strip is CSS bars, not a scaled SVG.** The first draft was one `viewBox` scaled to its container — the ordinary way to make a chart responsive — and it put 12px labels through a 0.26 scale factor on a 390px viewport, rendering every count at about three pixels. Percentage-height divs keep labels as ordinary DOM text, so the type scale means what it says at every width. This rules out reaching for a charting dependency too: fourteen bars, a hairline and direct labels need none.
- **`PageHeader` gained a `subNav` slot rather than `/corp` hand-rolling its header.** The default stack — title band, tab bar, then the first panel's header — was ~110px of chrome before any data on the route whose whole job is triage. Hand-rolling one route's header is precisely the drift `PageHeader` exists to prevent, so the slot is shared, and `tabListFlushClassName` exists so the bar brings no second baseline rather than fighting `border-b` with `border-b-0`.
- **The People panel names a capped handful of members.** "Dark 30d+: 3" prompted a question the page could not answer. `peopleHighlights` caps each list at three, and the loader resolves names for only those ids — so this costs one `/universe/names` call for at most nine ids however large the corporation is. This rules out naming the roster on the overview, which for an alliance-holding corp would be a chunked batch of a thousand ids to print three lines.
