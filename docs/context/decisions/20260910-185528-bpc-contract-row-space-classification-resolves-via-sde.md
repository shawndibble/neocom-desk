# Scope decisions — BPC contract-row space classification resolves via SDE snapshot only (issue #796)

_Recorded 2026-09-10 · issue #796._

- **A public BPC contract row's Space (highsec/lowsec/nullsec/wormhole) resolves through the bundled SDE snapshot only (`lookupNpcStation` + `lookupSolarSystem`), never through `/universe/structures/{id}`.** A contract at an NPC station gets a real classification for free — the whole snapshot is already loaded, zero ESI calls. A contract at a player structure stays unresolved (`space: null`), which the Space filter treats like any other unresolved row: excluded once the player narrows to specific kinds, shown when every kind is checked (the filter's default, a no-op). This mirrors ADR 0013's own reasoning for leaving contract rows' exact location unresolved on the first cut: a public contract's structure has no single character whose ACL it should be checked against, so resolving it would mean firing an ESI request per distinct structure id that usually 403s. Owned blueprints don't have this problem — `loadBlueprintLocation` resolves them through the viewing character's own ACL, same as `contractLocationName.ts` already does for personal contracts — so only the _contract_ side of Space classification takes this SDE-only shortcut.
- **An owned or contract row whose region/space could not be resolved is excluded once a Region or Space filter is actively narrowing, rather than shown.** Symmetric with the pre-existing behavior of the Region filter (an owned row with no location at all was always excluded when a region was picked, before this ticket added resolution). An unresolved row cannot honestly be said to match a specific region or space the player chose, so the safe default is to hide it rather than guess.
