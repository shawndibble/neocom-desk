# Scope decisions — Chevron column as a row-click affordance (issue #823)

_Recorded 2026-09-11 · issue #823._

- **A trailing decorative chevron column (`Icon.Descend`, `aria-hidden`) marks a fully-row-clickable `DataTable` row when the row's own text no longer carries a link.** The Wallet loyalty table used to style its `points` column as a link and add a second, redundant `IconButton` column to open the same destination — two entry points to one action. The fix makes the whole row clickable via `DataTable`'s `onRowClick` and removes both the link styling and the icon-button column, but a plain-text row with only `cursor-pointer` + hover for a cue reads as inert data at a glance. The chevron is the explicit "this row goes somewhere" affordance. Other `onRowClick` tables in the app (Characters, LoyaltyStore, TaxTab, BpcSourcingPanel, ProductionLogPanel, ProductionRunsPanel, VariationsTable) predate this decision and rely on `cursor-pointer` + row hover alone — this does not retroactively require adding a chevron to them, but new row-click tables where no cell already reads as an obvious link/control should prefer this pattern over a redundant per-cell link or action button.
