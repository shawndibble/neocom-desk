# Scope decisions — Communities: share blueprints by location

_Recorded 2026-10-12. Extends `20261012-152415-communities-share-all-blueprints-is-a-standing-switch.md`._

- **Sharing stays keyed by blueprint type.** Sharing a type shares every copy of it, wherever it is. There is no per-copy choice.
- **A shared location is a standing rule.** With "Share all my blueprints" off, sharing a station or structure shares every blueprint whose place is there, including ones that arrive later. A blueprint moved away is no longer shared through that rule. A copy is shared when its type is picked or its place is a shared location. Under share-all the locations do nothing (everything not stopped is shared), so turning share-all on clears them and the dialog shows no Locations section.
- **A location is the resolved station or structure, never the raw `location_id`.** That id can be a container. The rule matches the place `resolveBlueprintPlacement` gives, the same one the published library names; the tab and the publish both go through `loadPlacedBlueprints`, so they cannot disagree. Without cached assets nothing is published, so the dialog says locations need assets instead of offering a Share that would do nothing. A copy whose place cannot be traced never matches a location rule. A shared location whose name cannot be read is still a rule, but its copies are counted as skipped like any other unplaceable blueprint.
- **Location ids are never published.** The rule is applied on the device when the library is built. The Community gets the same `SharedBlueprint` items as before, so `firestore.rules` is unchanged. The rule lives in a `communityShare:{characterId}:{communityId}:locations` settings row, deleted when the last rule stops, so the logout question and Character-removal cleanup cover it. Settings sync is an allowlist, so the row never leaves the device.
- **A blueprint shared only through a location shows "via <station>" and has no Stop sharing button.** With several, it names the first and "+N more", every name in a tooltip, so the Member knows which location to stop. Stopping the location is the way out, so a per-type button would do nothing visible. A type that is both picked and covered by a location shows both its Stop sharing button and the "via" label, so stopping it explains why the row stays.
- **Turning share-all off still shares nothing.** It clears the location rules too, and the confirm dialog says so.
- **The list on the page is still the choice.** Shared locations are listed above the shared blueprints, each with Stop sharing. "Add blueprints" opens a dialog for adding: Locations (one row per station or structure the Character holds blueprints at, with system, count and Share or Stop sharing) and Blueprints (a search over every type not picked by type, including stopped ones under share-all and ones a location already partly covers, so their copies elsewhere have a way in). This replaces the old inline "Add to what you share" results under the search, which appeared only after typing and only with the switch off. The tab's search now only filters what is shared. No tri-state tree mixing locations and types.
