# Scope decisions — Campaign turn-ins: rewards from campaign objectives, one popover, dismissible permission mark

_Recorded 2026-11-23. Grilling session with Shawn; mockups in `docs/design/mockups/campaign-turn-ins/`._

- **Turn-in Rewards come from CCP's data, not a hand table.** The SDE's `militaryCampaignObjectives` (contribution method `ItemTraded`: traded item, trader, ISK per item, LP per block, issuer) is baked; ESI `/military-campaigns/{id}/objectives` gives each objective's live state and progress. An objective's reward shows only while it is Active, so nothing is curated when it fills or its campaign ends. The Item Trader is not an LP Store (no store lists these items).
- **Faction tokens stay out of every figure.** Trader recipes (items per token) are in neither ESI nor the SDE and CCP changed them mid-event (17 Nov 2026). Shown as "+ faction tokens" only. The reward alone already beats selling in the cases seen, so leaving tokens out never flips a verdict the wrong way.
- **No "turn in multiples of N" advice.** LP is paid per full block (e.g. 100 items); whether a remainder carries over is unverified, so the copy says "LP paid per full 100 items" and nothing more. No predicted close date either: progress jumps unevenly, so only "% filled" is shown.
- **A Turn-in Reward is never a price.** It does not count toward Net Worth, Appraisal Buy/Sell totals or contract values: it is conditional on Participate and on the objective staying open. It is a "how to get rid of it" choice beside Sell now / List / Refine.
- **New Permission "Military Campaigns", on in the Base Grant.** Reads whether a Character pressed Participate. Characters logged in before it ships lack it; they are never pushed to re-login.
- **Missing Permission = an amber mark with a popover, never a banner.** A figure or control that needs a Permission the row's Character lacks keeps showing (a control stays visible, `aria-disabled`) with an amber `Icon.Warn` mark after it. The popover: "<Character>: grant <Permission>", Grant in EVE for that Character, Don't ask again, and the Grant missing Permissions link. No reason text in the layout. One reusable primitive (`PermissionCellMark`), a new DESIGN.md §6c row in its PR. Menu items keep `DisabledMenuItem` / `GrantMissingMenuItem` (no popover inside a menu).
- **Don't ask again is per Permission, account-wide, synced, permanent.** One dismissal silences that Permission's mark for every Character, present and future, on every device (Editable Data), and across future campaigns. The way back is Settings › Permissions only. Dismissed: no mark; the figure's tooltip says "Pays only if you've pressed Participate", a disabled control's tooltip names the Permission. Rules out Standings' per-Character localStorage dismissal for this — 20 Characters must not mean 20 clicks.
- **Whose Participate counts:** the row's owning Character on Assets and Open Orders; the active Character on Appraisal and the Market item view; no Character → the plain "Pays only if you've pressed Participate" line.
- **One detail popover, one breakdown modal.** A single item's turn-in detail (reward ISK + LP, Item Trader and system, % filled, Participate state, Set destination; a missing **Autopilot waypoints** Permission — part of Write to EVE — gets the mark after it) is the `TurnInDetail` popover on every surface; each surface only supplies its trigger. A pile (Appraisal's Turn in total) opens the `TurnInBreakdown` modal, grouped by Item Trader with a Set destination and copy list per War HQ. Content size decides popover vs modal, not item count; Refine stays a modal because even one item's detail is a minerals table.
- **Surfaces.** Appraisal: per-row turn-in figure and a header total like Refine's; the Turn in copy list splits per Item Trader. Market item view: "| Turn in ~60k" after the spread. Open Orders: a sell order gets the lowest-precedence Order Problem `turnInPays` (Watch bucket, never in the "need you" count; a real problem still wins), Do this "Turn in instead"; a buy order's What's wrong is unchanged and a dim mark after its price opens the popover. Assets: only the Hauling-style mark after the value (Haul to War HQ lines were mocked and dropped in review as out of place; the popover's Set destination covers the trip). Hauling: the item stays listed with a compact trigger, never dropped (a haul to the War HQ is valid).
- **Overview widget "Military Campaigns".** Gallery only, not in the default layout. Lists Active objectives a widget Character Participates in (any objective type) plus turn-in objectives whose items they hold; a per-widget Faction setting (All default). Views: Table (default, matching the board's Number / Chart / Table names) and Number ("~72M waiting to turn in"). Uses the board's needs-permission Widget State and ignores Don't ask again (adding the widget is asking); a partly granted scope shows the granted Characters plus one header mark. No campaign: empty state, never removed. A turn-in row opens the `TurnInDetail` popover, not the board's widget-row modal (one detail popover everywhere); §6c notes the exception.
- **Words.** "Turn in" means only handing items to an Item Trader; the LP Store's are "required items" (its "Turn-ins" strings are renamed in their own ticket, landed before the Appraisal group). Player-facing "Participate", as the client says.
- **Out of scope here:** migrating existing waypoint controls and inline "Grant missing Permissions" text to the mark (own ticket); NPC-station fixed buy orders (Overseer's Personal Effects, Sleeper loot) priced away from the hub (own ticket); Corporation Projects / Freelance delivery jobs as turn-in sources (later); alerts when an objective nears full (idea only).
