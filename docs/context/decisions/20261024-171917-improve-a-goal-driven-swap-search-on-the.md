# Scope decisions — Improve: a goal-driven swap search on the Fittings page

_Recorded 2026-10-24. Design only: no code yet. Interactive mock and ticket split: the Fit Improver concept artifact (private link held by Shawn)._

- **Improve is a search the pilot points at an Improve Goal, never one "make it better" button.** Cheaper, tankier, faster and more damage pull against each other, so "better" has no single answer. Each Improve Goal is a score plus Guardrails, and the drawer shows only the goals the fit can score, with a disabled chip and a reason for the rest ("No miners on this fit"). It reuses the loop Make it fit already has (`findFitSwaps`: candidates, whole-fit recalculation, tolerance, rank by ISK) behind the same injected `stats` function, so the new `engine/fittings/improve.ts` stays pure and is written test-first.
- **Every number is a whole-fit recalculation by the dogma engine (ADR 0016), under the page's own conditions.** That means the selected Damage Profile, Target Profile, Overheat all, projected effects and the pilot's implant basis, so a suggestion's figures match what the pilot sees after applying it. The search passes `overheated: false` unless Overheat all is on, because the default roughly doubles each call. A Node timing with the real engine measured about 1.5 ms per recalculation and 300 swaps in about 0.5 s. The browser worker is unmeasured (guessed 2–5× slower on weak hardware), so timing it is an acceptance criterion of the foundation ticket.
- **Entry is an "Improve…" item in the header's ⋮ More actions menu**, not a button: the header already carries Fittings, Export and Update. It opens a `SlideOver` beside the fit on desktop (the Ring stays steerable, as with the module browser) and a bottom sheet below `md`. It is hidden in views that cannot be edited. Contextual entry points are a later ticket if the menu item proves hard to find.
- **An over-budget fit gets "Fix this first", not suggestions.** Make it fit already decided "a fit that doesn't fit has nothing to improve yet" (`20261019-144736`); Improve hands over to it.
- **Results are sectioned Train, Implants, No downside, Trade-offs, never ranked against each other**, as Make it fit does (`20261019-144736`): time, ISK and stat loss have no honest common scale. Train and Implants reuse What to train and the Implant Finder and cost the fit nothing. No downside is a change that worsens no stat; Trade-offs gain on the goal and name what they give up. "Upgrades" is not used as a section name, because What to train already calls a Tech I → Tech II step a module upgrade.
- **Guardrails are shown as one plain line and are not editable in v1.** Cheaper keeps damage, tank and speed each within 5%, the tolerance Make it fit's ranking already uses (`20261007-230641`); the combat and logistics goals keep capacitor stability. Editable guardrails and per-module locks wait until pilots ask for them.
- **Reach has three levels: Upgrade (default), Rebalance, Rework.** Upgrade turns a fitted module into a variation of itself. Rebalance also allows a different module doing the same job. Rework allows any module for that rack, and never removes the last module doing a job the goal does not score (propulsion, scram, web, EWAR, cap, remote repair, miners), because no damage or EHP score notices that loss. An empty slot is always free. Rework and large empty-slot searches prune to module groups that can move the goal's stat, and that hand-written table is the main place a good idea can be missed.
- **Defense is a choice that is always shown: Keep as is, Shield or Armor.** A hull's bonuses are already inside every engine figure, so for tank goals the drawer runs the search under each side and shows both results, instead of reading bonuses or guessing a fleet's need. Only tank modules and tank rigs are freed; propulsion, tackle, EWAR, cap, weapons and utility never are. Armor sits in low slots and shield in mid slots, so a hull without free slots on the other side shows a poor result, and that is the honest answer. The choice is not stored on the Fitting: a shield-fleet and an armor-fleet version are two Fittings.
- **Two modes, chosen by the pilot: Planning to buy (default) and Refitting a ship I own.** Planning treats the fit as a shopping list: ISK is the total fit price against a total budget. Refitting is the new part minus what the removed part sells for, against an extra-spend cap, and a rig change costs the full new rig and is flagged because rigs are destroyed when removed. Rigs sit in their own collapsed group, unticked. Both modes use one search; planning from scratch is a hull with empty slots. Prices are sell prices at the hub the Price section uses, and an unpriced item sorts last.
- **Empty slots are filled in v1, with pair moves.** A downgrade plus an add is tried when no single add fits the CPU and powergrid (the Make it fit pair search, capped). Officer and Deadspace modules are excluded unless the pilot ticks them. A module that needs a skill the pilot lacks never appears among the swaps; it goes under Train.
- **Applying makes the ticked suggestions one unsaved edit to the open Fitting.** Back undoes it, as other fitting edits do (`20260924-183346`), and a toast offers Undo. Nothing saves until the pilot presses Update.
- **While it searches the drawer shows progress and Cancel; after 10 seconds a "Show best so far" button appears.** Results appear when the search ends. When nothing helps, the drawer says so, lists the closest rejected swaps with the guardrail each broke, and names the setting that would widen the search.
- **The last Improve Goal, Reach, mode and spend cap are remembered on this device**, like other Fittings preferences, and are not stored on the Fitting.
- **Goals by role.** Combat: Best overall, More damage, Tankier, Faster, Longer reach, Cheaper. Best overall scores like What to train (damage and EHP weight 1; speed, align, lock range and reach 0.5; capacitor 0.25, a flipped cap state counting whole). More damage is sustained applied DPS against the Target Profile, with fighter DPS on fighter fits. Mining: Mine more, scored as m³/s for the crystal family the pilot picks, because mining yield carries no ore input and the ore enters only through the crystal. Hauling and movement: Carry more (the hold the pilot picks), Align faster, Align and warp faster. Logistics: Repair more, Transfer more, with cap-stability a hard guardrail. Tackle: Hold tighter (scram and disruptor points, web slowdown, range). EWAR: Stronger EWAR, scored as module strength and range, labelled as not the effect on a target, which the engine does not compute. Command: Stronger bursts, compression range, core fuel, reusing What to train's burst metrics.
- **Left out because the engine cannot score them.** Jump range and fuel goals (no module or rig is known to move them; What to train already scores jump range), probe-strength and cloak goals, and bubbles (not modelled; an engine ticket if wanted). Fighter range is skipped by the engine too.
- **Ticket split.** v1 is three tickets: Foundation (the pure search, the ⋮ entry and panel, the combat goals with fitted swaps, Apply with Undo, progress and the empty view, remembered settings), Free slots (fill empties, Reach, Defense, pair moves, the two modes, the Rigs group, spend cap, Officer and Deadspace), and Train, Implants and Fix first. After v1: Mining, Haul and move, Logistics, Tackle and EWAR, Command and fleet. Not scheduled: bubbles, any-slot refit in planning mode, a buy list that subtracts owned items, editable guardrails and locks.
