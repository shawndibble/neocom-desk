# Scope decisions — Mail organize: mark unread, delete and Custom Label tags (issue #5879)

_Recorded 2026-11-02 · issue #5879._

- **Mark as unread, mark read in bulk and Delete ship, behind the existing Mail organize Permission and nothing else new.** `PUT /characters/{id}/mail/{mail_id}/` (read flag only) and `DELETE` of the same route both use `esi-mail.organize_mail.v1`, the Write to EVE Permission `mailOrganize` (off by default, asked for on first use). Without it the row ⋮ menu, the reader's ⋮ menu and Select are not drawn and the compact grant note asks for it. This reverses the 2026-09-05 removal of the manual mark-unread control (a UI simplification, not an ESI limit) and the "delete stays out of scope" line of `20260910-103051`, which the Write to EVE section (`20261025-113942`) later made affordable.
- **ESI stays the source of truth; nothing new is stored or synced.** A successful write patches the cached header (kept at its own age) and, for a delete, drops the cached body and any Reply/Forward draft for that mail. Session-only sets of read, unread and deleted row keys make the list move at once. The folder chips' unread counts move at once by what this session changed (`unreadDeltaByTab`, attributed to the mail's own folder, so a mail carrying several labels is approximate), and the cached label counts are patched with the header so a reload agrees. Writes to the cached header list and label counts are queued per Character, so a bulk action's three parallel writes cannot drop each other's patch.
- **Delete is the one irreversible write, so it always asks first, in words:** "It is deleted in EVE too and can't be undone." One confirm covers a whole selection and states the count. A failed delete keeps its mail and the dialog open; a selection that partly fails keeps only the failures. The hostile review said to kill it (irreversible, the game client already deletes, no visible demand); the owner approved it on 2026-11-02, so the confirm and the Permission are the answer.
- **Select mode is a header toggle, not a control on every row.** "Select" swaps the page into ticking mode: a click on a row ticks it, a bar shows "N selected" with Mark read, Mark unread and Delete, and the header button becomes Done. A ticked mail that a later filter or search hides is not acted on: the bar counts and acts on what the list shows. Mark read and Mark unread write only the mail that would change. Writes run three at a time.
- **Custom Label names show as read-only tags on rows and in the reader.** Names come from the already-fetched label list, in the mail's own label order; a System Label is never a tag, and a label id with no name shows nothing. Rules out, for now: a "Label as…" action (ESI replaces the whole label array, so a stale set could clobber labels changed in game), filter chips (still removed by `20260905-140358`) and creating or deleting labels. Tags without a filter are a deliberate half step.
