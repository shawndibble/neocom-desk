# Scope decisions — Corp Tax Book: a Miner declares and disputes to the corporation (issue #6206)

_Recorded 2026-11-15 · issue #6206._

- **"I paid this another way" reaches the corporation as a declaration.** This supersedes `20261021-084415-corp-tax-book-a-miners-i-paid-it` (device-only note). A Miner declares on one of their own unsettled Late notices, with an optional amount and note, through the router action `declareCorpTaxBookPaymentCallable` (no officer role). The Tax tab offers it in three places: the detail of a billed row, a row marked paid that the book still bills, and the Overdue attention item. The overlap notice offers it too once a Late notice lists the day. A day no notice lists keeps the device-only note, because there is nothing to declare on. The declaration is stored with `kind: 'another-way'` and `via: 'player'`. Officers answer it in the existing Needs you declaration card.
- **The proof a caller owns the notice is the one the rules use for the member read.** The caller's sign-in must be in the notice's `uids`. Someone else's notice gets the same `not-found` as a missing one. The action also refuses a notice already settled (`settled`), a notice that already has an unanswered declaration (`already-declared`), and a book still in its member setup window (`no-book`). It does not re-run the account on the server, so a notice settled only through donations is not refused there. The client offers the action only on unsettled notices.
- **Members read their own declarations and disputes.** Every declaration now carries the notice's `uids` and `minerId`, including officer-recorded ones. The rules let `isOnOwnLine()` read `declarations` and `disputes`. A declaration written before this change has no `uids` and stays officer-only. The Tax tab shows "Declared — waiting for {corp}" until an officer answers, and then the answer, with the reason for a rejection. A waiting declaration now pauses the member's own Overdue attention item, the same way it pauses the officers' view.
- **A rejection resumes the original Overdue clock.** The time the declaration waited still counts as a pause, the same as for a confirmed one. The old "fresh 14 days from the rejection" is gone from both `overdue.ts` and its server mirror `overdueAtFor`. The pause cap stays at 14 days in total per notice, so declaring again cannot extend it.
- **Confirm pre-fills the declared amount** when the Miner gave one, and otherwise what is owed.
- **A dispute is one record per Miner and day.** A Miner sends a Conflict day from the Conflict notice with "Tell {corp} it went to {payee}" (`disputeCorpTaxBookConflictCallable`). The record is `disputes/{minerId_date}` and holds the ore lines with their record keys and the Payee name the Miner sent. Officers never see the Miner's Payee list, only that name. Each line's character must be one of the caller's own Miner's confirmed characters, the same Miner lookup `claimPayment` uses. Sending a second Conflict for the same day adds its lines to the record. An `overListed` Conflict is never billed, so the notice does not offer a dispute for it.
- **Officers answer a dispute in Needs you, one card per dispute.** "Dismiss the day" is the existing `dismissRecords` over the dispute's record keys, with the Director limit applied to their total. "Reject" is a new edit action, `rejectDispute`, that requires a reason. The card leaves Needs you once it is rejected, or once an active dismissal covers every one of its lines. A rejected day cannot be disputed again, and the Miner reads the officer's reason. The disputes card is built from the `disputes` collection, which is read with the ledger, so the server read models do not change.
- **A collection the book's version stamps never name is not read.** Every server write stamps its collection. On the officer side and the member side alike, `disputes` and the member's `declarations` are read only once a write has stamped them.
