# Scope decisions — Community shared blueprint row actions and jumps

_Recorded 2026-10-13. Extends `20261012-224358-communities-page-leads-with-shared-content.md`._

The Community Library's "Shared in the Community" table was read-only: no row click, no menu. A pilot who found a copy had to retype its name into another page to see it, plan with it, look for other copies or fly there.

- **Each row gets a ⋮ (and the same right-click / touch-and-hold menu): Show info, Build Plan, Open in BPC Sourcing, View route.** `RowActionsMenu` + `DataTable`'s `rowMoreActions`, with `linksKeepBrowserMenu` since the name and the jumps count are real links.
  - _Show info_ opens the blueprint's Item Detail (`openItemInfo`, the global `?info=type-<id>` modal). Not `ShowInfoMenuItem`: that needs an `ItemActionsProvider`, which the Communities page has none of.
  - _Build Plan_ opens a new plan for what the blueprint builds, seeded with this copy's ME / TE / runs (no seed for a BPO, as BPC Sourcing does). It is `BuildPlanContextMenu`'s own entry (`BuildPlanMenuItem`) with its index resolved the same way (`usePlannableIndexOnOpen`, on first open, kept for the row), so its "checking…" and "no blueprint options" states stay one implementation.
  - _Open in BPC Sourcing_ is `bpcSourcingHref(typeId)`: BPC Sourcing pinned to this blueprint, every source on, so the pilot sees this Community's copies beside contracts and the market. The page-level "Browse in BPC Sourcing" link above the table stays the Community-and-owned narrowing.
  - _View route_ opens Route Safety to the blueprint's system (`routeToHref`), from the Current System. While the system list is still loading it reads "View route (checking…)", disabled; when the system id cannot be found it is disabled with that reason.
  - Wording follows the app's existing labels rather than the request's ("Plan build", "Show route"): the same action reads "Build Plan" and "View route" on every other menu, one action, one wording.
- **§6c restraint is overridden on purpose, at the pilot's request.** Show info repeats the name link and View route repeats the jumps link; §6c's Restraint ("Duplicates": keep the visible one, drop the menu item; Show info does not count toward a ⋮) would drop both. The owner asked for the menu entries and the direct clicks together, so both stay. The ⋮ still meets §6c's floor on its own: Build Plan and BPC Sourcing are two real actions reachable nowhere else on the row.
- **The blueprint name opens Show info** (`ItemInfoLink`, a real `<a href>`), §6c Entities' default for an item name. The row has no primary action, so the name may be a link.
- **A Jumps column, after Location: jumps from the active Character's Current System to the blueprint's system.** The same machinery and rendering as BPC Sourcing's Jumps column: `useCurrentSystem` + `useJumpRangeFilter(…, 'any')` over the pilot's jump basis (Travel Settings and Route Safety's route preference, holes and bridges), drawn by `renderJumpsCell`, so a settled count is a real link to Route Safety (`JumpsLink`) and an unknown is the usual dim "—" with a tooltip saying why (no Current System, the stargate map unreadable, or no route / system not found). Sortable; a row without a count sinks to the bottom in both directions. On a phone card it is a labelled field like the others.
- **The system id is found by name, on the reading device.** A Shared Blueprint carries its station or structure name and its system's _name_ only (ADR 0018); nothing new is published. The Library reads the SDE system list (`loadSolarSystemsById`) apart from its own load and finds each row's id by lowercase name (`systemIdsByName`). Names come from the same SDE at publish time (`libraryPush`), so they match; an unreadable list leaves only the Jumps cells at "—".
- **The Location cell drops the system line when the place's name already starts with it.** An NPC station's name always starts with its system ("Jita IV - Moon 4 - …"), and so does an Upwell structure's as ESI names it ("Efa - Home Fortizar"); `libraryPush` publishes those names unchanged. The rule is the data's, not the kind's (`placeNamesSystem`: starts with the system as a whole word, followed by the end, a space or " -", case-insensitive), so a name that does not start with its system still shows it, and neither "Jitanomics …" for Jita nor a name that mentions another system elsewhere counts. Search by system and the Location sort (system, then place) are unchanged.
