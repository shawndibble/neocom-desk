# Scope decisions — Quickbar price alerts: re-arm key, hub price field, and scope-less events (issue #680)

_Recorded 2026-09-09 · issue #680._

- **Re-fire identity is `(typeId, targetPrice, direction)`, not a separate "already fired" flag.** `diffPriceAlertTriggered` (`src/engine/notificationDiffs.ts`) mirrors `diffStructureFuelLow`'s edge-trigger shape: it fires once per crossing, judged against the previous poll's own entry for the same tuple. This makes the choice between "one-shot" and "re-arming" moot rather than picking one: once fired, the same target never fires again (satisfies "fires the first time"), but editing the target price or direction produces a fresh, unobserved tuple and so re-arms itself for free (satisfies "editing the target price stops further alerts for the old target"). No extra state on `QuickbarItem` beyond the target itself — the poller's own snapshot baseline is where "already observed" lives, same as every other domain.
- **The "hub price" a target compares against is `HubAggregate.sellMin` alone**, not a buy/sell pair. The issue's acceptance criteria speak of one target price and one hub price per item, with no mention of tracking buy and sell separately (unlike `appraisalData.ts`, which does track both for a different purpose — reprocessing/material cost). `sellMin` (lowest sell order) is the conventional "price" a price-check tool quotes. A future ticket can split this into buy/sell-specific targets if that turns out to matter; nothing here forecloses it.
- **`NotificationEventDef.scope` (`src/features/notifications/events.ts`) becomes optional**, and `foregroundPoller.ts`'s `enabledEventsFor` treats an absent scope as always-satisfied, rather than reusing an unrelated existing scope as a gate. `priceAlertTriggered` needs no ESI OAuth scope at all — pricing comes from the public Fuzzwork aggregate path and the Quickbar item list is local Dexie data — so gating it behind a borrowed scope (e.g. the skill queue's) would incorrectly hide the event for a character who has never granted that specific scope, even though nothing about price alerts depends on it. This is the first Notification Event with no ESI backing; the type change is additive and every existing event still carries a real scope.
