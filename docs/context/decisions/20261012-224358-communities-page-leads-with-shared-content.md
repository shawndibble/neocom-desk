# Scope decisions — Communities page leads with shared content

_Recorded 2026-10-12. Extends `20261012-214150-communities-share-blueprints-by-location.md`._

The Community page read as settings: it opened on the Member's own share controls, other Members' blueprints sat behind an "Open the Community Library" button that replaced the tabs, and Members and Invites were admin chores in the same tab row. Reshaped after Snowflake's "Shared with you / Shared by your account", Langdock's All / Mine library filter, ClickUp's team header and Braintrust's Spaces list.

- **Tabs are Blueprints | Fittings | Skill plans | Members.** Blueprints is the default. Invites is no longer a tab.
- **Each content tab has an Everyone | Mine `SegmentedControl`, Everyone first.** Everyone is what the Community's Members share, this Character's own included; Mine is the share management that used to be the whole tab (switch, shared list, Stop sharing, Add). Only the picked view mounts, so its loads and publishes run only when shown.
- **The pick is remembered per tab, on this device, for every Community** (`communityContentScope`, a view preference cleared by "Reset saved view preferences"). A `?view=mine|everyone` link overrides it on the tab it opens until the pilot picks again; that is also how the page stories reach Mine. Until the stored pick has loaded, the content area shows a spinner, so a pilot whose pick is Mine never loads Everyone first.
- **Blueprints › Everyone is the Community Library, folded in, and opens on each shared blueprint.** The separate full-screen Library mode and its Back button are gone. Its first chip, "Shared in the Community" (the default), is a table of every **Shared Blueprint**: the Member who shares it (Stale badge, row greyed), station or structure with its system, ME / TE, and runs (BPO, or the runs a BPC has left), searchable by blueprint, Member, station or system, sortable by column, and stacked into cards on a phone. It reads the Members' published library chunks, which already carry those fields; nothing new is fetched or published. The other chips keep the market-group matrix (missing from the Community, owned by me, missing from me). The link to BPC Sourcing moved from Mine to the top of the Library, for sourcing a copy.
- **Fittings › Everyone lists every shared Fitting in this Community** with hull, sharer ("you" for this Character's own) and an In-game mark. The row is a real link to the editor (`fittingEditLocation`), where Save keeps a copy; it ends in the row caret and carries no other control (§6c Restraint). The Fittings library's Community rows (`useCommunityFittings`) are unchanged.
- **Skill plans › Everyone lists this Community's shared plans with Copy to my plans**, the list body shared with Skills › Plans' "From a Community plan" dialog (`SharedPlanList`). Copy adds an ordinary plan and opens it, as the dialog does (opening it is the confirmation; a failed save says so and stays); its remap count starts at 0 (the planner's "available remaps" is not known on this page, and the pilot sets it in the plan). The old "Browse skill plans shared in this Community" link to Skills is gone; the dialog and its `?browse=community` stay for Skills.
- **Mine always shows an Add button, never a search-to-reveal list.** "Add Fittings" and "Add Skill plans" open a dialog in `AddBlueprintsDialog`'s shape (`AddSharedItemsDialog`): every item not shared now, searchable, Share on each row, focus moving to the next row's Share. The tab's own search only filters what is shared. A failed Share's notice shows inside the dialog, since the page behind is inert. Add Skill plans shows even when the pilot has no plans; the tab and the dialog then link to Skills › Plans to make one.
- **Under "Share all my Fittings" a stopped Fitting can be added back.** Adding it lifts its exclusion (`allExcluded`), so its later saves follow again. Before, it could never be re-shared without turning the switch off. The exclusion is lifted on this device first and put back if the share does not go through, so a failure never leaves a shared Fitting that later saves skip, nor an unexcluded one that is not shared.
- **The admin's chores are in the header's Manage menu** (a `Button` with a caret, as the Fittings header's menu): Invites, Transfer admin…, then Delete Community… as a danger item. Every item opens its window after the menu closes (`useOpenAfterMenu`). Invites is one window holding the join requests, "Approve new Members", the invite link (copy, regenerate, revoke) and mail invites; nothing about invites is duplicated in the menu itself. While requests wait, the count rides on both the Manage button ("Manage · 2 waiting") and the Invites item, so a request is never out of sight; the Members tab no longer carries it. An old `?tab=invites` link opens Manage › Invites once and is dropped from the URL (replace), so a reload or a Character switch does not reopen it.
- **Transfer admin is reachable twice, on purpose.** The Members row ⋮ keeps "Make … admin" next to Remove: dropping it would leave a one-item ⋮, which §6c does not allow. Manage › Transfer admin… lists the other Members with Make admin, because the approved design puts every admin chore in Manage and a pilot looking for "how do I hand this over" looks there. Both lead to the same confirm. When the admin is the only Member, the window says there is nobody to hand it to; when the roster did not load, it offers Retry.
- **Delete leaves the Members tab.** It is in Manage only. A Member who is not the admin still leaves from the foot of the Members tab, set apart from the roster.
- **The Communities list shows each Community's name and Member count, and an Admin badge on the ones this Character admins.** No "Member" badge: every row is a Community the Character is a Member of, so it would say nothing (§6c restraint). It does not show counts of shared blueprints, Fittings or Skill plans: `CommunitySummary` does not carry them, and reading them would cost extra Firestore reads per Community on every list load.
