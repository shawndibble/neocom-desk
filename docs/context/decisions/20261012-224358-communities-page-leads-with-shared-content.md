# Scope decisions — Communities page leads with shared content

_Recorded 2026-10-12. Extends `20261012-214150-communities-share-blueprints-by-location.md`._

The Community page read as settings: it opened on the Member's own share controls, other Members' blueprints sat behind an "Open the Community Library" button that replaced the tabs, and Members and Invites were admin chores in the same tab row. Reshaped after Snowflake's "Shared with you / Shared by your account", Langdock's All / Mine library filter, ClickUp's team header and Braintrust's Spaces list.

- **Tabs are Blueprints | Fittings | Skill plans | Members.** Blueprints is the default. Invites is no longer a tab.
- **Each content tab has an Everyone | Mine `SegmentedControl`, Everyone first.** Everyone is what the Community's Members share, this Character's own included; Mine is the share management that used to be the whole tab (switch, shared list, Stop sharing, Add). Only the picked view mounts, so its loads and publishes run only when shown.
- **The pick is remembered per tab, on this device, for every Community** (`communityContentScope`, a view preference cleared by "Reset saved view preferences"). A `?view=mine|everyone` link overrides it on the tab it opens until the pilot picks again; that is also how the page stories reach Mine. Until the stored pick has loaded, the content area shows a spinner, so a pilot whose pick is Mine never loads Everyone first.
- **Blueprints › Everyone is the Community Library, folded in.** The separate full-screen Library mode and its Back button are gone. The link to BPC Sourcing (owner, place, ME/TE/runs per shared copy) moved from Mine to the top of the Library, since it browses other Members' blueprints.
- **Fittings › Everyone lists every shared Fitting in this Community** with hull, sharer ("you" for this Character's own) and an In-game mark. The row is a real link to the editor (`fittingEditLocation`), where Save keeps a copy; it ends in the row caret and carries no other control (§6c Restraint). The Fittings library's Community rows (`useCommunityFittings`) are unchanged.
- **Skill plans › Everyone lists this Community's shared plans with Copy to my plans**, the list body shared with Skills › Plans' "From a Community plan" dialog (`SharedPlanList`). Copy adds an ordinary plan and opens it, as the dialog does; its remap count starts at 0 (the planner's "available remaps" is not known on this page, and the pilot sets it in the plan). The old "Browse skill plans shared in this Community" link to Skills is gone; the dialog and its `?browse=community` stay for Skills.
- **Mine always shows an Add button, never a search-to-reveal list.** "Add Fittings" and "Add Skill plans" open a dialog in `AddBlueprintsDialog`'s shape (`AddSharedItemsDialog`): every item not shared now, searchable, Share on each row, focus moving to the next row's Share. The tab's own search only filters what is shared. A failed Share's notice shows inside the dialog, since the page behind is inert.
- **Under "Share all my Fittings" a stopped Fitting can be added back.** Adding it lifts its exclusion (`allExcluded`), so its later saves follow again. Before, it could never be re-shared without turning the switch off.
- **The admin's chores are in the header's Manage menu** (a `Button` with a caret, as the Fittings header's menu): Invites, Transfer admin…, then Delete Community… as a danger item. Every item opens its window after the menu closes (`useOpenAfterMenu`). Invites is one window holding the join requests, "Approve new Members", the invite link (copy, regenerate, revoke) and mail invites; nothing about invites is duplicated in the menu itself. While requests wait, the count rides on both the Manage button ("Manage · 2 waiting") and the Invites item, so a request is never out of sight; the Members tab no longer carries it. An old `?tab=invites` link opens Manage › Invites.
- **Transfer admin is reachable twice, on purpose.** The Members row ⋮ keeps "Make … admin" next to Remove: dropping it would leave a one-item ⋮, which §6c does not allow. Manage › Transfer admin… lists the other Members with Make admin, because the approved design puts every admin chore in Manage and a pilot looking for "how do I hand this over" looks there. Both lead to the same confirm.
- **Delete leaves the Members tab.** It is in Manage only. A Member who is not the admin still leaves from the foot of the Members tab, set apart from the roster.
- **The Communities list shows each Community's name, Member count and the Character's role** (Admin or Member). It does not show counts of shared blueprints, Fittings or Skill plans: `CommunitySummary` does not carry them, and reading them would cost extra Firestore reads per Community on every list load.
