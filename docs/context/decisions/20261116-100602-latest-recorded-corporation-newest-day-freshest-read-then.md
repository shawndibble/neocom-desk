# Scope decisions — Latest recorded corporation: newest day, freshest read, then refinery and corporation id

_Recorded 2026-11-16._

- **A character's latest recorded corporation is the one on the ledger row ranked first by: the newest day, then the freshest ESI read (`cachedAt`), then the higher refinery id, then the higher corporation id.** It decides member / left / guest standing in the officer's book view, a Miner's page, Grouping choices, and the server's Close account guard. Before this the three readers each had their own tie-break (input order within a day, the largest doc id, the first doc id of the newest day), so a character who changed corporation mid-day after mining as a member and as a guest could read as a guest in the officer view while the server refused Close account as "not a guest". The freshest read is what the player last saw; the refinery and corporation ids only order rows one ESI read reported together, which the data cannot order, so they are arbitrary but make every reader agree whatever order its rows came in. The rule lives in `src/engine/corpTaxBook/bookDocs.ts` (`latestRecordedCorp`, via `recordedLater` in `observed.ts`, which Observed Mining Entry grouping also uses) and is mirrored by hand in `functions/src/corpTaxBookEngine.ts` with a parity case in `functionsMirror.test.ts`. Server rows carry `cachedAt` and `structureId`, so both sides apply the full rule.
