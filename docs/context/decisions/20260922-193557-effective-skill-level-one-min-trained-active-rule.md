# Scope decisions — Effective skill level: one min(trained, active) rule for PI, industry, job slots and clone cooldown (issue #1236)

_Recorded 2026-09-22 · issue #1236._

- **"Effective skill level" is `min(queue-corrected trained level, queue-corrected active level)`, computed by `src/engine/effectiveSkillLevel.ts` and wired per-skill by `src/features/skills/effectiveSkillLevels.ts` / `CorrectedSkills.effective`.** "The level this character can use right now" — trained alone overstates an alpha-capped or lapsed-omega clone, and raw `active_skill_level` alone understates a level the queue just finished but `/skills` hasn't caught up to (it is exactly as stale as `trained_skill_level`, so it gets the same `applyCompletedQueueEntries` correction before the min()). Used by: PI planet slots (`planetSlots.ts`), customs rate (`customsRate.ts`), command center budget (`colonyBudget.ts`), industry job time/fees (`useIndustryWorkspace.ts`), job slots (`jobSlotSkills.ts`), and the clone jump cooldown (`routes/Clones.tsx`).
- **`useAccountSkillLevels`/`toAccountSkillLevels` (the account-wide skill-gate marker on Build Plan/Opportunities rows) is deliberately excluded and still reads raw `active_skill_level`.** That choice predates this ticket (see `20260914-221255-skill-gate-marker-level-threshold-marker-tone-account.md`) and issue #1236 did not name it as one of the sites to unify — an eligibility marker asking "can this character install a job with the clone it has right now" is a different question from "what level should this calculation credit," and queue-correcting it would let a just-finished-but-not-yet-applied skill mark a build eligible before the character has actually logged in and picked it up. Revisit only via a fresh ticket, not silently.
- **Skill training/planning surfaces (the Skill Plan, Skill Queue) keep reading `trained` (queue-corrected trained, uncapped by active), not `effective`.** Per the issue's own carve-out: a plan is about what training to queue next, which is bounded by trained level and clone type (alpha cap), not by whatever the character's clone happens to be active on this session.
