# Scope decisions — Open Orders gets a compact phone list; the row sentence stays (issue #1429)

_Recorded 2026-09-24 · issue #1429._

- **Below `sm`, each expanded Open Orders problem group renders `OpenOrdersList` — a tap-to-open list — instead of `DataTable`.** The filter fold itself was already shipped (20260906-170442, "the whole filter set collapses behind the funnel at every width on this page"); this decision covers only the worklist below it, the same compaction `OrderHistoryList` and `TransactionsDayList` already ship for their own pages. Rules out the `DataTable stackLayout="dense"` fork: a dense card keeps one DOM and `rowContextMenu` for free, but has no whole-row tap target, so the Details button would have to stay — the new component instead makes the whole row the tap target.
- **The row keeps its plain-English sentence (`OrderRowSummaryText`), but the badge itself renders `interactive={false}`.** `OrderProblemBadge` always carries an `InfoTooltip` "?" trigger, which is itself a `<button>` — nested inside the row's own `<button>`, that's invalid HTML and would fight the row's own tap the same way a nested item link or station tooltip would (`OrderHistoryList`'s docblock gives the same reasoning for dropping its own tooltip). `OrderProblemBadge` gained an `interactive` prop (default `true`, unchanged everywhere else) so the list can drop just the trigger and keep the label pill.
- **Location and expiry move into the detail modal; "Off hub" stays as a plain text tag on the row, and the modal gains a "View in Market" link.** The modal already showed station/system/region detail; it did not show an item link or the off-hub flag before this ticket. Off-hub is cheap enough to read as a bare warning-tone tag inline (no room for a full explanation on a three-line row), while the item link — nested interactive content, same as the badge and the dropped tooltip — only fits in the modal, not the row.
- **On a phone, the `CharacterFilterControl` strip moves inside the funnel sheet (`FilterBar`'s `children(draft, setDraft)`); outside it, only the existing per-character chips remain.** The chips already existed (`activeFilterChips` emits one `character:<id>` chip per selection) — nothing new was needed for "the active chip stays outside," only hiding the always-visible strip and re-hosting the same `CharacterFilterControl` (unchanged: it's already a plain `value`/`onChange` pair, indifferent to whether `onChange` commits immediately or writes to a filter-sheet draft) inside the sheet, gated on `isPhone`. Desktop is untouched — the strip still renders outside the funnel there, same as before this ticket.
- **`HUB_STATION_IDS` moved to a shared `hubStation.ts` (`isOffHubStation`)** so the table's "where" column and the new list's off-hub tag can never disagree about which stations count as trade hubs — it was previously a module-private constant in `OpenOrdersPanel.tsx` alone.
