# Scope decisions — Fitting Add panel: hull/resource/skill filter icons replace Can Fly

_Recorded 2026-09-27._

- **The Add panel's hull-fit and resource-fit checks become toggleable icon filters, matching the in-game Fitting window's three icon toggles (hull, resource, skill), rather than the always-on hard filter they were.** Previously `browseFilter` unconditionally dropped any item that failed `check.fitsHull` or `check.fitsResources`; only the skill check ("Can fly") was a toggle. Now all three are independent `FilterChip`-adjacent icon toggles, each defaulting **on** (so the default result list is unchanged from before this change), and turning one off shows items that fail only that check.
- **The "Can Fly" text chip is removed and folded into the third (skill) icon toggle**, since it is the same check the in-game client draws as an icon rather than a labelled chip. `MissingSkillsChip`, `CompareCanFlyByCharacter` and other "can fly" surfaces outside the Add panel are untouched — this only affects the Add panel's own filter row.
- **The three icons are CCP's in-game fitting-window art, copied from the EVE University wiki into `public/images/fitting/{hull,resource,skill}.png`** — the same sourcing pattern as the Ship Tree's class/faction icons (`20260926-135538-fittings-ship-tree-tab-and-ship-info-window.md`): copied rather than linked so the feature never depends on the wiki staying up, credited to CCP under the Data credit. There is no SDE or ESI image-server source for fitting-window UI chrome (confirmed by searching this repo's SDE build and `eveImages.ts`) — only per-type-ID item icons/renders and portraits are served that way, never client UI sprites — so unlike ship icons these three can't be fetched at runtime and are bundled as static assets instead.
- **The "N hidden" note only counts Resources and Skill, never Hull.** Most of the market fails a given hull's rack rules outright (capitals, structures, the other faction's ships' hardware), so counting past a Hull-off state would routinely name four- and five-digit counts and the note would stop being useful. Hull's own icon still toggles independently; the note's "show them" action only ever relaxes Resources and Skill.
- **`hullFitService` and `hullFit.worker` no longer drop hull-failing items from the check map — every fittable item now gets an answer, `fitsHull: false` included.** Both paths previously threw those rows away before this change existed, because nothing needed them (the old hard filter used the row's _absence_ as "doesn't fit"). `checkHullCandidate`'s null return for a hull failure is gone too — it now returns the same cheap, no-skill-cost check it always computed internally, just without discarding it; `RESULT_VERSION` bumped so a stale saved `hullFitCache` row (from before this change) is recomputed rather than silently missing hull-failing rows for a returning pilot. A rack the hull has zero slots of at all (`racksWithSlots`) is answered `fitsHull: false` for every item in it without asking the engine at all, on both the worker and page paths — cheap, since that verdict never depends on the item or the engine, only the hull's own slot counts.
- **A row the hull refuses outright is never addable, whatever the filters say.** With Hull off, `FittingAddPanel` can now show items dogma would reject at the door — the "Doesn't fit this hull" label replaces "Missing skills" on such a row, and it can't be clicked or dragged in, unlike a resource- or skill-failing row (which the game lets you fit and simply not activate).
