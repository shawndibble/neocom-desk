# Scope decisions — Calendar week-start day is a device-local Settings preference

_Recorded 2026-09-26._

- **Calendar's Month/Fortnight grids can start the week on Monday or Sunday, chosen in Settings, device-local, defaulting to Monday.** Monday is EVE's own in-game calendar value, so nothing moves until a pilot asks it to. `lib/calendarGrid.ts`'s `startOfWeek`/`buildMonthGrid`/`buildFortnightDays`/`weekdayLabels`/`formatFortnightLabel` all take an optional `WeekStart` parameter (default `'monday'`) rather than a second copy of each function — the same grid math, one more input. The preference itself (`features/character/calendarWeekStart.ts`) is Calendar-only in what it's consumed by (nothing else in the app builds a week-aligned grid), same as `calendarViewPref.ts`'s density — but its control sits in Settings' general Display panel beside Time format rather than as a page-level toggle, because "which day starts my week" is a set-once-and-forget preference like text size, not a per-visit choice like Month vs. Fortnight density.
- **This store needed its own `useHydratedStore` call inside `Settings()` itself**, unlike `fontScale`/`timeFormat` which `App.tsx` hydrates for the whole shell. Every other Calendar-local store (`calendarViewPref`, `calendarKindFilter`, ...) is read only from within `Calendar.tsx`, after that page's own `hydrate()` — this is the first Calendar-local store also exposed as a Settings control, so a cold load straight to `/settings` needs to hydrate it there too, or the chip would paint the default until Calendar happened to be visited first.
