# Scope decisions — Guest close-account forfeit rules and dismissals in the verify allocation (issue #4184)

_Recorded 2026-10-18 · issue #4184._

- **Close-account is one `closeAccount` edit, not two calls.** It issues the optional final Statement and sets `miners/{id}.closedAt` (plus `finalStatementId`, `closedBy`, `closeReason`, `closeCredit`) in one transaction, so a failed close never leaves a Statement behind. A solo guest has no Miner document until now; the close creates it (with their own-lines `uids`).
- **Only a guest can be closed.** The server reads the Miner's characters' latest observed day: if the ore was recorded for this corporation it refuses (`not-a-guest`). A leaver's debt keeps its one-click write-off. The Miner page offers the action only on a `guest` Miner.
- **Credit is refunded unless forfeit is justified.** Forfeit needs either a recorded consent note, or an "asked on" date at least 90 days back (the refund offer went unanswered). The server checks both (`forfeit-not-allowed`); the dialog shows the same rule through the engine's `forfeitAllowed`, pinned to the server mirror by `functionsMirror.test.ts`. A forfeit re-checks the role live (D7), a refund does not. The ISK refund itself is sent by the officer in game and recorded as a payment; the app cannot move ISK.
- **Mail stops by skipping, not by deleting.** `planStatementRun` skips closed Miners, so no later Statement is drafted; `StatementRun`'s "not yet mailed" list keeps the final Statement and anything issued before the close, and drops the rest (`mailableAfterClose`). The final Statement is mailed from the Statements tab like any other. The server also refuses `issueStatement` and `setMiner` for a closed Miner.
- **Days that are not Billable at the close are never billed.** The dialog says how much tax that is. Reopening is not built.
- **Moon and Extraction dismissals now count on the verify read.** The read loads the book's Extractions and uses the same rule as the client (`moonOnDay` with the book's per-structure expiry hours, from fracture through expiry). This supersedes the earlier decision that left those scopes out; `functionsMirror.test.ts` runs both copies on the same inputs.
