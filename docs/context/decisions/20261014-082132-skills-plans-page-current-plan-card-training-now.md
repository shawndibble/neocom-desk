# Scope decisions — Skills Plans page: current plan card, training-now hero, period groups

_Recorded 2026-10-14._

- **The Plans page leads with the in-game Skill Queue, not the plan list.** It opens on a queue strip (length, end date, skill count), then the level training now as a card, then everything queued behind it grouped by when it finishes (this week, next 3 weeks, month 2, then two-month windows). Supersedes the list-left layout of `20260902-052840-skill-plans-side-by-side-layout.md` for this route only; the editor route keeps its sidebar list.
- **"The plan" is the Skill Plan edited last.** The rail's Skill plan card shows that one plan (name, length, finish) as a link into its editor. A pilot with one plan sees it; with several, it is the one they were last in. Other plans are reached from "All plans…", a dialog holding the same `PlanListPane` the editor sidebar uses, so rename, duplicate, copy, delete and the certified and community starts keep one implementation. Moves the row-menu actions of `20260926-123835-plan-rename-lives-in-the-list-row-menu.md` into that dialog on this route.
- **Hero figures come from ESI, not attributes.** Progress is the elapsed share of the level's own start..finish window and SP/hr is its SP span over that window, so both already carry attributes, implants and clone state, and agree with the dates shown beside them (see `20260902-205013-a-plans-times-match-the-in-game-queue.md`).
- **Group is shown by icon and name, not colour.** The mockup's coloured stripe per skill group would have needed an invented palette whose hues collide with the status colours (success, danger, warning); the group icon and its name already say it without colour.
- **Phone puts the plan row and attributes above the queue, each as one line.** The plan is one tappable row (⋮ holds All plans… and New plan) and attributes are INT/MEM/PER/WIL/CHA on a single line, so the training card is still near the top. The remap note and data age stay desktop-only.
