# Scope decisions — MutaMarket is the abyssal price source

_Recorded 2026-10-16._

- **An abyssal (mutated) module is priced by MutaMarket's estimate, nothing else.** No market order exists for a mutated item, so Fuzzwork/ESI have no price for it; MutaMarket (mutamarket.com) runs a per-type price model on contract sales and serves the result as `estimated_value` from its free, keyless public API (`GET /api/modules/{itemId}`). Rejected: sampling public contracts ourselves (one ESI call per contract plus one per item, and we would still need a model).
- **Reached through a Cloud Function, `mutamarketEstimate`.** MutaMarket sends no CORS headers (checked: no `Access-Control-Allow-Origin`, preflight 405) and asks every caller for a User-Agent with a contact address, which page JS can't set. The callable takes `{ typeId, itemId, importIfMissing? }` (positive integers and a boolean, nothing else). User-Agent: the app's ESI one plus a contact, `Neocom Desk (github.com/shawndibble/neocom-desk); contact: https://github.com/shawndibble/neocom-desk/issues`.
- **A Character session is required, and importing is opt-in.** An import (`POST /api/modules`) gives the module a public page at `mutamarket.com/modules/{slug}` showing its rolls and its creator Character, and every import goes out under our User-Agent. So the callable rejects a caller without a Firebase session (`unauthenticated`, as the community callables do); anyone with assets to price has a Character, and the client signs in with `ensureAnySession`, as the public snapshot readers do. A plain lookup only GETs: a module MutaMarket hasn't seen answers `not-imported`. The function POSTs only when the call carries `importIfMissing: true`, which the UI sends on the pilot's explicit click and never while merely listing assets. Rejected: an anonymous callable (anyone holding the bundled Firebase config could drive ~20 imports a minute through us, publishing other pilots' modules) and importing on view (it publishes a pilot's module without asking). The function can't check that the caller owns the item; the session plus the import queue bound the abuse.
- **We never loop MutaMarket's import.** `POST /api/modules` reads ESI and runs the model, seconds per call, and their docs say not to loop it. The function GETs first and POSTs only on a 404 with `importIfMissing`; never for a type absent from `/api/estimator-statistics` or with an untrained model (`r2` null); one import at a time, 3 s apart, at most 5 queued, else `resource-exhausted`. A failed import (5xx, timeout) is not retried for that module for 1 h, however many clients ask. `maxInstances: 1` makes that queue and the memory cache global.
- **Caching.** Function memory, keyed by type id and item id (so a call with the wrong type id can't blank the item for others), at most 5,000 entries: a priced answer 6 h, `not-imported` 1 h, "no estimate"/"unknown" 24 h, the estimator list 24 h. Client (`src/market/mutamarket.ts`): the same TTLs in memory and in the `esiCache` table under `GLOBAL_CACHE_CHARACTER_ID`, key `mutamarket:{itemId}`, so no Dexie schema change. An import ask skips a cached `not-imported`. From one client, imports run one at a time and lookups at most 4 at once. Failures are never persisted.
- **Unpriced stays unpriced.** `getAbyssalEstimate` never throws and never answers 0: anything but `status: 'priced'` has `value: null`, a non-positive or non-finite estimate counts as no estimate, and a failure is `unavailable` (held in memory 5 min so a list doesn't retry each module). Consumers leave an unpriced module out of a total and say so; they do not count it as 0 and do not fall back to the base module's market price.
- **Attribution.** MutaMarket's API overview and legal page ask for no attribution. We credit it anyway beside every MutaMarket value: `market.mutamarket.priceFrom` ("Price from MutaMarket") linked to the module's MutaMarket page (`url`), and `market.mutamarket.estimateNote` says it is a model estimate, as MutaMarket's legal page does.
- **Not wired in yet.** Assets, appraisal and net worth pick this up in a later change, for abyssal (mutated) modules with an item id; a `not-imported` module offers the pilot an explicit "get MutaMarket estimate" action. `/api/abyssal-type-statistics` (roll ranges) is not proxied: nothing needs it yet.
- **Needs a deploy.** CI deploys only the GitHub Pages site; functions go out by hand (`firebase deploy --only functions`, docs/SYNC-SETUP.md). Until `mutamarketEstimate` is deployed every lookup is `unavailable`, which is harmless: the client merging first shows nothing new.
