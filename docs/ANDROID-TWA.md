# Android app (Trusted Web Activity)

The Play Store app is a **Trusted Web Activity (TWA)**: a thin Android shell that
opens https://neocomdesk.com full-screen in Chrome. There is no separate web
build and no app code in this repo — the shell is generated by
[Bubblewrap](https://github.com/GoogleChromeLabs/bubblewrap) from the deployed
web manifest.

`twa/twa-manifest.json` is the Bubblewrap config, checked in. Everything else
Bubblewrap writes into `twa/` (the keystore, the generated Gradle project,
build output) is gitignored and must never be committed.

> **Gap:** the checked-in `twa-manifest.json` was rebuilt from Bubblewrap's
> defaults and this repo's values, not recovered from the original build. Before
> the next release, compare it against the original (if anyone still has it),
> and set `appVersionCode` above the version code Play Console shows for the
> live release — the `1` here is a placeholder, and Play rejects an upload
> whose code isn't higher. `signingKey.alias` is Bubblewrap's default
> (`android`); match it to the alias in the real keystore.

## What ties the shell to the site

| Value                | Where                                                                                | Current               |
| -------------------- | ------------------------------------------------------------------------------------ | --------------------- |
| Application id       | `twa-manifest.json` `packageId`; `public/.well-known/assetlinks.json` `package_name` | `com.neocomdesk.app`  |
| Signing cert SHA-256 | `assetlinks.json` `sha256_cert_fingerprints`                                         | `41:EF:BB:8E:…:D0:CE` |
| Start URL / display  | `vite.config.ts` PWA manifest                                                        | `/`, `standalone`     |

`assetlinks.json` is served from `/.well-known/` on the production origin. It is
the Digital Asset Links proof that lets the app open the site without a browser
URL bar. If the fingerprint doesn't match the key that signed the installed
build, the app silently falls back to a Custom Tab with a URL bar.

**Play App Signing:** if Play re-signs the upload, the fingerprint that matters
is the _app signing key_ shown in Play Console → Setup → App signing, not the
local upload key. `assetlinks.json` may list both.

## Build steps (standard Bubblewrap)

```sh
npm i -g @bubblewrap/cli          # needs JDK 17 + Android SDK; it offers to download both
cd twa                            # twa-manifest.json is already here
# put android.keystore here (from the secret store), then:
bubblewrap update --skipVersionUpgrade   # generates the Gradle project from twa-manifest.json
bubblewrap build                  # -> app-release-bundle.aab (Play upload) and app-release-signed.apk
bubblewrap fingerprint list       # prints the SHA-256 to paste into assetlinks.json
```

Later releases: `bubblewrap update` (bumps `appVersionCode` and regenerates the
Gradle project from `twa-manifest.json`; `bubblewrap merge` first if the web
manifest changed), then `bubblewrap build` and upload the `.aab` to Play
Console. Commit the bumped `twa-manifest.json`.

Automation notes: `bubblewrap build` is interactive only for the keystore
password — supply it via `BUBBLEWRAP_KEYSTORE_PASSWORD` and
`BUBBLEWRAP_KEY_PASSWORD`. Keep the keystore in a secret store, not the repo.

## Notifications

Two `twa-manifest.json` settings decide whether a push shows up as the app or
as Chrome:

- **`enableNotifications: true`** — notification delegation. Without it, Chrome
  posts every notification itself, so it's labelled "Chrome", lives under
  Chrome's notification settings, and shows Chrome's small icon. With it, the
  shell registers Chrome's delegation service and adds Android 13+'s
  `POST_NOTIFICATIONS` permission, and notifications show as Neocom Desk.
  Delegation only works while the Digital Asset Links check passes (no URL
  bar); a Custom Tab fallback stays under Chrome regardless.
- **`monochromeIconUrl`** — once the shell posts notifications, the status-bar
  icon is the shell's own `ic_notification_icon`, not the web `badge` option.
  Bubblewrap generates it from this URL: `icons/badge-96.png`, the same
  silhouette the web notifications use, also listed in the web manifest as a
  `monochrome` icon so `bubblewrap merge` (which re-reads the web manifest)
  keeps it.

After shipping a build that turns delegation on, a user who already allowed
notifications while Chrome owned them must toggle notifications off and on in
the app so the device registers again through the shell.

## How the app knows it is the Play Store app

`src/lib/playStoreApp.ts`. A TWA launch sets `document.referrer` to
`android-app://com.neocomdesk.app`; a browser tab or a Chrome-installed PWA does
not (both look `display-mode: standalone`, so that media query can't tell them
apart). The result is kept in `sessionStorage` because the referrer only exists
on the first load. `Login.tsx` uses it to show the minimal logo + sign-in page.

If the package id ever changes, update `PLAY_STORE_PACKAGE` there as well as
`assetlinks.json`.
