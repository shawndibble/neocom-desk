## Routes (`src/app/App.tsx`)

- `/` -> `Root` (`:229`): Character count unresolved or active-store not hydrated -> `BootScreen gate="root"`; 0 Characters -> `/login`; Characters but none active -> `/characters`; else `/overview`. Waits on the active-character store as well as the count, so a returning user is not bounced to `/characters` (comment above `Root`).
- `/login`, `/callback`: eager, outside the shell (`docs/features/auth-login.md`).
- Under `RequireCharacter` -> `SignedInShell` (lazy `Layout`, preloaded at boot by `signedInShellHint`/`bootShellPreload`) -> every entry of `ROUTE_ELEMENTS` (`:151`) wrapped in `ScopeGate`, and `TabRoute` when the page is tabbed (`PAGE_TABS`, ADR 0015).
- Outside the shell: `/styleguide` (hidden design reference), `/share/fitting`, `/share/:shareId` (`:370`, no session needed), `/error` (`:372`), `*` -> `NotFound` (`:373`).
- Mounted once beside the router: `ReloadPrompt`, `EntityInfoRoute`, `PublicInfoModal`, `SkillDetailModal`, `ItemInfoModal`, `InstallPrompt`; trackers `AuthFailureRedirect`, `AnalyticsPageViewTracker`, `DocumentTitleTracker`.
- `ROUTE_ELEMENTS` is `satisfies Record<AppRoutePath, ...>`: a route without a scope declaration is a compile error; `routeScopes.test.ts` scans `App.tsx` so hand-written feature routes cannot slip through.
- Boot effects in `App()`: hydrate active Character, font scale, time format, mobile tabs, hidden nav and Recent nav (so first paint is right); subscribe ESI auth-failure, activity log, blocked-upgrade report, DB-wipe reload; schedule cache prune and lazy SDE warm; `triggerSync` of the active Character; `useBackgroundSync`; write `signedInShellHint`; `scheduleBootPrefetch` (idle slot, cancelled on switch).
- Layout transitions: a 140 ms opacity fade on page change only (not tab changes), skipped for reduced motion or no Web Animations API (`Layout.tsx:216-228`); route focus moves to the new page's `<h1>` after a real page change (`src/app/routeFocus.ts`, below).

## Nav model (`src/app/navDestinations.ts`)

One descriptor feeds the rail, tab bar, More sheet and palette (`NAV_PAGES`, `:109`; `listNavDestinations`, `:374`). Groups: primary (no heading: Overview with views Clones and Employment, Alerts, Corporation), Progression (Skills with four sub-views, Industry, Ships, Mining, PI), Economy (Market with LP Store sub-view, Wallet, Assets, Contracts), Social (Mail, Calendar, Contacts), Intel (Travel, Pilot Lookup), footer (Help, Settings, Characters). Labels: Overview, Alerts, Corporation, Skills, Industry, Ships, Mining, PI, Market, Wallet, Assets, Contracts, Mail, Calendar, Contacts, Travel, Pilot Lookup, "Help & FAQ", Settings, Characters (`nav.*`).

Gating kinds: `scope` (page locked, never hidden or disabled when a grant is missing), `corp` (hidden, not locked, unless Corp Access `ready` and the corporation is known — an amber dot would offer a re-login for a role only CCP can grant), `ungated` (Travel, Pilot Lookup, Help, Settings, Characters). `mobileTab` false for Corporation (hides rather than locks; a chosen one would leave a hole) and Settings and Help (permanent More rows). Characters is a tab choice but is excluded from the More sheet tiles (it has the portrait row).

Locks: `NAV_LOCK_PATHS` (`:311`) = every `scope` page and its sub-views; `useLockedRoutes` (`src/app/useGrantedScopes.ts:38`) builds one set from the stored grant (`undefined` -> empty set: no lock flashes while Dexie loads). A route is locked when `requiredScopesForRoute` has a scope not held. Only six routes actually declare endpoints (whole-page `ScopeGate`): `/assets` and `/assets/*` (`src/app/routeScopes.ts:178`), `/mail` (`:204`), `/clones` (`:243`), `/contacts` (`:269`), `/mining` (`:278`), and `/market/lp-store(/:id)` (`:39`: loyalty points). Everything else, including Wallet, Contracts, Industry, PI, Calendar, Overview, Market, is `UNGATED` at route level and degrades per panel (Grant notes/banners).

### Hide rules (`src/app/navRail.ts`)

## Scope gating and Grant UI

- `ScopeGate` (`src/app/ScopeGate.tsx:40`): for a gated route with a missing scope, renders a `ReauthBanner` in place of the page (not a redirect; title/hint/action from the route's i18n namespace `<ns>.reauthTitle|Hint|Action`, button asks `beginEveLogin({groups: permissionsForRoute(path)})`, `soleAction` for the 44 px tier). Decides from the stored grant before any request (never from 403s, which also mean a structure ACL no re-login can fix). While the Dexie read is in flight it renders the children (no spinner flash).
- `GrantBanner` / `GrantNote` (`src/app/GrantNote.tsx:33,69`; `grantAction.ts:15`): inline banner for a figure that degrades to a documented assumption (e.g. "Assumes no implants", "Assumes base standings"); appears only once the grant is known and missing, vanishes live when granted; action = `beginGrant(characterId, endpoints)` -> `beginEveLogin({characterId, groups: permissionsForEndpoints})` (explicit Character, because in multi-Character views the Character needing the grant is often not the active one).
- `grantCovers` (`src/app/grantCovers.ts:23`): the single "may this Character be asked" test for speculative reads (boot prefetch, hover warm), because a route can be `UNGATED` yet compose scoped reads (Calendar).
- `AuthFailureNotice` (`src/app/AuthFailureNotice.tsx:56`): a partial runtime failure (one ESI read 401/403 while the stored grant claimed the scope) -> dismissible ghost banner "EVE access was refused" naming the Character, **Log in again with EVE Online** asking for the refused endpoint's Permission, **Dismiss**; suppressed when the page owns its own re-auth (`pageOwnsReauth`, `:72`); active Character only.
- `AuthFailureRedirect` (`:24`): a total failure (`invalid_grant` only: `src/app/tokenProvider.ts:20`) for the active Character -> `navigate('/login', {replace, state:{from}})` once, unless already on `/login`.
- `StandingsScopeNotice` (`src/app/StandingsScopeNotice.tsx`): active Character whose grant lacks the standings scope -> "Broker fees are assuming 0 standings" + **Grant Character details** + **Dismiss**; dismissal per Character in `localStorage` `standingsScopeNoticeDismissed:<id>` (`:11`).
- `CorpGrantPrompt` (once per scope set when Corp Access becomes `roles-without-grant`; never again for that set; Settings › Permissions Corporation row is the durable path) and `NotificationPermissionPrompt` (once per device; Enable/Not now) mount in `Layout`. Banner priority for the one fixed bottom slot: `corp-grant` > `notifications` > `install` (`onboardingBannerSlot.ts:27`); eligibility is each banner's own, they only compete for the slot, so at most one shows.

## Update flow (`src/app/ReloadPrompt.tsx`; `docs/adr/0007-hand-written-service-worker-for-background-sync.md`)

No UI. Service worker `registerType: 'prompt'`. Polls `registration.update()` every 30 min (`:6`; skipped offline or while installing). A waiting update applies: immediately if found within 15 s of page start (`BOOT_APPLY_WINDOW_MS`, `:18`; a reload finding a fresh build), never on `/callback` (a reload would replay the spent OAuth code, `:117`); when the tab has been hidden >= 30 s (`:10`, re-checked on `visibilitychange` and every 15 s, `:13`); or on the next in-app route change of a visible tab (never mid-page on idle); a manual reload counts as consent (`beforeunload` fires skip-waiting best effort). Reloads go through a fade-to-background cover (150 ms, instant with reduced motion) instead of the library's flicker. Manual: Settings › Data & storage › **Update now** (`sync-backup.md`).

## Boot, errors, not found

- `BootScreen` (`src/app/BootScreen.tsx`): logo, name, spinner, "Loading…". With a `gate` (`root`, `require-character`, `login`, `fitting-shared`) it waits 10 s (`BOOT_STALL_MS`, `:12`), then says "Still loading. Another copy of the app may be holding your local data open." and offers **Reload** ("Reloading…" disabled once tapped). Reload = `recoverFromStalledBoot` (`bootRecovery.ts`): each step bounded 2 s (`:26`), get the registration, post `SKIP_WAITING` to a waiting worker if any (promotes the new bundle, evicting an old worker holding an older Dexie schema), wait 2 s, reload. Not guaranteed (a blocker like another tab survives a reload) but never leaves no action. Stall reported to Sentry once per page session, then "resolved after N ms" (`bootStallReport.ts:27`). A stalled live region `role=status` is mounted empty so the hint is announced. Without a `gate` (shell chunk download) there is no timer or recovery.
- `ErrorBoundary` (`src/app/ErrorBoundary.tsx`): full-page at the top, inline inside the shell around the outlet (rail survives); title "Something went wrong", hint "Reloading usually fixes this. Your Skill Plans and Build Plans are stored locally and are not affected.", **Reload**; never shows the error text; `resetKey` = pathname so navigating away clears it (`:70`); a chunk that fails to load lands here and retries on navigation (`preloadedLazy` does not cache failures).
- `NotFound` (`src/routes/NotFound.tsx:17`): "Page not found", hint, **Go to Neocom Desk** (to `/`), "Think this is a bug? Ask on Discord". Paired with a build-time `404.html` copy of `index.html` (GitHub Pages has no SPA rewrite).
- `/error` (`src/routes/ErrorProbe.tsx`): throws on render so Sentry can be verified; unlinked; tagged `probe`; the Reload button re-throws.

## Document title (`src/app/documentTitle.ts`)

`{most specific} — {…} — Neocom Desk` (separator `—`, `:14`), computed per pathname (tabbed pages add the tab label, nested routes add the section; duplicate names collapse so Market's Browser reads once, `:100`); `ROUTE_TITLE_KEYS` is `satisfies Record<AppRoutePath, ...>` so a new route without a title fails to compile; unmatched -> "Page not found"; `/login`, `/callback`, `/styleguide`, `/` -> app name alone. Updates when the language changes (WCAG 2.4.2).

## Route focus and tab routes

After a real page change focus moves to the new page's `<h1>` without scrolling (`src/app/routeFocus.ts`): not on first load, not with a hash in the URL, not for tab switches, drill-downs in the same page (`/assets/<id>`), or sub-nav pages (`SUB_NAV_PAGES`, `:19`: Skills, Corp, Overview sub-views). A page whose `<h1>` renders late gets 2 s (`HEADING_WAIT_MS`, `:32`) watched by a `MutationObserver`; the outlet container takes focus if none appears; a user who focused something else meanwhile keeps focus.

## Analytics (`src/app/analytics.ts`)

Firebase Analytics (GA4) `page_view` on every route change, only when `VITE_FIREBASE_MEASUREMENT_ID` is set, not in tests, and `isSupported()` (`:24`; lazy-imported, kept out of the startup bundle by `bootImportGraph.test.ts`). `page_path` is the route _pattern_ (`pagePathFor`, so `/skills/plans/:planId`); the redirect-only path of a tabbed page is skipped (`isTabRedirectPath`). `page_location` is the full `window.location.href` including the query string (`:71`). Failures drop the event silently.

## Interview Q&A

1. **Where do I land when I open the app?** `/` -> Overview for an active Character, `/characters` for Characters with none active, `/login` for none (`src/app/App.tsx:229`). First-ever login with one Character goes to Overview, adding an alt goes to `/characters` (`src/routes/Callback.tsx`, `docs/context/decisions/20260925-182747-first-login-with-one-character-goes-to-overview.md`).
2. **Why does a locked page still show in nav?** Locks mark, never hide or disable, because the `ScopeGate` banner is the explanation and the only way to fix it (`src/app/NavItem.tsx` doc; `navDestinations.ts:20`). Corporation is the opposite: hidden, since only CCP grants roles.
3. **Which pages are actually gated?** Whole-page: Assets, Mail, Clones, Contacts, Mining, LP Store (`src/app/routeScopes.ts:178-278,39`); all others degrade per panel.
4. **Why exactly four phone tabs?** Equal-width split of a possibly 320 px viewport; fewer looks unfinished, more truncates labels; stored arrays of another length are discarded (`src/lib/mobileTabs.ts` header comment, `:43`, `:101`).
5. **Does hiding a page remove it?** No: it stays in Go to and More; the page you are on is always shown; footer pages and Corporation can't be hidden (`src/app/navRail.ts:88,94`; string `nav.editHint`).
6. **Does nav hiding sync?** Yes (`sync.navHidden`), Recent does not (`src/app/navPreferences.ts:14,20`).
7. **What triggers an app update and why not a banner?** Silent; applies at boot window, after 30 s hidden, or on next route change; never on `/callback` (`src/app/ReloadPrompt.tsx:6-18,117`), to avoid wiping in-progress input.
8. **What if boot hangs?** After 10 s a Reload button appears; recovery promotes a waiting service worker, bounded 2 s per step (`src/app/BootScreen.tsx:12`, `bootRecovery.ts:26`).
9. **Do shortcuts fire in text boxes or dialogs?** No: typing targets and open overlays suppress them; Ctrl/Cmd+K is the exception for typing targets but refuses to open over an open dialog (`src/app/useKeyboardShortcuts.ts:20`, `src/lib/shortcuts.ts:53`).
10. **What does pasting do?** An EFT fit opens in Fittings, an item list in Appraisal, no confirmation; Back undoes (`src/app/GlobalPasteRouter.tsx`).
11. **What does the Customize dialog remember?** The last submitted selection on this device only; Cancel discards (`src/features/permissions/customizeSelection.ts:16`).
12. **Why is "Grant" unioned with stored scopes?** SSO issues exactly what is requested; asking for less would silently narrow the grant and revocation is judged as requested vs granted (`src/app/loginFlow.ts` docs; `docs/features/auth-login.md`).
13. **What happens on a dead refresh token?** `invalid_grant` -> central report -> `AuthFailureRedirect` sends the active Character's session to `/login` (`src/app/tokenProvider.ts:20`, `AuthFailureNotice.tsx:24`) — see gaps for what `/login` then does.
14. **How is the tab title built and why?** Page › tab › app, deduplicated, for crowded tab strips and screen readers (`src/app/documentTitle.ts:14,100`).
15. **How do analytics treat tabs and redirects?** Route pattern, not concrete URL, and bare tabbed paths skipped so a rail click is one page view (`AnalyticsPageViewTracker.tsx`, `pagePathFor.ts`).
16. **Which onboarding banner wins?** `corp-grant` > `notifications` > `install` for one fixed bottom slot (`src/app/onboardingBannerSlot.ts:27`).

## Observed gaps

- Old permanent Fitting Share Code links `/fittings?f=` (and `/fittings/*`) are redirected by a route that sits inside `RequireCharacter` (`src/app/App.tsx:175`, `src/features/fittings/LegacyShipsRedirect.tsx`); a signed-out visitor is sent to `/login` and, because `Login` ignores `state.from`, loses the fit. Only `/share/fitting?f=` is public. See `entities-share.md`.
- `Login` never reads `location.state.from` (no `useLocation`/`state` use in `src/routes/Login.tsx`); `RequireCharacter` (`src/app/RequireCharacter.tsx:26`) and `AuthFailureRedirect` (`src/app/AuthFailureNotice.tsx:37`) write it and nothing consumes it (the post-login landing uses a separate stash, `src/auth/loginReturnTo` via `rememberThisPage` in `src/app/loginFlow.ts`). Worse, `/login` with any Character present redirects to `/characters` (`src/routes/Login.tsx:264`), so a total auth failure navigates to `/login` and bounces on to `/characters`; the code shows no re-login prompt on that path (no `authFailure` consumer in `src/routes/Characters.tsx`; `AuthFailureNotice.test.tsx` only asserts the redirect lands on a stubbed `/login`). Cross-doc note: `docs/features/auth-login.md` says the redirect "remembers `from`" — nothing reads it.
- Stale comments: `ShortcutDef.descriptionKey` still says "shown in the Settings shortcut list" (`src/lib/shortcuts.ts:136`) and the Ctrl+K note says single-key shortcuts "can be switched off" (`:65`), but shortcuts moved to Help and are always on (`src/app/useKeyboardShortcuts.ts` header).
- `CustomizePermissionsDialog` header says "all 13 Permissions" (`:11`) while `SCOPE_GROUPS` has 15 and the counter reads "of 15" (`src/esi/registry.ts:53`).
- Most pages are `gating: 'scope'` in `NAV_PAGES` (Overview, Alerts, Skills, Industry, Ships, Mining, PI, Market, Wallet, Contracts, Mail, Calendar, Contacts, Assets: `navDestinations.ts:109`) but only Assets, Mail, Contacts, Mining, plus the Clones and LP Store views, are non-`UNGATED` in `routeScopes.ts`, so every other page's lock dot can never appear; the descriptor's gating label overstates what the router enforces.
- Help › Shortcuts "On a page" rows are hard-coded (`src/features/help/ShortcutsPanel.tsx`), not derived from a registry, so they can drift from the real handlers.
- No single-key shortcut for Skills, Assets, Mail, Calendar, Contacts, Travel, Corporation (`src/lib/shortcuts.ts:152`); only ten keys, two of which (`,` `?`) are for settings/help.
- The phone has no indicator for "syncing"/"offline" (see `sync-backup.md`).
- Install Prompt never shows on Android Chromium unless `beforeinstallprompt` fires; no fallback instructions (`installPromptRules.ts:51`).
- Updates apply silently with no "update available" indicator; a visible idle tab can run an old build until the next navigation or hide (`src/app/ReloadPrompt.tsx`).
- Analytics `page_location` carries the full query string (e.g. `?info=`, `?f=`, filters) (`src/app/analytics.ts:71`); the in-app FAQ does not mention analytics (the privacy page does).
- FAQ "Support" is Discord only; there is no in-app diagnostics or log-copy for bug reports (the Activity Log exists in Settings but is not linked from Support).
- The More sheet cannot show a page's views; reaching a deep view on a phone depends on Recent, search, or the page's own tabs (documented design: `MobileMoreSheet.tsx` header).
- `BootScreen`'s stall hint names only one cause (another copy of the app holding data) (`boot.stalledHint`).
