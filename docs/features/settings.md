## Storage model

Three tiers, all in Dexie `db.settings` (key/value) unless noted:

- Device-local: `createLocalSetting` (`src/lib/useLocalSetting.ts`). Plain key. Rejects any `sync.` key.
- Synced: `createSyncedSetting` (`src/lib/useSyncedSetting.ts`). Key `sync.*`, must be on allow-list `SYNCED_SETTING_KEYS` (`src/sync/syncedSettings.ts:~230`). Write = Dexie put -> `setSyncedSetting` (stamps for last-write-wins) -> `scheduleSync` for every Character on device. Pull rewrites Dexie, stores re-read after each sync and re-run `parse`. `legacyKey` seeds an unstamped value from the old device-local key (old row left in place). Whole-value LWW per key; deletes use a 30-day tombstone.
- Session-only: Activity Log (zustand, not persisted).

Sync: Firestore, per-Character uid, `src/sync/planSync.ts`; background sweep every >= 5 min active Character / 20 min others, on tick + `visibilitychange` (`src/app/backgroundSync.ts:36-45`). Sync state is a dot in the app shell (`SyncStatusDot.tsx`: idle/syncing/error/offline) — there is no sync UI inside Settings. Setup: `docs/SYNC-SETUP.md`. FAQ "What We Store": `src/features/faq/whatWeStore.ts`.

Settings forms show `DefaultsSyncHint` ("Kept across your devices") on every synced section (`settingsFields.tsx`).

## Interview Q&A

1. Which settings sync and which do not, and what is the rule? Synced (`sync.` keys, `lib/useSyncedSetting.ts`): preferences that describe the pilot's play (hub, ME/TE, blueprint cost, courier ratio, LP value, mining ore form, Characters defaults, dark threshold, all Travel rules except bridges, PI expiring window). Device-local: those describing the machine or screen (text scale, time format, week start, phone tab bar) plus PI sell/cadence, jump bridges, auto-continue sessions, notifications master/channel gates. Rule from decision `20260907-221425`; allow-list `SYNCED_SETTING_KEYS` (`sync/syncedSettings.ts`) pinned by test, and a new key forces an FAQ update.
2. How do conflicts between two devices resolve? Whole-value last-write-wins per key using a stamp from `setSyncedSetting`; a legacy-adopted value is written unstamped (`updatedAt` 0) so any real remote edit wins (`useSyncedSetting.ts` header). Deletes propagate via tombstones that expire after 30 days, so a device offline longer re-pushes its stale copy (`syncedSettings.ts` comment, `merge.ts:31`). That is why synced settings are "set to another value, never unset".
3. Why does a settings write fan out to every Character? Sync is per-Character (each has its own Firebase uid) while a synced setting is device-global; pushing under only the active Character would leave a device that holds only another Character blind to the change (`useSyncedSetting.ts` header).
4. What stops a click from overwriting a stored value with a default? `useHydratedStore` gates every form (Spinner) because a cold deep link to `/settings/...` mounts none of the stores; spreading an unhydrated record would silently drop fields (e.g. rig level, facility tax) (`useHydratedStore.ts` comment).
5. How does text scale avoid a flash on load? A synchronous `localStorage` mirror read by an inline script in `index.html` sets `<html>` font-size before first paint; Dexie is source of truth and heals the mirror (`lib/fontScale.ts:11-60`).
6. What does "Reset saved view preferences" actually delete and why not clear the table? 15 explicit keys (sorts, filters, expanded sections); never `db.settings.clear()` because the table also holds user-made groups, saved comparisons, starred Characters, ore tags, and every `sync.` key. The list is hand-maintained and pinned by `viewPreferenceKeys.test.ts` so adding a preference forces a decision.
7. How does the encrypted backup work and what are its limits? PBKDF2-SHA256 600k iterations -> AES-GCM-256; payload = all Characters, tokens, Editable Data, allow-listed `sync.` settings (excludes `esiCache`, notification feed). Import skips any Character already on the device whole and writes new ones in one transaction; reloads so boot sync refreshes tokens. Limits: bearer-credential file; no recovery; no picker; no merge; no min password strength (ADR 0014, `backup/io.ts`).
8. What does "Delete all data" do vs "Log out"? Log out: flush sync, remove Characters and tokens, unregister push, sign out of Firebase; synced data remains and returns on login. Delete: halt sync, purge each Character's Firestore docs (shared Firebase session, sequential), then wipe IndexedDB, web storage and runtime caches (keeps the Workbox precache so an offline reload is not blank), clear badge, `location.replace('/')`. A purge that cannot run is never retried; the dialog names the Characters and waits on the 90-day inactivity purge (`deleteAllCharacterData.ts`, decision `20260926-223948`).
9. How do notifications reach a closed app with no server holding tokens? The client uploads a Projection of scheduled facts (skill finish, job end, extractor expiry, fuel, calendar) for the next 72 h; a Cloud Function fires due rows via FCM (ADR 0010). Periodic Background Sync was abandoned because Chrome floors it at 12 h (ADR 0009). Events that are state changes (undercut, mail) have no scheduled push and only fire while the foreground poller runs (5 min); the scheduled-push badge marks only events whose every occurrence is projectable.
10. Why can a notification row be disabled, and how is it fixed? Each event requires an ESI scope; if the Character's token lacks it the row is disabled and shows "Needs the <Permission> permission" with a Grant button that re-auths for that group (`missingEventPermission`, `events.ts:278`; test `Settings.test.tsx:714`). Corp events are also disabled when the Character lacks the role-derived capability; an unresolved capability read is treated as enabled, not locked.
11. How is the route penalty applied and why are Avoided Systems "a cost, not a wall"? `exp(0.15*penalty)` per unwanted jump (x2 nullsec), 0.9 wanted, 1 under Shorter, 1e12 per avoided system (`jumpRoute.ts:84-130`). A wall would make some destinations unreachable; a huge cost makes the route cross as few as possible while still returning a route.
12. Why can Industry assumed ME not be set to 11? Input is clamped 0-10 and a synced out-of-range value is rejected on read, because the industry engine throws on an invalid ME (`assumedMe.ts`, `useSyncedSetting` re-parses pulled values).
13. What is the page settings modal for, and how do forms avoid drifting? A page's gear/menu opens the exact same `*SettingsForm` Settings renders, in a modal with an "All settings" link, so there is one copy of each control (`PageSettingsModal.tsx`, decision `20261004-155006`).
14. How does the Corporation section hide, and can it still be reached? Hidden from the rail unless Corp Access is `ready` (`sections.ts:44`), but the URL still resolves and shows "unavailable" so a bookmark does not 404; the Permissions row is the way into corp access (decision `20260924-174340`).
15. What happens to old links into Settings? `/settings/shortcuts|faq|help` redirect to `/help/...`; `/settings/general`, `/settings/mobileTabs`, `/settings/device` fall to Display; `#shortcuts` -> Help shortcuts, `#corp-access` -> Permissions (`LEGACY_HASH_TARGETS`, `Settings.tsx:917`; `Object.hasOwn` so `#constructor` is ignored).
