### Data freshness rule (ADR 0005, kept by 0011/0012)

Only fields fixed at install are trusted: `expiry_time`, `extractor_details.{cycle_time,qty_per_cycle,heads}`, `install_time`, pin type/count. Never `contents[].amount` or `last_cycle_start` (ESI recalculates those only when the colony is opened in-game). UI states it: "What we can't see" line + `InfoTooltip` (`pi.stalenessTooltip`), "As of the last time you opened this colony" on launchpad.

### 4.4 Make a specific product - Goal Planner (`GoalPlannerPanel.tsx`, `GoalPlannerRail.tsx`, `goalPlanResults/*`)
Purpose: "I want N of product X per day; which colony does what, what do I buy, is it worth more than leaving my colonies alone?" Answer is a **Lift** over the **Baseline**, never a gross margin (`engine/pi/baseline.ts:1-30`, `planEconomics.ts:1-40`).

Pipeline: `planBest` (`engine/pi/planBest.ts:122`) solves `planGoals` once per eligible factory host and keeps the best; `planDiff` makes the change list; `planEconomics` prices the plan's flows; `baselineTotal` is the comparison. Inputs deferred (`useDeferredValue`) so typing never waits on a re-plan; rail text commits debounced 300 ms (`GoalPlannerRail.tsx:42`). Layout: grid with a 20rem rail beside results at `md` (48rem) up; DOM order Goals, Colonies, Assumptions, results (no CSS `order`, WCAG 2.4.3). Colonies and Assumptions start folded on phone.

**Rail**
- **Goals**: `RegionSelect` combobox adds a product ("Product (Tn)", searchable; only plannable types: P1+, `usePiPlannable`; a P0 is refused because `planGoals` throws on it). New goal starts at 10/day (`DEFAULT_GOAL_PER_DAY`, `goalsParam.ts:18`). Per goal: tier chip, `PiProductLink`, units/day `UnitsBox` (commits on blur/Enter; invalid text shows `numberInvalid`), row menu (item menu + Remove). URL `?goals=typeId:perDay,...`; duplicate ids merge by summing, non-positive ids and negative/non-finite rates are dropped on parse, zero rate is kept (solver drops it). Hand-edited links naming a non-plannable type are filtered (`plannableGoals`), never crash.
- **Colonies** (folded on phone): per colony tick `Checkbox`; switched-off ids go to `?off=`. Row: facts, exclusion reason (no detail / no planet type / no link cost: such a colony cannot be planned), customs `PercentInput` (+ reset). Customs source text: highsec skill-derived, "assumed 10%" when skill unread, player POCO 0% outside highsec (`customsRate.ts:55`). `#customs` deep link expands and focuses it. Customs override is per system and synced (`sync.piCustomsRates`).
- **Assumptions**: settings summary (sell market, buy tiers, cadences) + "Change" opens the PI settings modal; "Max P0 types per colony" `SegmentedControl` 1 / 2 (default 2; one-per-planet gave false shortfalls on ordinary two-ECU colonies); fallback P0/h per ECU (default 6,000) shown only when some colony's rate is assumed. Both are device-local (`goalPlannerPrefs.ts`, key `piGoalPlanner`).

**Solver facts** (`engine/pi/goalPlan.ts`, header 1-110): greedy, not optimal; every gap is a named Shortfall. Policy (`goalPlannerModel.ts:270`): max 2 ECUs per colony, `maxP0TypesPerColony` 1|2, second ECU on the same P0 yields 0.8x (`DEFAULT_EXTRA_EXTRACTOR_YIELD_FACTOR`, `stopTier.ts:207`), `buyTiers` from settings. Steps: (1) type gaps, goals needing a P1 whose P0 no enabled colony's planet type yields are dropped and reported; (2) demand = `expandChain` at units/day / 24, summed across goals then factories re-ceiled (two goals share a factory); (3) factory host needed only for P2+, must carry every made schematic's factory (P4 => Barren or Temperate only); price-free default picks lowest scarcity score; (4) extraction: P0s scarcest first; fills host first, then colony already extracting that P0, then fewest ECUs, measured before estimated rate, etc; fewest ECUs that cover the need else the most that fit; (5) release-and-refill rounds (max 8, `goalPlanSteps/extraction.ts:130`): a goal short on its scarcest P1 runs at that fraction (`achieved`), surplus slots are released and refilled where P1 binds; (6) gaps bought at hub if the tier is buyable else Budget gap only if no colony yielding it can take more; buying higher tiers re-solves up to 4 rounds (`MAX_BUY_ROUNDS`, `goalPlan.ts:174`); (7) spare capacity: used-but-not-full colony adds one slot of its best P1; unused colony keeps role `baseline`; only a colony with no sellable Baseline is `idle`.

**Host choice** (`planBest.ts` `pickBest:88`): per candidate host rank by (1) goal attainment sum of min(1, achieved/requested); (2) fewer shortfalls; (3) among nets within 5% of max(|best net|, |Baseline|), floor 100 ISK/h (`NET_TOLERANCE`, `NET_TOLERANCE_FLOOR`): fewer changed colonies (verbs other than keep, and other than idle-that-ran-nothing); (4) fewer unknown-distance legs, then lower m3-jumps/h only among all-known; (5) higher net (only when every candidate priced); (6) smaller Baseline forfeited; (7) lower planet id. Reason tag on the plan: `only-eligible` or `best-net`. With <=1 candidate `planGoals` runs once.

**Results panels (top to bottom; each hides when empty)**
- **Headline** (`Headline.tsx`). `needs-price`: `EmptyState` "unpriced" naming missing types at the hub (never a number). Otherwise: warning line "N of M goals met" with unmet goals and their % when attainment < 0.999 (`goalPlanView.ts:22`) plus a "Lift counts met goals only" tag; big signed Lift ISK/day (green/red; zero neutral) with `InfoTooltip`; verdict sentence = lift (more / less / same, same when |lift| < 1 ISK/day, `goalPlannerModel.ts:391`) + hauling half (higher / lower / same %, "pending" while distances resolve, "unknown" if a leg has none); StatChips Net (goals only), Baseline, Earns now (what colonies make today; tooltip), Buys, Customs (goals only); "switch gain" line when |Baseline - Earns now| >= 1 ISK/day; "earns now left out" for colonies with no usable figure; caveat line with Estimate badge: colonies using an estimated rate, colonies at assumed customs (10%), types valued at the ask because no buy order exists. No goals: prompt "pick a product" with Baseline/Earns now only. Screen-reader live region announces the verdict 500 ms after the last recompute (5 s cap while distances pending). `DataAgeBadge` = price fetch time.
- **Shortfalls** (`Shortfalls.tsx`): header counts them. Four kinds: **type-gap** ("needs <planet types> for <P0>", rate P1/h and P0/h; "Open the Map" link, or "switched off: <colonies>" when an enabled-but-switched-off colony could fix it); **budget-gap** (hint = re-target <colonies> or buy the P1); **no-factory-host** (names the missing facility: advanced / high-tech); **host-over-budget** (colony + limiting axes CPU/Powergrid). Order set by `compareShortfalls`. Blocked goals show no budget gap for their other inputs until the type gap is fixed.
- **Changes** (`Changes.tsx`): one `DirectiveRow` per assigned colony, verb by `planDiff` (`engine/pi/planDiff.ts`): `keep` (same P0 set; ECU counts are NOT compared; `notNeeded` marks colonies the plan has no role for, which keep their Baseline), `add-extractor` (all today's P0s stay plus new), `retarget` (anything else on an extractor, incl. a colony extracting nothing today), `convert-to-factory` (host: names the extraction it gives up and the factory pins gained), `idle`. UI verbs: as-is, start, add, stop, swap (retarget), build (host). Detail lines: "Remove N ECU on <P0>", "Extract N ECU of <P0> + k basic -> <P1>", "Make n <product> factories", "Ship <item> to <place>" ("new" tag when the leg is new; only new legs on as-is rows), italic tip "switch to <P1s>" with gain for colonies not needed. P0 lists are sorted so reordering is never a change.
- **Colony fit** (`ColonyFit.tsx`): two-column grid of cards for every non-idle assignment: colony link, role (Extracting / Factory host / As is / Idle; "As is" wins when Changes says as-is), CPU and Powergrid `LoadMeter`s (used vs the colony's own Command Center budget, `colonyBudget(upgrade_level)`), warning "over: CPU/Powergrid" when `limitedBy` non-empty. Special case: if the colony runs this layout today (`runningToday`) and the model's load exceeds budget, meters are replaced by "Fit as built" + tooltip: the model is pessimistic, the layout is not over budget (`ColonyFit.tsx:117`). Slot lines "N ECU on <P0> -> <rate> <P1>/h" with an Estimate badge + tooltip when the rate is not the colony's own measured program at today's ECU count: `ecus-changed` (ECU count differs from today; second ECU scaled by 0.8), `own-mean` (mean of the pilot's measured programs; colony does not extract this P0 today), `assumed` (typed fallback; nothing measured). Factory hosts list pin counts (basic / advanced / high-tech). Footnotes "borrowed heads" (heads per ECU taken from other colonies, default 10 for unbuilt, `DEFAULT_PLANNER_HEADS`) and "borrowed link cost".
- **Hauling** (`Hauling.tsx`): meta "per trip = N days" (haul cadence). StatChips: effort Plan / Baseline in m3-jumps per trip (`haulEffortOf`: sum of units/h x volume x jumps; legs that stay put are not legs; unknown-distance legs counted, not guessed), change % (hidden unless every leg known and Baseline > 0; green when lower), plan and Baseline m3 per trip. ## 7. Engine (`src/engine/pi`, pure; TDD) - formulas and thresholds

Rules: no fetch/DOM/Dexie/`Date.now()` in the engine; `nowMs`, prices, rates, budgets arrive as parameters. Unknown is never zero: a missing price gives `needs-price`/`null`, a missing radius throws (`linkCost.ts:92`). Tests sit beside each module (`*.test.ts`; e.g. pinBudget 56, planAdvice 50, network 33, colonyStatus 32, extraction 32, planHaul 30, goalPlan 28, stopTier 27 cases).

### 7.1 Extractor decay (`extraction.ts`; CCP guide https://developers.eveonline.com/docs/guides/pi/)
- Per-cycle yield (`cycleYield`, `extraction.ts:61`): `t=(cycle+0.5)*barWidth` (bar = 900 s, so barWidth = cycle_time/900); `decay = qty/(1+t*0.012)` (`EXTRACTOR_DECAY_FACTOR`, dogma 1683); `phase = qty^0.7`; `sinStuff = max((cos(phase+t/12)+cos(phase/2+0.2t)+cos(0.5t))/3, 0)`; `height = decay*(1+0.8*sinStuff)` (noise 0.8, dogma 1687); yield = barWidth*height. Not monotone (cosine ripple). Test pins CCP's 14-day example: total 1,874,985; day 1 513,262; day 14 45,254.
- Whole cycles only: `floor((expiry-install)/cycle)`; a partial trailing cycle yields nothing. `sustainedRatePerHour` = program total / hours = the figure fed to chain cost and pin budgets (never `qty_per_cycle`, which overstates a 14-day program by ~150%, 2.5x). A program with no baseline (`qty`, `cycle_time`, `install_time` all finite) returns nothing, never a default.
- `yieldBankedBy`: cycle banks only on completion. `fractionOfPeak`: current cycle / first cycle (noisy; used for Reset now). `fractionOfFirstDayRate` (`:185`): trailing 24 h output / first 24 h; reports 1.0 until a full day has elapsed (else 4 h in reads 0.256, decay that has not happened). `pastEfficientWindow(threshold)` strict `<`.
- **Decayed flag**: threshold `EFFICIENT_WINDOW_FRACTION = 0.35` (`colonyStatus.ts:52`). A display judgement, not a game rule: CCP's example hits 0.38 on day 3, 0.30 on day 4; 3-day resets yield 2.46x a 14-day program over a fortnight; 14-day program banks 53% in first 3 days. Colony `decayed` only when EVERY projectable program is past it; programs without a baseline are skipped; none projectable = flag absent (not false).
- **Restart cadence** (`restartCadence.ts`): reprices a counterfactual program of exactly N hours off the same install baseline (never the real expiry). Documented as a FLOOR: EVE Uni reports longer programs also start lower per cycle (~30k vs ~20k at 1 h vs 24 h); no published formula so unmodelled (research doc section 4).
- **Reset now** (UI, `ColonyExpanded.tsx:37`): `(peak - peak*fractionOfPeak) * (86.4M ms / cycle_time)` units/day, floored at 0; no ISK on it by design.

### 7.2 Status and batches
- `extractorState`: expired when `now >= expiry`; expiring-soon when within the window (pilot's 1/6/12/24 h, default 24); else active. Colony `idle` if ANY program expired. Attention rank: idle 0, expiring-soon 1, decayed 2, healthy 3 (`colonyStatus.ts`). Colonies tab uses its own five-state `checkStatus` (`coloniesModel.ts:79`): stopped, expiring, needs-look (decayed OR fills before haul OR idle factories > 0), unknown (no detail or an extractor pin dropped for missing data), healthy. STATUS_RANK stopped 0 .. healthy 4 (unknown sits above healthy).
- `colonyBatches.ts`: Reset Run = colonies whose expiries are within `BATCH_WINDOW_MS = 90 min` of each other (`:34`); kinds expired / running / idle; row names the soonest deadline; a past deadline on an expired batch is a fact, not a schedule. Why generous: splitting one run in two is the failure that matters.

### 7.3 CPU / Powergrid budget (`pinBudget.ts`, `linkCost.ts`, `colonyBudget.ts`; ADR 0011; research doc)
- No pin-count cap: CPU and Powergrid are the two ceilings. Colony budget = row of `pi.infrastructure.commandCenterUpgrades` at the colony's own ESI `upgrade_level` (`colonyBudget.ts:52`, clamped 0..5); skill (Command Center Upgrades, type 2505) is only a ceiling for planets not yet built (`maxColonyBudget`; unread skill = level 0 with `assumed` flag). Reading the skill as the budget would overstate headroom of un-upgraded colonies, the direction the app must not err in.
- Table (CPU tf / PG MW): L0 1,675/6,000; L1 7,057/9,000; L2 12,136/12,000; L3 17,215/15,000; L4 21,315/17,000; L5 25,415/19,000 (`public/data/pi.json`). Only L0 is asserted against the SDE dump; L1-5 are hand-maintained from EVE University (`scripts/build-sde.mjs` `CC_UPGRADE_LEVELS`); L0 and L1 independently match ESI type data (types 2254, 2129). Command Center itself draws no CPU/PG.
- Pin costs from the SDE dump (CPU/PG): ECU 400/2,600; basic 200/800; advanced 500/700; high-tech 1,100/400; storage 500/700 (12,000 m3); launchpad 3,600/700 (10,000 m3); extractor head 110/550 each; max 10 heads per ECU (`EXTRACTOR_HEADS_MAX`, secondary source, used only as an upper bound).
- Links (`linkCost.ts`): per link `(15 + 0.2*km) CPU`, `(10 + 0.15*km) PG`, times `1.4^level` CPU / `1.2^level` PG (level modifier as a power is the natural reading but UNVERIFIED; all checked links were level 0). km = great-circle distance on the planet's own radius (ESI latitude is a polar angle 0..pi; cosine clamped before acos to avoid NaN). Radius is its own SDE payload (`pi-planet-radius.json`; 121 km to 159,270 km; one pilot saw 255 MW vs 1,708 MW for near-identical layouts). A new, unbuilt link is priced at the colony's LONGEST existing hop at level 0 (`newLinkLoad:130`; a floor on what fits, not a coin flip); null with no links or no radius. Planning charges one link per planned pin except the launchpad (a tree of N pins has N-1 links, `colonyCapacity.ts`).
- `fitColony` (`:352`): repeats a ratio block beside fixed overhead (launchpad/storage), reports which axis binds (`limitedBy`); empty `limitedBy` with 0 blocks means the overhead alone overruns (needs a higher CC level, not fewer factories). Throws on heads outside 0-10, non-finite or negative budget, empty block.
- `checkThroughput` (`:547`): second budget. Whole-colony flow vs ONE link's capacity and a buffer cycle vs launchpad + storage; deliberately over-reports pressure. Never uses `contents[].amount`. Needs positive block count (throws otherwise).
- Hours-to-full (`colonyThroughput.ts:248`): two chains per colony (sustained mean and each extractor's own peak) because a fresh program runs far above its mean; `fillsBeforeHaul(h, haulHours)` = `h !== null && h < haulHours` is the single gate every fill-time surface uses (`colonyStripModel.ts:108`).
- Unbuilt planets (`unbuiltPlanModel.ts`): assume 10 heads per ECU, overhead 1 launchpad + 0 storage, link = median of the pilot's own hops by CPU (middle element, not per-axis median), fallback link `{cpu 25, pg 18}` (~50 km) for rankings (`planAdviceModel.ts:138`). Statuses: advised / needs-pick / needs-measured-extraction / needs-link-cost / needs-skill (an assumed skill never drives advice).

### 7.4 Money
- `CUSTOMS_TAXABLE_VALUE` by tier P0..P4: 5 / 400 / 7,200 / 60,000 / 1,200,000 ISK per unit (`chain.ts:131`; NOT SDE basePrice; reproduced to the ISK by `chain.test.ts` against ticket #304 tables). Import taxed at 0.5x (`IMPORT_TAXABLE_FRACTION`). Default NPC rate 10% (`DEFAULT_CUSTOMS_TAX_RATE`). Customs are charged per PLANET boundary, not per tier: two tiers on one planet pay nothing between them; the host feeding itself pays nothing.
- Customs rate (`customsRate.ts:55`): highsec = 10% - 1 point per level of Customs Code Expertise (type 33467; 10% untrained, 5% at V); null skill reads as untrained (cannot understate). Outside highsec default 0 (player POCO; owner tax is not in ESI); vestigial NPC lowsec office at 17% is a manual override. Unresolved security = highsec. Wormhole reads as nullsec. Overrides per system, max 1.0.
- Sales tax = 7.5% x (1 - 11% x Accounting level) (`engine/industry/fees.ts:35`; 3.375% at V); `salesTaxRate.ts` loads the level, unknown skill treated as 0 (highest). Sale priced at the hub bid; no bid falls back to the ask (and is flagged `valuedAtAsk`); buyback pays the chosen % of that.
- **Baseline** (`baseline.ts:93`): for each colony every fitting extraction option (one P0 at 1 or 2 ECUs, or two P0s at one each) scored `sum p1PerHour*(bid*(1-salesTax) - taxRate*400)`; best wins; ties by sorted P1 ids then fewer ECUs. Any option's P1 unpriced => `needs-price` (never skip it: it may be best). No option fits => `nothing-fits`. Best <= 0 => ok with no slots and 0 (pilot would idle it).
- **Plan economics** (`planEconomics.ts:82`): per flow leg: leaving a colony pays export customs at that colony's rate x tier value; arriving at a colony pays import at host rate x value x 0.5; arriving at hub = sale at bid with sales tax; leaving hub = purchase at ask. `net = revenue - salesTax - buys - all customs`; `lift = net - Baseline` where Baseline sums ALL enabled colonies (a colony the plan ignores nets out). A goal bought outright loses spread + tax. Any missing bid/ask or Baseline price => `needs-price` with every missing type.
- Hauling: m3/week = units/h x volume x 168 over every leg between two places once (`goalPlanSteps/flows.ts`); effort = m3 x jumps per hour (`haulEffort.ts`). Ship hold approximations: Frigate 400, Industrial 5,000, Epithal 45,000 m3 (`planHaul.ts:30`; round figures, not a fit calc); industrial trips = ceil(m3/5,000), min 1. Route exposure counts lowsec/nullsec jumps; unknown route is null, never "0 lowsec".

### 7.5 Plan advice (Make more; `planAdvice.ts`, `planAdviceModel.ts`)
- One model feeds Plan, Map and Colonies. Wins add to today; a rebuild is quoted on top of today-after-quick-wins.
- Quick win kinds: restart (stopped, decayed), storage, idle-factories (remove, or add heads), spare-room extractors / factories. Estimated in-game minutes (`QUICK_WIN_MINUTES`, `planAdvice.ts:139`): restart `ceil(1+1*extractors)`; idle `ceil(2+0.5*pins+1 if heads to add)`; storage 3; extractors `ceil(2+2*extraEcus)`; factories `ceil(2+1*factories)`. Rebuild step minutes (`STEP_MINUTES`): upgrade 2, remove pin 0.25, place pin 0.5, set 0.5, route 0.5 (routes = one per production pin, an estimate: ESI does not say which pin feeds which).
- Ordering: ISK/minute desc; unpriced after every priced one; tie-break gain desc then id. A storage win is a SAVING: shown, minutes counted, ISK left out of totals (`isSaving`, `totalQuickWins`). `spendRoomOnce`: one colony's room (heads / extractors / local-factories / network-factories claims) is spent once; the claim adding the most ISK wins (a figure beats none); losing heads claims degrade to unpriced "remove idle factories".
- Storage win gain = `nominal * stall * 24` where `stall = 1 - max(0,hoursToFull)/haulHours` when `hoursToFull < haulHours` (`planAdviceModel.ts:641-644`). Decayed restart added only if the restart rate beats the current rate AND the program is past the 0.35 window.
- `pickRebuild` (`planAdvice.ts:488`): candidates are P1/P2 one-planet recipes with finite ISK > 0. Preference isk: sort ISK desc, tier asc, id. Preference haul ("Least hauling"): keep recipes earning >= 50% of the best (`LEAST_HAUL_MIN_SHARE`), sort by m3/day asc. Keep reasons: `already-best`, `gain-too-small`, `no-candidates`, `no-haul-saving`. Minimum gain: 5% of today (`REBUILD_MIN_GAIN_SHARE` = `NET_TOLERANCE`) and 100 ISK/h x 24 = 2,400 ISK/day (`REBUILD_MIN_GAIN_PER_DAY`). Alternative = best of the other preference, else next candidate.
- Recipe ranking assumes Command Center level 4 when the skill never loaded (`ASSUMED_RANKING_CC_LEVEL`, `planAdviceModel.ts:131`); fit of a ranked layout is ONE source (decision `20261006-085250`): "needs CC level N" tag, Show me how level line + meter, Map drawer note all read `RecipeLayout.fit`; heads stepped down per P2 until it fits.
- Planet slots = `1 + Interplanetary Consolidation level`, max 6 (`planetSlots.ts:43`, hand-maintained; unread skill = 1 slot with `assumed`). `slotNudge`: free = max(0, allowed - used).

### 7.6 Find best (`planRecipes.ts`, `planAdviceModel.ts` `rankingFor`)
- Recipe = a P1 or P2 one planet makes from its own ground (never raw P0, never P3+). Each recipe is scored per hosting planet type; the pilot's owned type when one hosts it, else best host. ISK/day is after customs and sales tax at the sell market.
- Verdict vs the best P1 the same planet type sells: better / same (within 5%, `NET_TOLERANCE`) / worse; the reference product itself is flagged `isReference`.
- Rank order: fits the pilot's CC first, then lowest needed CC level, then ISK desc, tier asc, type id (`byFitThenValue`). Unpriced recipes are dropped from ranking and counted. `bestAnywherePerDay` counts fitting rows only.
- Store: filter any/p1/p2 (`?fb.filter`), mode picks/all (`?fb.mode`); planet-type toggles and what-if chips are component state (lost on reload).

### 7.7 Chain estimates and whole-account plan
- `chainEstimate.ts`: capacity search over goal rate: start 0.25 units/day, double up to 20 times (`MAX_DOUBLINGS`) while `reachesInFull` (no shortfalls, every goal >= 1-1e-9), then 6 bisection steps (`BISECT_STEPS`); keeps the best rate reached (greedy solver is not monotone). Figure = plan `netPerHour` x 24 (absolute, not Lift: hypothetical colonies have no Baseline). Nothing bought unless `allowBuy`. Statuses: estimated / needs-price / no-plan. Chain-estimate UI cache size 4 (`useChainEstimates.ts:26`); what-if cache 4 (`useBiggerChains.ts:45`); 2 raws per planet assumed for a hypothetical planet (`RAWS_PER_PLANET`).
- `accountPlan.ts:201` (generator, yields after each solver search so UI can slice at 30 ms, `runSliced.ts`): stage 1 apart (each colony on its best pick), stage 2 buying (each colony may run any candidate from bought inputs; best of stage 1/2), stage 3 hauling (greedy rounds: candidate chain over free colonies; gain = what used colonies earn under it minus what they earned after stage 2; take the biggest positive gain, lock its colonies, repeat). A chain with non-positive gain is never taken. Candidates narrowed to 4 per tier (`CANDIDATES_PER_TIER`). Unknown colonies counted as 0, never guessed.

### 7.8 Other engine modules
- `stopTier.ts`: best tier for ONE planet; candidate = products whose whole P0 closure the planet yields (a P2 needing a P0 the planet cannot extract is never recommended); raw selling (tier 0) is itself a candidate; extra ECUs on the same P0 scaled by 0.8 (flat conservative placeholder, issue #957). Score is colony ISK/h = blocks x chain.targetPerHour x per-unit margin (forgetting `blocks` once reported one factory's earnings for twelve). No link charge in this module (caller passes an honest budget).
- `network.ts` (ADR 0012): colonies together; supply allocated greedily by ISK/h per factory until an input runs out (not provably optimal; an exact solve is a small LP, not worth a simplex); returns `unallocated`; margin from `chainCost` (P1 floor, single-planet) so customs stay in one place. P3+ not in it; Plan's Bigger chains cover those.
- `colonyCapacity.ts`: extraction slots = ECUs on one P0 + basics refining to P1 on the spot (one basic eats 6,000 P0/h: 3000 per 1800 s); raw P0 never leaves the colony; `runningToday` accepts what a colony already runs without a model check. `factoryBalance.ts`, `colonyEarnings.ts`, `extractionUpgrade.ts` (feed an idle factory vs remove, Powergrid fit), `nearestPlanetTypes.ts` (BFS over gates).

## Interview Q&A

1. **Why does the Goal Planner show a "Lift" not a profit?** P0 a colony extracts would otherwise be priced at zero, making any chain look fat when the same planet selling P1 already earned most of it. Lift = plan net minus Baseline (every enabled colony selling its best P1). A plan that only repackages the Baseline nets 0 by construction. `planEconomics.ts:82`, `baseline.ts:93`.
2. **How is "Baseline" computed and when is it 0?** Best fitting extraction option per colony scored `p1/h x (bid x (1 - salesTax) - taxRate x 400)`. If even the best nets <= 0 it is ok with no slots = 0 (never negative). An unpriced P1 in any option makes it `needs-price`, not a skipped option. `baseline.ts:93`.
3. **Why does the app not use `contents[].amount` for storage-full?** ESI only recalculates it when the colony is opened in game, so it can be arbitrarily old (ADR 0005). Fill time is derived from install-fixed fields: pin counts, static capacities, extractor decay curve. Two chains (mean and peak) because a fresh program runs far above its mean. `colonyThroughput.ts:248`.
4. **What exactly is the decay model?** CCP's `calculateExtractorValues`: per 900 s bar `qty/(1+0.012t)` times `1+0.8*max(mean of three cosines,0)`; whole cycles only. A 14-day program's last day is 8.8% of its first; `qty x cycles` overstates by ~150%. `extraction.ts:25-75`.
5. **What makes a colony "Slowed" / "Needs a look"?** Trailing-24h output under 35% of first-day output on EVERY projectable program (`colonyStatus.ts:52`); or storage fills before the pilot's haul cadence; or idle factories. Judgement threshold, not a game rule (day 3 of CCP's example = 0.38).
6. **Where does the colony's CPU/Powergrid budget come from, and why not the skill?** Its own `upgrade_level` indexes a 6-row table (`pi.json`, hand-maintained L1-5). The skill is only the ceiling, bought per colony in ISK; using it would overstate headroom for un-upgraded colonies. `colonyBudget.ts:52`, ADR 0011.
7. **How are links charged and why the longest hop for a new link?** `(15+0.2km, 10+0.15km)` at level 0 per link, km from pin lat/lon on the planet's own radius; a new link uses the colony's longest existing hop so "what fits" is a floor. `linkCost.ts:130`.
8. **How does the Goal Planner choose a factory host?** Solve once per eligible host; rank by goal attainment, fewer shortfalls, then (within 5% net, 100 ISK/h floor) fewer changed colonies, less hauling (known distances only), higher net, smaller Baseline forfeited, lower id. Goals first, ISK second. `planBest.ts:88`.
9. **Why is a Quick win's ISK missing for "storage"?** It is a saving (income lost to a full launchpad), shown but excluded from totals; minutes still count. `planAdvice.ts` `isSaving`, `totalQuickWins`.
10. **How do Plan, Map and Colonies stay consistent?** One `buildPlanAdvice` object; Colonies row actions are that advice's own quick wins; Map picks follow Plan's rebuild preference; a ranked layout's CC fit is a single source. Decisions `20261005-123211`, `20261006-085250`.
11. **Why can P3/P4 on Map show an estimate not a figure?** One-planet recipes are P1/P2 only. P3/P4 come from `estimateChain`'s capacity search over goal rate (0.25 doubling to 20 times, 6 bisections), net ISK/day, Est. badge, nothing bought. `chainEstimate.ts:63`.
12. **What does "Bigger chains" need?** Opt-in "I will haul between my planets" (`piSettings.haulBetweenPlanets`, off by default). Never enters a pick, quick win or total. Only chains that beat one-planet picks are lead rows. `BiggerChainsPanel.tsx`.
13. **How does the whole-account plan avoid recommending worse than today?** Three stages (apart, buying, hauling); a chain is taken only when its gain over what its colonies earned after the previous stage is positive; greedy, biggest gain first, colonies locked. `accountPlan.ts:201`.
14. **How are customs computed for a chain?** Per planet boundary: export `units x colonyRate x tierValue(5/400/7,200/60,000/1,200,000)`, import 0.5x on the receiving colony; same-planet hops free. Rate default 10% highsec minus 1 point per Customs Code Expertise level, 0 in player space. `chain.ts:131`, `customsRate.ts:55`.
15. **Why does Colony fit sometimes say "Fit as built"?** The colony runs this layout today but the model's pessimistic load exceeds the CC budget; the layout is not over budget. `ColonyFit.tsx:117`.
16. **Why does a whole colony row expand on click even though it holds links?** Recorded decision `20261006-093301`: row click expands; clicks on inner links/buttons keep their own action (`ColonyRowView.tsx`).
17. **What is a "Reset Run"?** Colonies whose expiries fall within 90 minutes of each other (one sitting); used by the Overview card so 18 colonies read as 3-4 trips. `colonyBatches.ts:34`.
18. **What is the default for planet slots when skills are unread?** 1 (`1 + level`), flagged `assumed`, so "free slots" is hedged. `planetSlots.ts:43`.

- `/planetary-industry/advisor` still has entries in `ROUTE_REQUIREMENTS`, `documentTitle.ts:48`, `routeChunks.ts:179` and `App.tsx:187` (retired-tab redirect kept alive).
- Storage-fullness and chain starvation are estimates only from install-fixed fields; ESI `contents[].amount` / `last_cycle_start` never used (ADR 0005/0011). Throughput check compares whole-colony flow to one link, over-reporting by design.
- Network engine (ADR 0012): greedy allocation (not provably optimal); P3+ out of scope for the Advisor-era engine; routes inside a colony are not modelled (`routes[]` read but unused). Bigger chains (Plan) cover P3/P4 only when the user opts in.
- CC upgrade table levels 1-5 are hand-maintained from EVE University, not derived from the SDE (`scripts/build-sde.mjs`, ADR 0011); research doc notes the per-level numbers are not in dogma.
- Hub prices only (Fuzzwork via `loadMarketSnapshot`, 15-min cache); an unpriced type is absent not zero; with prices down Plan shows only no-price Quick wins and Find best/Map show `PricesUnavailable` only.
- Customs: POCO owner tax not in ESI; player-owned space assumes 0%; unknown skill assumes 10% highsec base (`piShared.customsRateSource`); overrides per system only.
- Alt colonies are cache-only and can be days old; their figures are excluded from Plan totals and Today's check; their ISK is estimated with skills unknown, so priced cautiously (`pi.altColonies.notInPlanTooltip`).
- Sell market and cadence (`piSettings`, `cadencePref`) are device-local while customs overrides, richness and expiring window are synced (`syncedSettings.ts`); settings a user sets on one device do not follow them for sell hub, buy tiers, haul opt-in or cadence.
- Find best's planet-type toggles and what-if chips are local component state (not in URL), unlike filter/mode (`FindBestPlan.tsx:67-68`); reload resets them, and deep links cannot carry them.
- Extractor-expiring push is hedged and may fire for programs already restarted in game; occurrences are retracted only when a later poll sees the replacement (`disprovenExtractorOccurrences`).
- Customs override and richness picks have no bulk view; edited per colony in Goal Planner Colonies rail and Map drawer respectively.
- No CSV export on Map or Colonies (only Goal Planner Hauling/Flow).
- `EXTRACTOR_HEADS_MAX = 10` and the 12,000 / 10,000 m3 storage figures come from a secondary source / SDE dump; heads cap is an upper bound only.
- Goal Planner: `keep` verb ignores ECU counts (colony only compared by P0 set; `planDiff.ts` header), so "keep" can hide a needed ECU change.
- Goal Planner solver is greedy; a P1 rationed by a scarcer input is not reported as a gap (shown only as "held back" in Flow).
- Hub price fallback: a sale with no buy order is valued at the ask and only disclosed in a caveat line, which flatters Baseline and plan equally.
