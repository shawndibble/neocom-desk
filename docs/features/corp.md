Sub-nav is real routes (`src/features/corp/CorpSubNav.tsx`), each tab shown only if its Corp Capability is held. All four routes `UNGATED` in `src/app/routeScopes.ts:141-165` (the page gate is `useCorpRouteGate`, not a scope gate, so a non-Director is not offered a pointless re-login). `/corp` is not allowed in the phone tab bar (`mobileTab` false; nav hides rather than locks).

## Purpose and user goal

"Is anything in my corporation about to run out, come out, or go quiet?" Corp is for the few pilots who hold a Corp Role: the Overview is a widget grid whose default merges fuel, structure timers, moon extractions and finished jobs into one deadline-ranked Due soon widget ("the ranking is the feature", `20260903-155950`) with the money and people widgets after it, and the pilot rebuilds it (`20261020-201817`). Members, Wallet and Assets are the tables behind it. The grant banner shows only to role holders, to spare "the ~95% who hold no role" (Interview Q14).

- **Top jobs (ranked):** 1. "What corp deadline is next, and is any structure out of fuel?" (Due soon widget and its day bars) 2. "How much money does the corp have, and how long will it last?" (Corp wallet and Cash flow widgets; Wallet) 3. "Who has gone dark, joined or left?" (Members and Inactive members widgets; Members).
- **Device and cadence:** desktop primary, as for the whole app (owner, 2026-10-11; the owner has no Corp-specific answer). `/corp` is `mobileTab: false` and kept out of the phone rotation (`20260913-095527`), reachable from More. The `structureFuelLow` alert lands on `/corp`; member and wallet-threshold alerts land on Members and Wallet (`notificationOptions.ts`). ESI caches corp data about an hour, so short timers belong to notifications (`20260903-155950`).
- **Above the fold:** the default layout leads with Due soon (L), Structures and Moon extractions, then Corp industry jobs and Offline services, then the money and people widgets (`CORP_DEFAULT_KINDS`). Every default kind is in it; only those the Character's capabilities open are drawn. The pilot reorders, resizes, renames, removes and adds from the Gallery.
- **Not for:** live short timers (notifications); corp industry jobs (Industry Jobs panel, `20260929-102524`); corp contracts (no view exists).
- **Sources:** owner, 2026-10-11 (desktop primary, phone for one-off lookups); `20260903-155950`, `20260907-101244`, `20260903-224842-people-beside-money-on-the-corp-overview`, `20261010-162048`, `20260903-164718`, `20260929-131220`, `20260913-095527`, `20260903-121925`; #2857, #3123, #3142.
- **Unconfirmed:** desk-first use (the phone-bar exclusion is structural: a hidden route would leave a hole in the bar); that fuel/timers outrank money for most role holders; how often a manager opens it (daily vs on alert); whether Station Managers (no wallet role) need a different top.

### Mobbin brief

- **Fit:** medium. An ops dashboard of headline figures, a per-day load bar chart, grouped cards and a team roster are generic; structure fuel, reinforcement timers and moon chunks are EVE-specific.
- **Analog apps:** PagerDuty, Datadog, Linear, Gusto (team), Ramp (cash runway).
- **Screen queries:**
  - `web: operations dashboard with three headline metrics above a 14-day bar chart of upcoming deadlines colored by severity`
  - `web: grid of category cards each listing its three most urgent items with a countdown and a show-all link`
  - `web: team member table sorted by last active with an inactive filter and joined/left counts above`
  - `web: company cash panel with balance per account, net 30-day change and runway in days`
- **Flow queries:** none.
- **Mobbin won't help with:** Corp Role and scope gating, structure states and fuel semantics, moon extraction timing; reference the EVE client Structure Browser and corp management windows.

## 1. Overview (`/corp`)

A customizable widget grid on the Overview's engine (`docs/design/overview-widgets.md` section 13; decision `20261020-201817-corp-overview-is-a-widget-grid-the-pilot.md`). It replaces the fixed ops board (Standing, Deadline Strip, Kind Cards, Offline services, Money, People), which no longer exists. Terms: Corp overview, Corp overview layout, Widget board.

**Structure.** `Corp()` (`routes/Corp.tsx`) mounts behind `useCorpRouteGate`, then `CorpGridView` only once Corp Access is `ready`, so the first render already has the real capability set (a character switch returns to `unknown` and remounts). It provides `WidgetBoardContext` = `corpWidgetBoard(capabilities)` (`features/corp/grid/corpGrid.ts`: the board's kinds from `boardKinds('corp')`, groups `CORP_KIND_CATEGORIES` (clocks, money, people, industry, ops), `canDraw` = `kindOpenTo(kind, capabilities)`, `characterScope: false`, default layout), plus the shared `OverviewRefreshProvider`, `WidgetDataProvider`, `OverviewEditProvider`, `WidgetGrid`, `CustomizeBar`, `PhoneCustomizeList` and `Gallery`. Header: title, `CorpSubNav` (flush), data-age popover (with `corp.dataAgeNote`), Customize. No Next deadline button: it squeezed the tabs off the line, and Due soon names the next clock.

**Layout.** One per pilot: `useCorpOverviewLayout` (`sync.corpOverviewLayout`, `widgets/layoutStore.ts`), not per corporation or Character. No Role chooser, no first-run prompt. Until the pilot edits, the page draws `corpDefaultLayout()` (every default kind) and never saves it. It draws at once; a first edit is held in memory until this device's first sync pull has landed (`useFirstRunReady` with the corp key), and a synced layout arriving meanwhile wins. Never trimmed to one Character's roles, so an alt's edit cannot drop a Director main's widgets. Default order (`CORP_DEFAULT_KINDS`): Due soon, Structures, Moon extractions, Corp industry jobs, Offline services, Corp wallet, Cash flow, Members, Inactive members, Income by source, Moon mining ledger; kinds the Character cannot read are kept but not drawn.

**Hide, don't lock.** A kind whose capability the Character lacks is never offered in the Gallery, drawn or fetched; one already saved stays in the layout, undrawn (it returns if the role does). Kinds with several capabilities open on any one. Coming-soon kinds are listed for everyone, not addable. A Station Manager who is not an Accountant gets clocks and no wallet widgets, with no error. No Character scope menu (corp data belongs to one corporation).

**Reads.** Feeds are in `widgets/data/corpFeeds.ts` (shapes, thin `import()` loaders so the Overview's first paint does not carry corp code) and `corpFeedLoaders.ts` (the real work). Each loader calls `resolveCorpReadAccess` and checks the capability before it fetches, so an unheld read costs no request and no 403. Three answers stay distinct, and builders keep them apart: `readable: false` (no role, or a lapsed grant when `needsReauth`: the widget asks for Grant access or says the roles do not cover it; no request made), a thrown `CorpReadFailed` (allowed and failed: Retry), and data, possibly empty (read fine: the empty message). Structures and Moon extractions reuse the Overview's own feeds (`boardData.ts`). Wallet feed: balances, divisions, master-division journal; Jobs feed; Members feed (members, tracking, roster diff against the stored baseline, names); Mining feed (observers and their ledgers).

**Corp widget kinds** (`kinds.ts` specs; builders in `widgets/data/corpClockModels.ts`, `corpMoneyModels.ts`, `corpPeopleModels.ts`, registered in `corpModels.ts`). Views: N Number, C Chart, T Table. Default view and size first.

## Interview Q&A

1. Why does the Corporation nav entry disappear instead of showing a lock? Because a lock implies the user can unlock it; a corp role is changed in-game, and a re-auth cannot fix a server-side 403. `useCorpNavVisible` requires `ready` plus a known corporation id (`features/corp/useCorpNavVisible.ts`); routes are `UNGATED` (`src/app/routeScopes.ts:141`) so a non-Director is never offered a pointless re-login. Decision `20260903-121925`. `unknown` also renders nothing so the item never flickers in.
2. What are the two access axes and how do they compose? Granted scopes (JWT, offline) and in-game roles (ESI `GET /characters/{id}/roles`). `useCorpAccess` (`features/corp/useCorpAccess.ts:75`) returns `unknown | not-granted | none | roles-without-grant | ready`. Roles -> capability in `engine/corpRoles.ts:139` (Director satisfies all); capability -> scopes in `corpScopes.ts:44`; `missingCorpScopes` is computed only for held capabilities, so a Factory_Manager is not asked for wallet scopes.
3. Why is the roles read skipped when the roles scope is missing, and what if it fails? Without the scope it is a guaranteed 403 (`useCorpAccess.ts:~90`), so state is `not-granted` with no call. If the read fails, state stays `unknown` rather than `none`: `none` is a claim, and a Director cold-starting offline must not be pinned to `none` (test `useCorpAccess.test.ts:148,156`).
4. How is runway computed and why is it only division 1? `runway = balance(div1) / (abs(sum of negative journal amounts over 30 days) / 30)`, null if nothing spent or balance <= 0 (`engine/corp/vitals.ts:73-94`). ESI has no all-division journal and each division is separately role-gated, so mixing all balances over one division's spend would overstate runway (`vitals.ts:124` comment). Income is excluded so one big sale does not hide a burn rate.
5. Why "Under 1h" rather than a countdown? CCP caches corp endpoints ~1 h; a 12-minute timer from an hour-old read is not trustworthy. `withinStaleWindow = 0 < remaining < 3,600,000` (`board.ts:207`); the corp builders show the label plus a pointer to the game client (`corpClockModels.ts`), and the data-age popover states the hourly cache (`corp.dataAgeNote`). Short alerts belong to the notification feed.
6. What does an absent `fuel_expires` mean? Already dry: ESI drops the field when a structure is out of fuel, so the board makes it `passed`/critical and sorts it above every dated clock (`board.ts:213-221,352`). Treating it as "no data" would hide the worst case.
7. How does the app decide a corp job is ready for pickup? Status `ready`, or `active` with `end_date` passed; any terminal status (delivered/cancelled/paused/reverted) never counts (`board.ts:381`). ESI leaves finished jobs `active` for days; decision `20260910-175421`. Consequence: a new ESI status needs an explicit decision.
8. How is a "dark" member defined and why are never-logged-in members dark? `now - max(logon, logoff)` >= threshold days (14/30/60/90, default 30, synced); a never-logged-in member is measured from join date so a recruit who never played still surfaces (`members.ts:115`, decision `20260903-164718`). The table says "Never" for them rather than a bogus span.
9. How do roster joined/left announcements work without double-reporting? A per-Character/corporation baseline (`corp.rosterBaseline`) is read and replaced by Members in one pass; the Members widget feed only reads it (`corpFeedLoaders.ts`), so whichever page opens first does not eat the change. Baseline is not replaced when the id list is unreadable or the run was cancelled (`CorpMembers.tsx:~165`). No baseline (first visit, new device, corporation change) yields no summary (`diffRoster`, `members.ts:155`).
10. Why did the Overview change from Kind Cards + Deadline Strip to a widget grid? The fixed board suited one role mix; a Station Manager, an Accountant and a CEO want different things first. Same engine as the Overview means one customize grammar, and the Deadline Strip lives on as the Due soon chart (`20260907-101244` for why per-day counting matters; `20261020-201817` for the grid). Local days because managers plan by weekday; round-not-floor handles DST (`deadlines.ts`).
11. How are corp assets organised and why not reuse `/assets` directly? Division-first tree (`engine/corp/assetDivisions.ts`): seven hangars always shown; office folders are pass-throughs re-homing contents into their hangar under a station node; unknown flags -> Other. Hangars have no `item_id` to key a URL on, so groups use a path head of `1..7` or a flag name (`assetPath.ts`). Reuses `assetTree` and row components; deliberately omits cross-character merge, pinning, jump badges. Cap: 25 pages (~25,000 assets) then `truncated` banner.
12. What happens on a 403 from a corp endpoint? It is the role gate, not an auth problem: `detectCorpAuthFailure` excludes 403 (`corpAuthFailure.ts:26`) so no "log in again" notice appears; the panel shows the cached/empty/failed state (test `CorpWallet.test.tsx:364`).
13. What persists and what syncs for Corp? Only the dark threshold (`sync.corpDarkAfterDays`) syncs; ESI data, roster baseline, grant dismissals and column choices are device-local; filters/sort/division/view live in the URL (ADR 0015).
14. How does the one-time corp grant banner avoid nagging? Dismissal stores the scope set offered per Character; dismissed only if what was offered then covers what is on offer now (superset check), so a widened group re-offers (`grantPromptDismissal.ts:~55`); pressing Grant also records dismissal (a cancelled SSO trip is not a new occasion); it shows only for `roles-without-grant` (not `not-granted`, to avoid showing it to the ~95% who hold no role).

## Observed gaps

- Due soon, Structures and the jobs widgets are tables inside widget size limits; a long structure list scrolls or truncates by size, and there is still no structure detail page (services, location, fuel quantity).
- Board gives no notification bridge: short clocks are explicitly deferred to notifications, but the foreground poller runs every 5 min (`foregroundPoller.ts:59`) while the decision text cites a ten-minute cadence; corp events are best-effort, no server push (Notifications panel disclosure).

- Corp Assets CSV is whole-corporation (group label, item, quantity), not the current view, with no ISK value or location column; no ISK sort/filter or totals beyond per-row estimates; no offline/refresh-failed banner (wallet panels have one).
