# Corp

Corporation section. Four routes under one nav entry (`src/app/navDestinations.ts:133`, `gating: 'corp'`: hidden, never locked). Sub-nav is real routes (`src/features/corp/CorpSubNav.tsx`), each tab shown only if its Corp Capability is held. All four routes `UNGATED` in `src/app/routeScopes.ts:141-165` (the page gate is `useCorpRouteGate`, not a scope gate, so a non-Director is not offered a pointless re-login). `/corp` is not allowed in the phone tab bar (`mobileTab` false; nav hides rather than locks).

Terms per `CONTEXT.md`: Corp Access, Corp Capability, Corp Role, Corp Board Item, Kind Card, Deadline Strip, Board Severity, Permission, Core Grant. (CONTEXT's Corp Capability entry lists four capabilities; code has seven, see gaps.)

## 1. Overview (`/corp`)

`Corp()` -> `CorpBoardView` (`routes/Corp.tsx:330`). Loader `loadCorpSnapshot` runs `useRouteSnapshot` with `staleWhileRevalidate` and `cacheKey: 'corp'` (board stays on screen during refresh). Each read fires only for the capability that opens it, so an unheld one costs no request and no 403. An unreadable source is `null` (renders nothing) versus `[]` (read fine, empty state): a Station Manager never sees "No industry jobs".

Header: title, `CorpSubNav` (flush, same line), `DataAgeBadge` (oldest `fetchedAt` across the panels actually read), Refresh `IconButton` (disabled while loading).

ESI reads by capability: structures `GET /corporations/{id}/structures`; moon extractions `GET /corporation/{id}/mining/extractions` (singular path, CCP quirk); industry jobs `GET /corporations/{id}/industry/jobs`; wallet: `/wallets`, `/divisions`, `/wallets/1/journal` (master division only, `MASTER_WALLET_DIVISION`); members: `/members`, `/membertracking`. Names: SDE type names then ESI; `POST /universe/names` for at most 9 People-panel ids.

## Formulas, thresholds and edge cases (engine)

All pure, `nowMs` is a parameter (never `Date.now()` inside `src/engine`).

| Rule                       | Exact behavior                                                                                                                                                                                                                                                                                                                                                      | Source                                                     |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| Severity ladder            | remaining <= 24 h critical; <= 3 d warning (UI "Due soon"); <= 7 d watch ("Worth watching"); else clear ("Not urgent"). `remaining === null` (no clock) = warning. Overdue (negative) stays critical; remaining is stored unclamped so overdue items keep relative order                                                                                            | `engine/severity.ts:68-73`, `engine/corp/board.ts:193-221` |
| Fuel                       | `fuel_expires` absent = `timing: 'passed'`, severity critical, sort key -Infinity (above every live clock). ESI drops the field once a structure runs dry, so absent means dry, not "unknown"                                                                                                                                                                       | `board.ts:213-221`, `board.ts:352`                         |
| Structure timer            | `state_timer_end` present -> item `structureTimer` with detail = state (`structureStateLabel` replaces `_` with space); `unanchors_at` present -> separate `structureTimer` item "unanchoring". Both can exist for one structure. No timer fields -> nothing                                                                                                        | `board.ts` `structureItems`                                |
| Offline service            | only `state === 'offline'` services raise an item; `cleanup` (transient) is ignored. `untimed`, severity warning, sort key +Infinity                                                                                                                                                                                                                                | `board.ts` `structureItems`, test `board.test.ts:153,175`  |
| Moon extraction            | before `chunk_arrival_time`: deadline = arrival, detail "arrival" (ready to fracture). After arrival: deadline = `natural_decay_time`, detail "decay". Rows missing either timestamp are dropped (`toBoardExtractions`). Subject = structure name from the structures read, else `Moon <moon_id>`                                                                   | `board.ts:303`, `boardSources.ts`                          |
| Job delivery               | status `ready` always counts. Status `active` counts only once `end_date` has passed (ESI leaves finished jobs `active`). Any other status (delivered/cancelled/paused/reverted) never counts. A job with unparsable `end_date` is dropped. Subject = product name else blueprint name else `#jobId`; row links Show info on product type id else blueprint type id | `board.ts:381`, decision `20260910-175421`                 |
| Short-clock refusal        | `withinStaleWindow = remaining > 0 && remaining < 3,600,000 ms` (`CORP_CACHE_WINDOW_MS`, `routes/Corp.tsx:114`). The row prints "Under 1h" + tooltip instead of a countdown. Overdue and untimed/passed rows are never doubted                                                                                                                                      | `board.ts:207`, `CorpBoardRow.tsx` `Countdown`             |
| Board order                | primary: deadline (passed first, untimed last); tie 1: kind rank `structureTimer < structureFuel < moonExtraction < jobDelivery < serviceOffline`; tie 2: id string compare. Deterministic whichever order sources arrive; NaN guard for two untimed items                                                                                                          | `board.ts:352-366,393-398`, tests `board.test.ts:401,416`  |
| Day bucket                 | local calendar days, `localMidnight` + `round((midnight(deadline) - day0) / 86,400,000)` (round, not floor, for 23/25 h DST days). Index < 0 (overdue) -> day 0; index >= days -> excluded; passed -> day 0; untimed -> none. Day labels built by local-calendar arithmetic so DST cannot shift them. Day severity = worst severity landing there                   | `deadlines.ts:78-125`                                      |
| Strip width                | 14 days (`DEADLINE_STRIP_DAYS`); phone shows first 7 (`NARROW_DAYS`, `useIsNarrow`). Bar height = count / busiest * 100%, minimum 12%                                                                                                                                                                                                                               | `CorpDeadlineStrip.tsx:51,54`                              |
| Due soon                   | counts timed items with `deadline - now <= 86,400,000` (edge inclusive), plus all `passed`; `overdue` = passed or `deadline <= now`; untimed excluded. Note: an item exactly 24 h out is counted in Due soon                                                                                                                                                        | `deadlines.ts:138-160`, test `deadlines.test.ts:216`       |
| Kind cards                 | top 3 per kind (`ROWS_PER_CARD`), footer "N more", header "N critical". Card set = capabilities held: Fuel + Timers (structures), Moons, Jobs. ## Interview Q&A

1. Why does the Corporation nav entry disappear instead of showing a lock? Because a lock implies the user can unlock it; a corp role is changed in-game, and a re-auth cannot fix a server-side 403. `useCorpNavVisible` requires `ready` plus a known corporation id (`features/corp/useCorpNavVisible.ts`); routes are `UNGATED` (`src/app/routeScopes.ts:141`) so a non-Director is never offered a pointless re-login. Decision `20260903-121925`. `unknown` also renders nothing so the item never flickers in.
2. What are the two access axes and how do they compose? Granted scopes (JWT, offline) and in-game roles (ESI `GET /characters/{id}/roles`). `useCorpAccess` (`features/corp/useCorpAccess.ts:75`) returns `unknown | not-granted | none | roles-without-grant | ready`. Roles -> capability in `engine/corpRoles.ts:139` (Director satisfies all); capability -> scopes in `corpScopes.ts:44`; `missingCorpScopes` is computed only for held capabilities, so a Factory_Manager is not asked for wallet scopes.
3. Why is the roles read skipped when the roles scope is missing, and what if it fails? Without the scope it is a guaranteed 403 (`useCorpAccess.ts:~90`), so state is `not-granted` with no call. If the read fails, state stays `unknown` rather than `none`: `none` is a claim, and a Director cold-starting offline must not be pinned to `none` (test `useCorpAccess.test.ts:148,156`).
4. How is runway computed and why is it only division 1? `runway = balance(div1) / (abs(sum of negative journal amounts over 30 days) / 30)`, null if nothing spent or balance <= 0 (`engine/corp/vitals.ts:73-94`). ESI has no all-division journal and each division is separately role-gated, so mixing all balances over one division's spend would overstate runway (`vitals.ts:124` comment). Income is excluded so one big sale does not hide a burn rate.
5. Why "Under 1h" rather than a countdown? CCP caches corp endpoints ~1 h; a 12-minute timer from an hour-old read is not trustworthy. `withinStaleWindow = 0 < remaining < 3,600,000` (`board.ts:207`); the row shows the label plus tooltip pointing at the game client (`CorpBoardRow.tsx`), and the data-age badge states the hourly cache (`corp.dataAgeNote`). Short alerts belong to the notification feed.
6. What does an absent `fuel_expires` mean? Already dry: ESI drops the field when a structure is out of fuel, so the board makes it `passed`/critical and sorts it above every dated clock (`board.ts:213-221,352`). Treating it as "no data" would hide the worst case.
7. How does the app decide a corp job is ready for pickup? Status `ready`, or `active` with `end_date` passed; any terminal status (delivered/cancelled/paused/reverted) never counts (`board.ts:381`). ESI leaves finished jobs `active` for days; decision `20260910-175421`. Consequence: a new ESI status needs an explicit decision.
8. How is a "dark" member defined and why are never-logged-in members dark? `now - max(logon, logoff)` >= threshold days (14/30/60/90, default 30, synced); a never-logged-in member is measured from join date so a recruit who never played still surfaces (`members.ts:115`, decision `20260903-164718`). The table says "Never" for them rather than a bogus span.
9. How do roster joined/left announcements work without double-reporting? A per-Character/corporation baseline (`corp.rosterBaseline`) is read and replaced by Members in one pass; the Overview only reads it (`routes/Corp.tsx` loader comment), so whichever page opens first does not eat the change. Baseline is not replaced when the id list is unreadable or the run was cancelled (`CorpMembers.tsx:~165`). No baseline (first visit, new device, corporation change) yields no summary (`diffRoster`, `members.ts:155`).
10. Why did the Overview change from one merged list to Kind Cards + Deadline Strip? The merged list answered "what is next" but not "what is my fuel situation". Cards group by kind (filter, never re-sort); the strip restores the cross-kind "bad Tuesday" view by counting per local day, coloured by worst severity (`20260907-101244`). Local days because managers plan by weekday; round-not-floor handles DST (`deadlines.ts:78`).
11. How are corp assets organised and why not reuse `/assets` directly? Division-first tree (`engine/corp/assetDivisions.ts`): seven hangars always shown; office folders are pass-throughs re-homing contents into their hangar under a station node; unknown flags -> Other. Hangars have no `item_id` to key a URL on, so groups use a path head of `1..7` or a flag name (`assetPath.ts`). Reuses `assetTree` and row components; deliberately omits cross-character merge, pinning, jump badges. Cap: 25 pages (~25,000 assets) then `truncated` banner.
12. What happens on a 403 from a corp endpoint? It is the role gate, not an auth problem: `detectCorpAuthFailure` excludes 403 (`corpAuthFailure.ts:26`) so no "log in again" notice appears; the panel shows the cached/empty/failed state (test `CorpWallet.test.tsx:364`).
13. What persists and what syncs for Corp? Only the dark threshold (`sync.corpDarkAfterDays`) syncs; ESI data, roster baseline, grant dismissals and column choices are device-local; filters/sort/division/view live in the URL (ADR 0015).
14. How does the one-time corp grant banner avoid nagging? Dismissal stores the scope set offered per Character; dismissed only if what was offered then covers what is on offer now (superset check), so a widened group re-offers (`grantPromptDismissal.ts:~55`); pressing Grant also records dismissal (a cancelled SSO trip is not a new occasion); it shows only for `roles-without-grant` (not `not-granted`, to avoid showing it to the ~95% who hold no role).

## Observed gaps

- Kind cards' "N more" is a plain line (`CorpKindCards.tsx:121-127`), not a control: rows past the top 3 are unreachable (#2857).
- No structures page: fuel/timers/moons/jobs/offline services exist only as Overview board items (top 3 per kind, remainder counted "N more"); no all-rows view, no sort/filter, no structure detail (services, location, fuel quantity).
