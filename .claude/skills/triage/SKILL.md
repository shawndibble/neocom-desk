# Triage

Move issues on the project issue tracker (GitHub Issues — see `docs/agents/issue-tracker.md`) through a small state machine of triage roles.

Every comment posted to the tracker during triage **must** start with:

```
> *This was generated by AI during triage.*
```

## Reference docs

- [AGENT-BRIEF.md](AGENT-BRIEF.md): how to write durable agent briefs
- [OUT-OF-SCOPE.md](OUT-OF-SCOPE.md): how the `.out-of-scope/` knowledge base works

## Roles

Two **category** roles: `bug`, `enhancement`.

Five **state** roles (label string == role name, see `docs/agents/triage-labels.md`):

- `needs-triage`: maintainer needs to evaluate
- `needs-info`: waiting on reporter for more information
- `ready-for-agent`: fully specified, ready for an AFK agent
- `ready-for-human`: needs human implementation
- `wontfix`: will not be actioned

Every triaged issue should carry exactly one category role and one state role.

## Invocation

The maintainer invokes `/triage` and describes what they want in natural language: "show me anything that needs attention", "let's look at #42", "move #42 to ready-for-agent", "what's ready for agents to pick up?".

## Show what needs attention

Query the tracker and present three buckets, oldest first: (1) unlabeled, (2) `needs-triage`, (3) `needs-info` with reporter activity since the last triage notes. Show counts and a one-line summary per item.

## Triage a specific issue

1. **Gather context.** Read the full issue (body, comments, labels, author, dates). Parse prior triage notes so you don't re-ask resolved questions. Explore the codebase using the domain glossary in `CONTEXT.md`, respecting `docs/adr/`. Run two checks: (a) **redundancy** — search for an existing implementation of the requested behavior by domain concept, and report where you looked; if found, it's an already-implemented `wontfix`. (b) **prior rejection** — read `.out-of-scope/*.md` and grep `docs/context/decisions/` (past scope decisions are where most rejections actually live, and a later one can reverse an earlier one — check dates), and surface any that resembles this request.
2. **Recommend.** State your category and state recommendation with reasoning, plus a brief codebase summary. Wait for direction.
3. **Verify the claim.** For a bug, reproduce it from the reporter's steps. Report: confirmed (with code path), failed, or insufficient detail (a strong `needs-info` signal).
4. **Grill (if needed).** If the request needs fleshing out, call the Skill tool for "grilling" and "domain-modeling" and grill it into shape a round of questions at a time.
5. **Apply the outcome:**
   - `ready-for-agent`: post an agent brief comment ([AGENT-BRIEF.md](AGENT-BRIEF.md)).
   - `ready-for-human`: same structure, note why it can't be delegated.
   - `needs-info`: post triage notes (template below).
   - `wontfix`: close, with the comment depending on _why_ — already implemented (point to where it lives; do **not** write to `.out-of-scope/`); rejected bug (polite explanation, close); rejected enhancement (write to `.out-of-scope/`, link from a comment, close).
   - `needs-triage`: apply the role.

## Quick state override

If told "move #42 to ready-for-agent", trust it and apply the role directly. Confirm what you're about to do, then act. Skip grilling.

## Revalidation mode (called from /next-ticket)

When `/next-ticket` calls `/triage <n>` on a ticket that is **already** `ready-for-agent`, there is no human in the loop. Do only the non-interactive parts:

1. Read the issue in full, including comments and any agent brief.
2. Run the **redundancy check** — is this already implemented on `main`? If yes: comment (with the disclaimer) pointing to where it lives, apply `wontfix`, close, `gh issue edit <n> --remove-assignee @me`, and tell `/next-ticket` to stop (pick nothing else this run).
3. Run the **prior-rejection check** against `.out-of-scope/*.md`. On a clear match: comment, apply `wontfix`, close, unassign, stop.
4. Check the ticket is still coherent against the current codebase (referenced modules/behaviour still exist in some form; `## Blocked by` refs are all closed). If it needs decisions a human must make (grilling territory), comment saying so with the disclaimer, apply `needs-info` or `ready-for-human` as appropriate, `--remove-assignee @me`, and tell `/next-ticket` to stop.
5. Otherwise: proceed. Optionally post a one-line "revalidated, proceeding to implementation" comment (with the disclaimer).

Never invent answers to grilling questions in this mode. If a human is needed, hand it back.
