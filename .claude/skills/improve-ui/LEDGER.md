## Contract already enforced

UI rules proved by a spec or a shared primitive, so no run re-discovers them.

- Page width: every single-column route is `mx-auto max-w-6xl` (Industry `max-w-7xl`), decided in `20260901-172427-app-wide-page-width`. `/fittings` is the deliberate exception: it has no cap because the editor goes three columns at 100rem.

## Standing kill-tests

Reusable heuristics learned from runs, beyond RUBRIC.md's own. A new one earns
its place by killing a whole class of finding.

- **A width-mismatched page that shares a route with a wide editor.** Fittings start screen vs its siblings' `max-w-6xl` is the editor's width, not drift. Drop unless the start screen itself misbehaves.
- **Mock artefacts.** An `Unknown 90000001` issuer or a blank status in a screenshot comes from the e2e mock (missing names, non-ESI status values), not the app.

## Killed findings

What was killed, and why. This is what stops a re-pitch.

- Skills trained per-group SP subtotal in the header: no named user cost; Total SP chip already answers "how much SP".
- Fittings start page wider than sibling routes (no `max-w-6xl`): shares its container with the wide editor.
- Contracts History: nothing survived (Expires column shows absolute dates only, but Calendar already carries contract expiries).
- Fittings start list has no Saved/In-game filter or sort: the decision file rejected a sortable table, and search covers it.
- Overview `SummaryStrip` labels ragged because the row is `items-center` (2px in the empty state): killed, populated drift unmeasured and the deadline hero is deliberately larger than its neighbours. Re-open only with a populated screenshot showing visible misalignment.
- Industry `max-w-7xl` vs siblings' `max-w-6xl`, and the wide gap between plan name and columns: deliberate (#534, side-by-side ledger).
- Assets Sort and Route selects show only their value ('Name', 'Shortest'): the Select-with-aria-label pattern is deliberate and the values are self-describing. Only a `title` tooltip on Route would survive.
- Characters card's always-visible red remove button beside the star: removal confirms in a dialog, so no real misclick cost.
- Alerts feed-off banner has no link to Settings: the gear button sits in the same header.
- Characters table wrapped in a `Panel` to fix the pinned-column fill: group sections and card view are bare, so a Panel per group costs density. Narrowed to fixing the fill (#2076).
- Characters row menu given a visible More-actions button on its own: `CharacterRowContextMenu` is deliberately bare (#2059 out of scope) while it only holds nav shortcuts. Only reopens with group/remove actions (#2077).
- Characters density select as a misplaced global setting: its header comment says it is the shared text-size control on purpose.
- Calendar Coming Up long title ellipsizing at 1024: the event modal is one click away, no named cost.
- Ships Tree default zoom making labels tiny: documented game-art exception, `Aa` control exists.
- Mail reading pane's message body has no max-width, leaving a wide empty gutter beside a short mail at 1440: no named cost beyond taste, and constraining it would trade density for optical readability against DESIGN.md's own opening rule.
- Skill Plans list has no search/sort control: plan counts stay small (a CRUD list someone builds, not a data feed), unlike Assets/Contracts where row counts are large; no sibling comparison argues a real gap.
- Mining Tax ledger overflow: a scroll-edge shadow/fade affordance on the table's `overflow-x-auto` wrapper was narrowed out — `Tabs`, the app's only sideways-scroll precedent, has no such affordance to reuse, and truncating the Payee column (#2147) is expected to remove the overflow on its own.
- Mail bulk "mark all read": issue #741's own decision file explicitly rules out "broader mail actions (delete/label/reply)" beyond the one per-mail read write; a bulk action is the same shape.
- Mail CSV export: shipped once (#91), then explicitly removed in the two-pane rebuild (`20260901-172427-mail-page-rebuild.md`) — tab-filtered buckets make "export what I'm looking at" ambiguous, so the decision drops the feature rather than re-scope it. Not a regression.

## Tooling notes

- A fittings ESI route regex must allow the missing `/latest` prefix: `esi\.evetech\.net\/(.*\/)?characters\/\d+\/fittings`. `.*\/characters` needs two slashes and matches nothing, so the page silently shows the empty state.
- Populated preview needs the mocked `/universe/types/{id}` route from `e2e/fittingsLoadNarrow.spec.ts`.
- Seeding Dexie rows (a build plan, a production run) works as in `e2e/industryRecordsNarrow.spec.ts`; call `signInAndGoto` once per test, a second seed hits a `VersionError`. Routes are lazy: wait for `main h1` before screenshotting or the page is blank.
- `npm ci` from Git Bash can leave `node_modules/.bin` missing; rerun it from PowerShell.
- Market's order book needs both `esi.evetech.net/markets/*/orders*` and `.../history*` routed (empty `[]` is enough for History); seed the `#/market?section=browser` search box and click the best-match result to open an item's detail pane.
- Seeding extra skill plans/entries through the UI (New plan, skill search, level buttons) is simpler than raw IndexedDB when the entries need to render through the live plan-editor queue math (training time, projected finish).
- Mining Tax's ledger populates from raw IndexedDB the same way `e2e/miningTaxNarrow.spec.ts` does (an `esiCache` row keyed `miningTax:ledger`, plus `payees`/`miningTaxAssignments` rows) — but Mining **Overview** reads a different, live endpoint (`characters/{id}/mining/`, mocked empty by `mockEsi.ts`'s `PREFETCHED_EMPTY` set) and does not share that cache key, so seeding the ledger alone does not populate Overview; overriding the route directly got the page as far as a stuck loading spinner with no chrome, not investigated further.
- Contacts populates via `page.route` on `characters/{id}/contacts` and `.../contacts/labels`; the Across tab needs a second Character seeded into the `characters`/`esiCache` stores directly, matching `e2e/contactsNarrow.spec.ts`.
- A Build Plan seeded straight into the `buildPlans` IndexedDB store (no `productionRuns` needed) is enough to reach `/industry/plans/:id`'s full Materials/Costs & Revenue layout — no ESI mocks required, but with no price mocks every verdict/profitability figure reads "no price data" (code-read only for those).
- Noticed but not pursued this run: `BuildPlanDetail`'s verdict header logs a real-browser console warning ("`<h2>` cannot be a descendant of `<p>`") from a `ContextMenuTrigger`-wrapped heading — worth a look on a future Industry re-audit.
- A Build Group renders straight off IndexedDB: put member `buildPlans` rows with a shared `buildGroupId`, plus a `settings` row keyed `sync.industryBuildGroups` valued `{ [characterId]: [{ id, name, order }] }` (`db.settings.put`, raw object — no JSON.stringify). No ESI or price mocks needed to reach the full Members/Materials layout; with no Fuzzwork mock every plan reads "couldn't be priced" (code-read only for those figures).
- PI Colonies populates from the same fixture `piAdvisor.spec.ts` already built for the Advisor tab (`COLONIES`/`COLONY_DETAIL`/`STORAGE_COLONY_DETAIL`/`SYSTEM`/`PLANETS`, routed over `esi.evetech.net/**` plus a Fuzzwork price stub) — it works unchanged for the Colonies tab too, and needs `clearEsiCache` before navigating since the shared fixture pre-warms an empty `/planets` answer at boot.
- Loyalty Store populates by overriding `characters/{id}/loyalty/points` and `/loyalty/stores/{corp}/offers/` (both otherwise answered empty by the shared fixture); offer `type_id`s not in `UNIVERSE_TYPES`/Fuzzwork's mocked set read "no price data" for Profit/ISK-per-LP, same caveat as Build Plan detail.
- Corp Members has no known populated e2e fixture yet: it needs a mocked corp id, `/corporations/{id}/membertracking/`, `/corporations/{id}/roles/` and enough `Director` role wiring to clear `useCorpRouteGate`'s `canReadMembers` check before the roster renders past its empty state — worth building on a future run so this page stops being code-read only.
