## What changed

The Fitting editor's Save button only ever overwrote the open My Fittings record — no way to keep the saved original and try a variant. Its caret menu now offers **"Save as new…"** (shown once there's an original to keep, i.e. `updating`), prefilled with `"<original name> copy"`, which inserts a **second** My Fittings record and leaves the one the Fitting was opened from untouched. The header's **Compare** action now opens Fitting Compare with the saved version and the current in-progress edit side by side whenever there are unsaved edits against a saved record, instead of just the one code already in the URL.

- `useFittingWorkspace.ts`: new `saveAsNew(name)` — always inserts, never updates; syncs the on-screen Fitting's name to the new record afterward (same as a first-time Save).
- `FittingSaveButton.tsx`: new "Save as new…" caret item, gated on `updating`.
- `routes/Fittings.tsx`: "Save as new…" name-prompt dialog; Compare now compares the saved record's code against the current `?f=` code when they differ.
- New i18n strings in `en.json`.

## Review notes

Ran this through `/code-review`'s three axes (Standards/Spec/Quality) as parallel sub-agents. Fixed:

- On-screen title didn't sync to the new record after "Save as new…" — now does, via a local (no-history) rename.
- Whitespace-only name + Enter key silently no-op'd and closed the dialog — now just no-ops without closing.
- A one-tick `hasUnsavedEdits` flicker right after save (stale `useLiveQuery` record vs. already-updated `savedId`) — now guarded by an id match.

Two judgement-call findings (duplication between `save()`/`saveAsNew()`, and the route querying Dexie directly instead of through the hook) were left as-is — both already match this codebase's existing conventions (e.g. `MyFittingsPanel.tsx` also queries `db.fittings` directly from a component).
