## What changed

Adds a reusable, tabbed, read-only **Public Info Modal** for looking up another Character, Corporation, or Alliance by public ESI data — the foundational component issue #399 asked for, ahead of the Contacts/Corp Members/Contracts tickets that will adopt it.

- `src/stores/publicInfoModal.ts` — a global Zustand signal store (`request: { kind, id } | null`), mirroring `stores/authFailure.ts`'s shape, since this modal is opened from several unrelated features rather than one route's own local state. Exposes `openPublicInfoModal(kind, id)` and `usePublicInfoModal().open(kind, id)`.
- `src/features/character/publicInfoData.ts` — read-through loaders for the three already-public ESI endpoints (`getCharacterPublicInfo`/`getCorporationPublicInfo`/`getAlliancePublicInfo`), cached under `esi/cache.ts`'s global sentinel with `STALE_AFTER.static` (same pattern as `stations.ts`). Corporation lookups additionally resolve the CEO's name via `resolveNames`.
- `src/components/PublicInfoModal.tsx` — the tabbed UI, mounted once in `App.tsx` beside `WhatsNewPanel`. Opening by character id resolves the whole chain (character → corp → alliance) in one pass; opening directly by corp or alliance id skips straight to that tab. A tab only appears once its kind has entered the chain, so an alliance-less character/corp simply has no Alliance tab rather than an error. Tab data is kept in local state for the life of one open request, so switching tabs never re-fetches.
- `src/lib/eveImages.ts` — adds `corporationLogoUrl`/`allianceLogoUrl` alongside the existing `characterPortraitUrl`/`typeIconUrl`.
- `CONTEXT.md` — records implementation choices as round 50, on top of round 49 (already on `main`, added concurrently by a batch-audit doc covering issues #399-#422 that had independently named the same round number for the higher-level "Public Info Modal" decision — resolved by keeping round 49 as-is and filing this branch's specifics as round 50).

No new ESI scope: all three endpoints were already registered `PUBLIC` in `src/esi/registry.ts`.

## Deviations from the ticket

- The ticket's own text referenced "CONTEXT.md round 49" as pre-existing context that didn't actually exist yet when work started; a concurrent ticket added it as a forward-looking, multi-ticket decision doc while this branch was in flight, so this PR's own CONTEXT.md entry became round 50 instead (see merge commit).
- `/code-review`'s Spec pass caught that the Character tab's corp/alliance links initially rendered a bare `#id` instead of the resolved name once available, and that the Character tab was missing its own Alliance row (per the ticket's "alliance if any" line). Both fixed before commit: `CharacterTab`/`CorporationTab` now receive the resolved name from the parent and fall back to `#id` only while that name is still loading.

## Review notes

- `/code-review`'s Standards pass flagged two non-blocking judgement calls, left as-is: a 3-way ternary dispatching on the active tab kind (`PublicInfoModal.tsx`), and reuse of the generic `common.loadFailedTitle`/`common.loadFailedHint` copy for all three tabs' error state rather than per-tab-scoped strings.
- Corp/alliance logo images (`corporationLogoUrl`/`allianceLogoUrl`) weren't explicitly asked for in the ticket's field list (only the Character tab's portrait was) but were added for visual consistency across the three tabs — harmless, flagged as minor scope creep by review.

Closes #399
